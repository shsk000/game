# /bug-hunt — AI 探索バグハント

ゲームを Playwright MCP で実際にプレイし、バグ候補を集め、**敵対的検証 → 再現ゲート**で偽陽性を落としてから `gh issue create` する。

方法・設計の芯・2 オラクルの定義は **`docs/qa/bug-hunt.md`**、プレイ台本は **`docs/qa/usecases.md`** を必ず読んでから実行する。ブラウザ操作の作法は playwright-verify skill に従う（自前 script は書かない）。

## 引数
- 無し：`docs/qa/usecases.md` の全 UC を回す。
- `UC-03` のように UC-ID：その UC だけ。
- 自由文（例 `採用まわり`）：関連する UC に絞る。

## 実行手順（この順で必ず通す）

**[0] 準備**
1. dev 起動を確認。worktree なら `npm install` 済みか確認 → `npm run dev`。**起動ログの実ポートを必ず確認**（main と worktree で 5173/5174 に割れる）。
2. `browser_resize` 1280×800 → `browser_navigate` → `browser_console_messages` で clean 確認。

**[1] プレイ（発見）** — 各 UC を操作。候補は必ず**証拠付き**で記録する。エージェントの自己申告は信じない。
- 候補 = `{ 症状 / 再現手順 / 期待 / 実際 / 証拠(スクショパス・実数値・console) / オラクル種別 / UC-ID }`。
- 証拠の無い「感想」は候補にしない。
- **規約オラクル**（1280×720 はみ出し・`console.error`・NaN・マイナス残高・白画面・濃色背景に黒字）に該当したら → 敵対的検証を飛ばして **[4]** へ（確定）。
- それ以外（spec とのズレ・詰み・評価/売上の食い違い）は **仕様オラクル** として [2] へ。

**[2] 敵対的検証**（仕様オラクル候補のみ） — サブエージェントを **まっさら**に立てる。
- 渡すのは **主張＋証拠＋該当 spec 抜粋のみ**。発見時の推論は渡さない（アンカリング防止）。
- 指示："この主張が**仕様通り**であることを反証せよ。デフォルトは仕様通り（不採用）。バグと言い切れる根拠が無ければ却下。"（kill mandate）
- 反論が成立したら候補を破棄。

**[3] 経験的再現ゲート** — 生存候補の**再現手順をブラウザで再実行**。
- 同じ症状が再現しなければ破棄（フレーク・ハルシネーション排除）。**ここが偽陽性を落とす最強フィルタ**。

**[4] issue 化** — 生存分のみ。
1. **dedupe**：`gh issue list --state open --search "<症状キーワード>"` で既存確認。重複はスキップ or コメント追記。
2. 起票：
   ```
   gh issue create --title "<簡潔な症状>" --label auto-bug,ai-found \
     --body "## 症状 … ## 再現手順 … ## 期待/実際 … ## 証拠 … ## 検出元(commit/UC-ID/オラクル種別)"
   ```
   規約系は `--label guideline` も付ける。スクショは本文にパスを明記（or gh でアップロード）。

## 最後に必ず出す（本文レポート）
- 回した UC 一覧
- 候補 N 件 → 敵対的検証で M 件排除 → 再現ゲートで K 件排除 → **起票 L 件**（各 issue 番号）
- dedupe でスキップした既存 issue

## やらないこと
- 証拠の無い候補を起票する（silent wrong-success の温床）。
- 敵対的検証・再現ゲートを飛ばして直接起票する（規約オラクル該当を除く）。
- 定期実行化（今回は手動のみ）。
