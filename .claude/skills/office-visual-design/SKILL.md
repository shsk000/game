## 0. このスキルが必要になる理由

過去に「素材を生成してから不整合を発見」「ユーザー指摘でようやく気付く」を繰り返した。原因は**確定仕様の不在**。
このスキルは「何が正解か」を**先に**決めて、生成・配置・評価の全段階で一貫した基準を提供する。

## 2. カメラ・パース仕様

### 2-0. 視点：**アイソメトリック（2:1 dimetric）**

このプロジェクトの視点は **アイソメトリック（30°×30°、2:1 dimetric projection）** で確定。
横2:縦1の比率で斜め見下ろした絵作り。Kairosoft Game Dev Story と同じ視点。

参考画像：https://kairosoft.net/shared/images/company/pc_anm.png

### 2-1. アイソメトリック視点の特性
- カメラ角度：**水平 30°・垂直 30°**（両軸とも傾ける）
- 部屋・床・物体すべて**ひし形（diamond）**として描く
- 正方形タイルが画面上では「縦に潰した菱形（横:縦 = 2:1）」になる
- **遠近法なし**（パラレル投影）— 奥のキャラと手前のキャラが同サイズ
- 同じ高さの面は画面上で同じ y 位置に来る

### 2-2. 結果として見えるもの
- 物体・人物の**上面 ＋ 正面 ＋ 側面**の3面が同時に見える
- 机：天板 + 南面（前板） + 西面または東面（側板） が見える
- 椅子：座面 + 背もたれ + 脚 + 側面が見える
- モニター：画面 + 上面 + 側面 が見える
- 壁：北壁 + 西壁または東壁 の**2面**が L字型に立ち上がる
- 床：オレンジ/イエロー系のタイル（ひし形パターン）

### 2-3. 真俯瞰・正面・3/4・アイソメの区別
| 視点 | 見え方 | 用途 | 我々の選択 |
|---|---|---|---|
| 真俯瞰（90°） | 上面だけ・薄っぺら | フロアプラン | ❌ |
| 正面（0°） | 正面だけ・奥行きなし | 横スクロール | ❌ |
| 3/4 オブリーク（35° 一軸） | 上面＋少し正面 | RPG Maker VX | ❌ |
| **アイソメトリック（30°×30° 二軸）** | 上面＋正面＋側面 | カイロソフト・JRPG・SimCity | **✅** |

### 2-4. 物体の向き（アイソメでは「軸平行」の意味が変わる）
- アイソメでは床がひし形なので、物体も床の対角線に沿って配置する
- 物体の正面は **南東 or 南西**を向く（厳密な南ではない）
- 部屋の壁は **L字型**（北壁＋西壁、または北壁＋東壁）
- ❌ 物体を画面と平行に置くと**逆に違和感**（アイソメでは画面平行＝床と45°ズレる）

### 2-5. 床のひし形パターン
- 1タイル = 画面上で横64 × 縦32（2:1 比率）
- タイルの境界は**斜め線**（画面と並行ではない）
- パターンは菱形格子状に配置

## 2-A. 【最重要】Sandbox 立方体ベース設計

> ⚠️ **このセクションが全素材の基準**。すべての家具・人・装飾は「**整数倍の立方体に収まる**」前提で発注・配置する。
> Minecraft / 街づくりサンドボックスのように、物体を**ボックスで占有**する感覚で組み立てる。

### 2-A-1. 基準ユニット：「**1キューブ = 32×32×32 voxel** 」
- ゲーム内ワールドの最小単位
- 1キューブ = 床1タイル相当の空間（縦・横・高さ）
- 画面上では 3x スケールで **96×96×96 px 相当の空間**を占める

### 2-A-2. アイソメ投影で1キューブが画面上で見える形

```
   ┌─── top face ───┐   ← 上面（ひし形 64w × 32h px）
   │\               /│
   │ \   diamond   / │
   │  \           /  │
   │   \─────────/   │
   │west│       │east│  ← 西面・東面（rect 32w × 32h px）
   │side│       │side│
   │    │       │    │
   └────┴───────┴────┘
       64w × 64h px total（上面ひし32 + 側面32）
```

1キューブ全体の画面表示サイズ：
- 横：64px（上面ひし形の幅）
- 縦：64px（上面ひし形 32 + 側面 32）
- これに 3x スケールで 192×192 px 表示

### 2-A-3. 各物体の占有キューブ規格（**確定**）

| 物体 | W × D × H | 解説 |
|---|---|---|
| **床タイル** | 1 × 1 × 0 | 上面のみ（厚みなし） |
| **壁（北・東・西）** | N × 1 × 2 | 部屋の境界、高さ2キューブ |
| **デスク** | **2 × 1 × 1** | 横長・奥行き1・天板の高さ1 |
| **椅子** | **1 × 1 × 2** | 1キューブ床面、座面まで1、背もたれまで2 |
| **モニター** | **1 × 0.5 × 1.5** | デスク上の北寄り、薄く・高めに立つ |
| **人物（着席）** | **1 × 1 × 2** | 椅子に座って身長2キューブ |
| **人物（立ち）** | 1 × 1 × 2.5 | 立つと頭がもう少し高い |
| **窓** | 1.5 × 0.1 × 1.5 | 壁にめり込んで配置 |
| **観葉植物（小）** | 1 × 1 × 1.5 | 鉢＋葉 |
| **ホワイトボード** | 2 × 0.1 × 1.5 | 壁に貼る |
| **ソファ** | 2 × 1 × 1.2 | 横長・低い |
| **本棚** | 1 × 1 × 2.5 | 高い・狭い |
| **コーヒーマシン** | 1 × 1 × 1.5 | 小型家電 |

### 2-A-4. 1ワークステーション（人＋机＋椅子＋モニター）の占有スペース

```
       北
        ↑
   +────────────+
   │   monitor  │  ← H 1.5 cube（机の上）
   │  (1×0.5×1.5)│
   │ ┌─────────┐│
   │ │   desk   ││  ← 2×1×1
   │ └─────────┘│
   │   worker   │  ← 1×1×2（座位）
   │ (1×1×2)    │
   │   chair    │  ← 1×1×2
   │ (1×1×2)    │
   +────────────+
        ↓
       南

占有面積（床面）：2 × 2 = 4 cube
高さ最大：2.5（モニター天）
```

→ 1ワークステーションは床上 **2×2 cube** を占有。これを単位として部屋にグリッド配置する。

### 2-A-5. 部屋のグリッド計算（アイソメ前提）

| 規模 | 部屋 cube サイズ | 配置可能ワークステーション |
|---|---|---|
| mini | 6 × 6 cube | 2×2 = 4個 |
| mobile | 9 × 6 cube | 3×2 = 6個 |
| indie | 9 × 9 cube | 3×3 = 9個 |
| hit | 12 × 9 cube | 4×3 = 12個 |
| aaa | 12 × 12 cube | 4×4 = 16個 |

部屋の壁は厚み1キューブ。床は内部に敷き詰める。

### 2-A-6. プロンプト指示への影響（PixelLab 発注時の必須句）

物体を発注するとき、**占有キューブ数を明示する**：

```
isometric pixel art of a [object name], fits within a 2×1×1 cube bounding box,
top face + south face + east face all visible (three faces in isometric projection),
30 degree isometric view, 2:1 dimetric projection, axis-aligned cube space,
solid sandbox-style chunky pixel art (Minecraft / Game Dev Story / SimCity inspired),
thick black outline, flat shading, bright saturated palette, transparent background
```

→ 「**N×M×H cube bounding box**」を必ず明示することで、PixelLab が**サイズ感を守って**生成する確率が上がる。

### 2-A-7. 失敗パターン → サンドボックス基準で見る

| ❌ NG | 立方体ベースでなぜダメ |
|---|---|
| キャラが椅子より大きい | 人 1×1×2、椅子 1×1×2 → 同じ高さのはず |
| モニターが机と同サイズ | モニター 1×0.5×1.5、机 2×1×1 → モニターは机の上に乗る小物 |
| 椅子が机より大きい | 椅子 1×1、机 2×1 → 机が幅2倍 |
| 物体が斜めに回転 | キューブは画面の対角に沿って描く（アイソメ世界軸） |
| 視点バラバラ | 全物体が同じ30°×30°のアイソメ世界に存在 |

### 2-A-8. なぜ立方体ベースが効くか

- **整合性の保証**：すべての物体が同じ世界座標系に存在する
- **発注の規格化**：「2×1×1 cube」と言えば PixelLab に伝わりやすい
- **配置の数学化**：ワークステーション = 2×2 cube → グリッドが組みやすい
- **拡張性**：将来「家具を増やす」「部屋を広げる」が**ボクセル単位**で計算できる
- **見え方の予測**：N×M×H が分かれば画面上の占有 px が計算できる

## 2-B. ⭐【最重要】同じ物体の「2アイソメ向き」を1シートに統合

> **このプロジェクトでは机を「向かい合わせペア」にしか配置しない**ため、
> 各物体に必要な向きは **SW / NE の 2方向だけ** で済む。
> 「向き違い = 別ファイル」ではなく「**1スプライトシートに 2向き横並び**」で管理する。
>
> 将来「壁際机」「窓向き机」を追加するなら4方向に拡張。

### 2-B-0. 基準方向は SW（左下向き）に確定 ⭐

**このプロジェクトの確定基準方向 = SW（左下向き）**。全家具・キャラの基準向きが SW。

#### PixelLab への発注ルール（2026-06-07 再実証）
旧仮説「PixelLab は方向指定を無視するので prompt に方向句を入れなくても SW になる」は**机だけのバイアス**で、椅子では成立しなかった（無指定だと SE に倒れた事例あり）。
→ **全物体で必ず prompt に SW 方向句を明示する**：

```
facing south-west (the front of the object points to the lower-left of the frame),
three faces visible from the camera: top, south, and west,
isometric 30-degree dimetric perspective
```

#### 採用前チェック（必須）
レビュー4候補から1つ採用する前に、**前面が画面の左下を向いているか**を必ず目視確認。SE（右下向き）が混じっていたら全候補棄却を検討。

#### NE 方向の作り方（⭐ すべて新規発注）
- **すべての物体**：PixelLab で NE 方向句を入れて新規発注（`create_map_object` 推奨）
- 2D 反転・回転は使わない（§2-B-5 参照、絶対禁止）

このルールは：
- ✅ 安定（prompt 明示で方向が揃う）
- ✅ 統一感（全物体が同じ角度・パレットで揃う）
- ⚠ コストは椅子・人物で2倍（SW/NEそれぞれ20gen）

### 2-B-1. 2つのアイソメ向き

ペア配置での「物体の向き」は2種類：

| 向き | 用途 | 物体の状態 |
|---|---|---|
| **TOP**（上段用、index 0） | ペアの上側＝北側に座る Worker A 用 | drawer北 / 背もたれ北 / 画面北向き / 人は南向き |
| **BOTTOM**（下段用、index 1） | ペアの下側＝南側に座る Worker B 用 | drawer南 / 背もたれ南 / 画面南向き / 人は北向き |

### 2-B-2. スプライトシート形式（必須）

```
横並び 2 向き：
[ TOP ][ BOTTOM ]
  0      1
```

ファイル名：`desk.png` 1枚（2向き内包）、`chair.png` 1枚、`monitor.png` 1枚 …

ピクセル例（1向き 64px の場合）：
- desk.png 全体：128 × 48 px（2向き × 64px幅）
- CSS：`background-position-x: -${orientationIndex * 64}px`

### 2-B-3. 物体ごとの向き数の指定

> ⭐ **重要原則**：物体が **完全対称（drawer や非対称な特徴なし）**なら 1方向で済む。
> **非対称な特徴（背もたれ・顔・引き出し等）を持つ物体**は 2方向必須。

| 物体 | 向き数 | 理由 |
|---|---|---|
| **机（drawer 付き・非対称）** | **2**（SW / NE） | 上段＝SW向き、下段＝NE向き（180度反転） |
| **椅子** | **2**（SW向き / NE向き） | 背もたれ位置が反転、180度反転で作成 |
| **モニター（Game Dev Story の嘘採用）** | **1** | 両方とも画面が見える方を表示（物理的に嘘） |
| **モニター（リアル方式）** | **2** | 画面の向きが反転 |
| **人物 idle** | **2**（SW向き / NE向き） | 上段＝SW向き、下段＝NE向き |
| **人物 着席** | **2** | 同上 |
| **人物 タイピング** | **2** | 同上 |
| **窓** | 1 | 北壁に貼るだけ。向き不要 |
| **植物** | 1 | 向きの影響なし |
| **床タイル** | 1 | 真上タイル可 |

→ **このプロジェクト確定方針**：
- 机・椅子・人は 2方向（SW / NE）
- モニターは Game Dev Story の嘘採用で 1方向
- すべての NE 方向は **SW 生成 → ImageMagick で180度回転** で作成

### 2-B-4. データ駆動の向き指定

equipment.ts などで：
```ts
type EquipmentDef = {
  id: string;
  sprite: string;      // スプライトシートパス（SW左 / NE右の2枚横並び）
  frames: 1 | 2;       // 1=向き不要、2=SW/NE
  frameSize: number;   // 1向きあたりのピクセル
};

// 配置時に向きを選ぶ
type Placement = {
  equipmentId: string;
  orientation: 'SW' | 'NE';  // 2向きから選択
};
```

ペアの上下で向きを自動決定：
```ts
function pickOrientation(role: 'top' | 'bottom'): 'SW' | 'NE' {
  return role === 'top' ? 'SW' : 'NE';  // 上段=SW向き、下段=NE向き
}
```

### 2-B-5. 別方向の作成 ⭐ **すべての物体で別途 PixelLab 発注**

#### ⚠️ 2D 反転・回転で別方向を作ろうとしない（絶対禁止）

2D 画像（PixelLab 出力）を `magick -flop` や `magick -rotate 180` して別方向に使うのは **すべての物体で禁止**。

**理由:** PixelLab 出力は 2D ピクセル画像であって 3D モデルではない。反転や回転は左右上下のピクセル入れ替えに過ぎず、3D 空間での視点回転と等価ではない。
- 椅子・人物・ノートパソコン・モニター：背面は画像に存在しないので反転しても出てこない
- 机：左右対称に見えても、影や光源の方向も反転するので「下から見上げた違和感」が出る（2026-06-07 のセッションで実証・ユーザー却下）

**正しいフロー:**

| 物体 | 別方向の作り方 |
|---|---|
| すべて | **PixelLab に新規発注**：`create_map_object`（1gen / 1候補 / 方向句効く）か `create_8_direction_object`（20gen / 8方向）|

#### 推奨ツール選定（2026-06-07 確定）

- **`create_map_object`**：1gen 1候補、**方向句が prompt で効く**（"facing south-east" 等）。最もコスト効率良い。第一選択。
- **`create_8_direction_object`**：20gen で 8方向、`reference_image_base64` で既存物体の8方向版を作れる。同じ物体のフルセットを揃えたいときに使う。
- **`create_1_direction_object`**：20gen で 16候補、ただし**方向句は効かない**（PixelLab デフォルト SW向きに倒れる）。コスパ最悪、原則使わない。

#### 椅子・人物の NE 方向は別途発注

椅子・人物は SW（前向き）と NE（背中向き）が**全く別の見え方**：

| 方向 | 椅子の見え方 | 人物の見え方 |
|---|---|---|
| SW 向き（前向き） | 座面が見える・背もたれは奥に立つ | 顔・体が見える |
| NE 向き（後ろ向き） | 背もたれの**裏側**が見える・座面は見えない | **背中**が見える |

→ それぞれ別のプロンプトで PixelLab に発注。180度回転では絶対に作れない。

### 2-B-5. PixelLab 発注時のプロンプト

4向き同時生成は PixelLab の `create_character` （humanoid なら可）か、または**1向きずつ4回発注**：

#### 方法1: 1向きずつ発注して後で連結（推奨・確実）
```bash
# Step 1: 4向きを個別生成（4 gen）
# Step 2: ImageMagick で連結
magick desk_se.png desk_sw.png desk_ne.png desk_nw.png +append desk.png
```

各向きのプロンプト：
```

fits within a [W]×[D]×[H] cube bounding box,
visible faces: [top + south face + east face for SE / top + south + west for SW / etc],

```

#### 方法2: PixelLab の `create_character` の n_directions=8（キャラのみ）

```ts
  // アイソメで必要なのは斜め4方向（NE/SE/SW/NW）
  // 8方向なら南北東西も含む
});
```

### 2-B-6. なぜ机を TOP/BOTTOM の 2向き必須か

ペア配置では：
- ペアの上側（A）：drawer が北、モニター置き場が南
- ペアの下側（B）：drawer が南、モニター置き場が北

→ 上下で**机の前後を反転**する必要があり、CSS 反転（scaleY）では破綻する（アイソメ3D感が崩れる）。
→ なので**別スプライトで2向き必須**。

| 人物 idle | 2（south/north） | **2 gen** |
| 人物着席アニメ | 2 | **2 gen** |

→ 残15枠あれば十分。

## 2-C. ⭐【確定配置】「机は向かい合わせペア」が標準

> このプロジェクトの机配置は **「向かい合わせ（face-to-face pair）」が確定標準**。
> オフィスシム定番の「お見合い席」レイアウト。Game Dev Story もこれが基本。

### 2-C-1. 1ペアの構造（2人ユニット）

```
       (north)
         ↑
   +────────────+
   │  Worker A  │  ← 北側に座って south を向く
   │   ↓ face   │
   │ ┌────────┐│
   │ │ Desk A ││  ← 机Aは drawer(work side) が北
   │ │  (NE)  ││     monitor 側（南）が共用ゾーン
   │ │   ▓▓▓▓ ││  ← Desk A の南端にモニター（south 向き／A から見える）
   │ │ ════   ││  ← 机Aの南端＋机Bの北端が接する境界
   │ │ ▓▓▓▓   ││  ← Desk B の北端にモニター（north 向き／B から見える）
   │ │  (SE)  ││
   │ │ Desk B ││  ← 机Bは drawer が南
   │ └────────┘│
   │   ↑ face   │
   │  Worker B  │  ← 南側に座って north を向く
   +────────────+
         ↓
       (south)
```

→ 2人ペアで上から：**Worker A → Desk A → [モニター背中合わせ] → Desk B → Worker B**
→ Worker A と Worker B は**互いの顔を見ている**（机越しに対面）

### 2-C-2. ペアの占有スペース

| 要素 | サイズ | 配置 |
|---|---|---|
| Worker A | 1×1×2 cube | 北端 |
| Desk A | 2×1×1 cube | A の南 |
| Desk B | 2×1×1 cube | A の南に隣接（背中合わせ） |
| Worker B | 1×1×2 cube | 南端 |
| **ペア合計** | **2 × 4 cube** 床面 | 縦長配置 |

### 2-C-3. 4人配置（mini オフィス = 2ペア）

```
   [ペア1: AB対面]   [ペア2: CD対面]
   ┌──────────┐   ┌──────────┐
   │ Worker A │   │ Worker C │  ← 上段ワーカー（south向き）
   │ Desk A   │   │ Desk C   │
   │ Desk B   │   │ Desk D   │
   │ Worker B │   │ Worker D │  ← 下段ワーカー（north向き）
   └──────────┘   └──────────┘
```

→ AB は対面ペア、CD は対面ペア。2ペアが横並び。
→ A↔B、C↔D で顔合わせ。A↔C は隣同士（並ぶ）

### 2-C-4. 必要な机の2向きと配置ルール

```
ペアの上側机（A や C）= 「ユーザー側（drawer）が北、モニター置き場が南」
  → スプライトシートの TOP（index 0）

ペアの下側机（B や D）= 「ユーザー側（drawer）が南、モニター置き場が北」
  → スプライトシートの BOTTOM（index 1）
```

- **机は2向きシート必須**（TOP / BOTTOM）
- 配置時に「上段なら TOP、下段なら BOTTOM」を指定

### 2-C-5. ⭐【最重要】「ペアの上下で全要素が反転する」原則

> **机を向かい合わせにすると、関連する全要素（机・椅子・モニター・人）が**
> **上下のポジションで反転する必要がある**。これは設計の最重要原則。

#### 反転マトリクス（必ず守る）

| 要素 | **上段（TOP）= NE 側に座る Worker A** | **下段（BOTTOM）= SW 側に座る Worker B** |
|---|---|---|
| **Worker（人）** | **SW向き**（机を見る方向 = カメラ寄り） | **NE向き**（机を見る方向 = カメラから離れる） |
| **Chair（椅子）** | **SW向き**（背もたれが NE 側＝人の背中側） | **NE向き**（背もたれが SW 側＝人の背中側） |
| **Desk（机）** | **SW向き**（PixelLab デフォルト） | **NE向き**（SW を180度回転） |
| **Monitor（PC）** | SW向き or 嘘採用で1種 | NE向き or 嘘採用で1種 |

#### なぜ全要素が反転するか

- **椅子**：人の背中側に背もたれ＝人の向きで反転
- **机**：drawer/keyboard 位置の関係で180度反転
- **モニター**：画面はユーザーに見える方向＝反対向き
- **人**：当然反対方向を見る

#### 制作の実際

1. **SW 向き**を PixelLab で生成（基準）
2. **NE 向き**を ImageMagick で180度回転して作成
3. 1枚のスプライトシートに横並び（SW左 / NE右）

#### スプライト管理

| 要素 | 上段で使う向き（index） | 下段で使う向き（index） | 必要シート |
|---|---|---|---|
| Desk | TOP（0） | BOTTOM（1） | **2向きシート**（desk.png 内に横並び） |
| Chair | TOP（0） | BOTTOM（1） | **2向きシート**（chair.png 内に横並び） |
| Monitor | TOP（0） | BOTTOM（1） | **2向きシート**（monitor.png 内に横並び） |
| Worker | south facing スプライト | north facing スプライト | **2向きシート**（worker_idle/sit/typing 各 2列） |

#### コード上の表現例

```ts
type PairRole = 'top' | 'bottom';

function orientationIndex(role: PairRole): 0 | 1 {
  return role === 'top' ? 0 : 1;
}

// 配置時
<EquipmentSprite sheet="/sprites/office/desk.png" frameIndex={orientationIndex(role)} />
```

→ ペア単位で「**上下を反転して 1セット**」が組める。

#### Game Dev Story の慣習との折衷案

レトロゲーム慣習で「**全員 south 向きで顔を見せる**」を採用するなら、下段ワーカーも south 向きにする選択もあり：

| 戦略 | 上段 worker | 下段 worker | メリット | デメリット |
|---|---|---|---|---|
| **リアル方式（推奨・確定）** | south facing | **north facing** | 物理的に正しい・向かい合わせ感が出る | north sprite 必須・PixelLab で生成必要 |
| レトロ慣習方式 | south facing | south facing（顔がカメラに）| 全員顔が見える・cute | 物理的におかしい（下段は机に背を向けて座る） |

→ このプロジェクトでは **「リアル方式」を採用**（向かい合わせの説得力優先）。

### 2-C-6. 拡張時の配置

| 規模 | ペア数 | 配置 |
|---|---|---|
| mini | 2 | 1列に2ペア横並び |
| mobile | 3 | 1列に3ペア横並び |
| indie | 4 | 2列 × 2ペア（または 1列 × 4ペア） |
| hit | 6 | 2列 × 3ペア |
| aaa | 8 | 2列 × 4ペア |

### 2-C-7. ペア配置のメリット

1. **オフィスらしさ**：「お見合い席」は会社の標準配置
2. **密集感**：机が背中合わせで床面積効率良い（Game Dev Story の密集感）
3. **コミュニケーション感**：対面なので雑談・協業の雰囲気
4. **拡張容易**：ペア単位で増やせる
5. **モニター裏面の有効活用**：ペアの中央に立つので裏面が「相手のモニター裏」となり辻褄が合う

## 3. レトロ慣習の許容（物理的におかしいけど見せたいもの）

Game Dev Story 系の伝統的な「嘘」：

1. **椅子の背もたれが見える**：本当は作業員が座っていて見えないはずだが、座っている感を出すため**手前に立ち上げて見せる**
2. **奥のキャラも手前のキャラも同サイズ**：遠近法を無視（パラレル投影）
3. **顔の向きはペアの上下で反転**：物理的にはユーザー側に画面が向くので作業員は south facing ／ north facing でペアごとに切り替え（§2-C-5 リアル方式）

これらは「物理的に正確」より「見やすさ・かわいさ」を優先する。

## 4. 各要素の見え方

### 4-1. 床・壁（部屋枠）
- **床**：完全に真上の平面パターン（タイル）。歪みなし
- **北壁**：画面上端に**縦帯**で立ち上げる（壁紙＋幅木）
- **東西壁**：画面左右に**細い縦帯**（奥行きの示唆）
- **南壁**：表示しない（カメラ側 ＝「壁を取り外して中を見ている」状態）
- 部屋は **3面ボックス** として描く

### 4-2. 机（デスク）
- ✅ **天板（上面）が主役**。長方形（軸平行）で、わずかに南北方向にひし形化（後傾の影響）
- ✅ **南エッジに薄い影**（接地表現）
- ✅ **南エッジに少しの深さ**（厚みの示唆、3〜5px ぐらい）
- ✅ 脚は天板の四隅から下に伸びる（黒メタルフレームが標準）
- ❌ 引き出しの「前板」を南面に描かない
- ❌ 側面（東西の縦面）を見せない
- ❌ 真俯瞰の「ただの長方形」NG
- ❌ 物体ごと斜め回転 NG
- 素材：**白いラミネート天板＋黒い金属脚**（オフィス標準）。木製は自宅っぽくなるので NG

### 4-3. モニター（PC）
- **後傾視点で立ち上がって見える**
- 画面の四角形が**こちらを向く**（south facing screen）
- スタンドは底面に小さく
- 上端・側面のフレームが少し見える
- ❌ 「上から潰した薄い板」NG

### 4-4. 椅子
- ✅ 座面の上面（円形/楕円）が見える
- ✅ 背もたれが**手前に立ち上がって見える**（人の背中側に縦に立つ）
- ✅ 5つのキャスター脚が座面の周りに放射状にはみ出す
- ✅ アイソメ視点で seat + back + base が見える
- ❌ 「真上から見た円盤」NG

### 4-5. 人物（社員）
- **半身が見える**：頭・肩・胸・腕＋膝あたりまで
- 椅子に座っている。**足は机の下に隠れる**（CSS clip-path や物体重なりで隠す）
- 顔向きは **ペアのポジションで反転**（§2-C-5 参照）：
  - 上段ワーカー → south facing（顔がこちら）
  - 下段ワーカー → north facing（背中がこちら）
- アニメ：
  - **idle**：わずかに揺れる（呼吸感）
  - **typing**：両腕が机上で動く

### 4-6. 装飾（窓・植物等）
- **窓**：北壁の上端に立ち上がって見える。外の空（青色）が見える
- **植物**：床に置かれた状態でアイソメ視点（鉢＋葉が広がる）
- これらも軸平行（アイソメ世界の対角線に沿う）に置く

## 5. 現実比率（サイズの確定基準）

### 5-1. 基準比率（現実の家具・人体から導出）
| 比較 | 比率（高さ/幅） | 解説 |

| **窓幅 ÷ 北壁幅** | **0.2〜0.4 : 1** | 窓は壁の一部 |

- ❌ 机が人物と同じ幅

## 7. ワークステーション 1セットの z-order 仕様

「**y座標が大きいほど（南に近いほど）手前**」の painter's algorithm。

```
z=1  机天板（北寄り、奥）
z=2  モニター（机に立つ）
z=3  人物（机の前で座る、机に下半身が隠れる）
z=4  椅子背・脚（人物の手前、座っているのを示す）
```

### 7-1. 1ワークステーションの理想的縦配置
```
y=0       ┌──────────────────┐  ← 机の北端
          │                    │
y=0.3     │   [モニター画面]    │  ← モニター（机上で立ち上がる）
          │      ▓▓▓▓          │
y=0.7     │   [モニター下部]    │  ← スタンド
y=0.9     └────────────────────┘  ← 机の南端
y=0.9     ┌──────[人物]──────┐  ← 上半身（机の南エッジに被る）
y=1.0     │   頭・肩・腕        │
y=1.5     │   胴・両腕（机上）   │
y=1.7     └────[椅子座面]────┘
y=1.7     ┌────[椅子背・脚]────┐  ← 椅子の手前部分
y=2.0     └────────────────────┘
```

### 7-2. CSS 実装パターン
```tsx
<div style={{ position: 'absolute', left: baseX, top: baseY, width: stationW, height: stationH }}>
  <div style={{ position: 'absolute', top: yMonitor, zIndex: 2 }}>{monitor}</div>
  <div style={{ position: 'absolute', top: yDesk,    zIndex: 1 }}>{desk}</div>
  <div style={{ position: 'absolute', top: yWorker,  zIndex: 3 }}>{worker}</div>
  <div style={{ position: 'absolute', top: yChair,   zIndex: 4 }}>{chair}</div>
</div>
```

## 9. 検証プロトコル（生成・配置のたびに実行）

新しいスプライトを生成・配置した後、必ず：

### 9-1. スプライト個別の検証
1. **サイズ計測**：`magick identify -format '%wx%h' file.png`
2. **視点判定**：Read tool で画像を表示し、§2 のアイソメ仕様と照合
3. **立方体規格確認**：§2-A-3 の物体ごとの N×M×H に収まっているか
4. **軸確認**：アイソメ世界軸に沿っているか（物体ごと回転していないか）
5. **背景透明確認**：透明背景になっているか

### 9-2. 並べた時の整合
- §5-1 の比率と一致するか（±20%以内）
- 全要素の視点角度が同じか（一部だけ真俯瞰でないか）
- パレットが統一されているか

### 9-3. 配置後の検証（Playwright スクショ）
- 人物が机の下に下半身を隠せているか（「座っている感」）
- ワークステーション間に不自然な隙間がないか
- 部屋枠（壁）が違和感なく成立しているか
- §1 の世界観に合っているか（カイロソフト感）

### 9-4. ユーザーへの報告フォーマット
```
## 自己チェック結果（office-visual-design §9）
- 視点一貫性： [✅ / ⚠️ デスクだけ真俯瞰寄り]
- 比率： 人/モニター = 2.31 ✅ / 椅子/人 = 0.72 ✅
- 軸平行： [✅ / ⚠️ 椅子が右に5°傾いてる]
- 配置検証： [✅ 4人着席確認]
- 残課題： [リストアップ]
```

→ 検証で問題があれば**ユーザー報告前に修正**または**修正案を併記**。「動いたから見せます」だけはNG。

### 10-1. 共通スタイル句（家具・装飾共通）
```
oblique 3/4 top-down view from south, slight tilt back showing top surface and a hint of front edge,
axis-aligned (not rotated diagonally), cute Japanese pixel art Game Dev Story style,
thick black outline, flat shading, bright friendly palette
```
- ❌ 「strict bird's eye view」「from directly above」は使わない（真俯瞰になる）
- ❌ 「diagonal angle」も使わない（物体が斜めになる）

### 10-2. 家具系
```
[家具名], oblique 3/4 view, axis-aligned, you see the top surface and a hint of the front edge,
slight shadow under the south edge, transparent background outside the shape,
[Game Dev Story style prompt as above]
```

### 10-3. 人物
```
[character description], oblique 3/4 view sitting at desk facing camera,
upper body visible (head, shoulders, torso, arms), legs hidden behind desk,
[Game Dev Story style prompt as above]
```

### 10-4. 失敗時の追加指示
- 真俯瞰になりすぎたら：`"NOT a flat overhead view, this is isometric with three faces visible"`
- 斜め回転になったら：`"the object is placed parallel to the isometric world axes, NOT rotated diagonally on the floor"`
- 立方体規格からはみ出したら：`"must fit within the specified N×M×H cube bounding box"`

## 12. 過去の失敗パターンと学び

| 失敗 | 原因 | 教訓 |
|---|---|---|
| 椅子・モニターの向きが机と一致しない | ペアの上下で反転する原則を忘れた | §2-C-5 の反転マトリクスを毎回確認 |
| 机が斜めに回転 | プロンプトの「oblique」を物体回転と解釈 | "axis-aligned with isometric world axes" を明示 |
| 人と物を1枚に焼き付けて差し替え不可 | 「便利だから」と妥協 | **pixelart-prompting §3-1 の鉄則**を毎回確認 |
| 木製机で「自宅っぽい」 | 素材を考えてなかった | **オフィスは白ラミネート＋黒メタル** |
| サイズがバラバラのまま報告 | セルフチェックなし | §9 を毎回実行 |
| 視点バラバラ（机だけ真俯瞰） | 並べた時の整合チェックなし | §9-2 を実行 |
| 立方体規格を意識せず発注 | サイズ感が崩れる | §2-A-3 の N×M×H を必ず明示 |
