## 0.0. バランス調整の前提：v0.10 P0 で発見されたバグ

> バランスを調整する前に、これらの致命的バグを修正しないと正しい計測ができない。
> 通しプレイで発覚した実装上の不具合。

### B-Crit-1: 販売中作品の売上が funds に入らない【致命】
- **症状**：販売中作品のサマリは「残¥XX / 累計¥YY」と更新されるが、`funds` に流れ込まない
- **原因**：`tickSales(deltaSec)` の実装は `gameStore.ts` にあるが、**どこからも呼ばれていない**
- **影響**：
  - プレイヤーは「売上を体感」できない（Reward Loop §3 壊滅）
  - 経済バランスの計測が不可能（売上テーブルの数値が無意味）
- **修正方針**：アプリ全体で 1 秒ごとに `tickSales(1)` を発火するグローバルタイマーを設置（仮：`GlobalTicker` コンポーネント）

### B-Crit-2: 開発が 5 秒で完了する【致命】
- **症状**：mini 1 本が **5〜10 秒で完成**してしまう
- **原因**：`DevelopScreen.tsx` で `doneLoC >= requiredLoC` を満たした瞬間 `finishDevelopment()` が発火
  → タイピング速い人なら数秒で requiredLoC に到達 → 即完了
- **影響**：
  - 「mini 60 秒」の時間バランス（§1-1）が成立しない
  - 月初固定費発生・神ゲー判定・経営感、すべて発火する暇がない
- **修正方針**：完了判定を `elapsedWeeks >= neededWeeks` のみに変更（doneLoC は副指標に降格）
  - `useTyping` 側では requiredLoC 到達後も次のスニペットを連続ロード

### B-Crit-3: 開発中以外は時間が止まる【致命】
- **症状**：オフィス画面で何もしないと **ゲーム内時間が止まる**
- **原因**：時間進行 setInterval（7.5 秒/週）は `DevelopScreen` 内に置かれていた
- **影響**：
  - spec §9-1（「タイマーで一定速度で進む、タイピングと独立」）違反
  - アイドル中の固定費が発生しない → 経営の緊張感ゼロ
  - 「⏩ 1 週進める」ボタンで手動カバーしていたが UX が歪んでいた
- **修正方針**：時間進行も `GlobalTicker` に集約。画面に応じて速度を切り替え：
  - 開発中：7.5 秒/週
  - アイドル中：30 秒/週
  - 「⏩」ボタンは廃止

### B-Crit-4: 神ゲーガチャ確率が高すぎる【バランス影響大】
- **症状**：初心者で「メタスコア 85+ が乱発」
- **原因**：神ゲーガチャ 5% で品質 ×1.5、4 要素の base から -15 オフセットも未調整
- **影響**：
  - 85+ の希少性が崩壊（5 柱の Reward Loop §3 の山場が薄れる）
  - メタスコア分布が想定外に高い側にシフト
- **修正方針**：
  - 神ゲーガチャ確率を 2% + ピティ +0.5%/本（§3）に
  - 品質 base に -15 オフセット（仮、実装で要検証）

### B-Maj-1: OfficeView のスプライト 404 で黒い枠が並ぶ【見た目）
- **症状**：家具・キャラの PNG が無く、img タグの **壊れ画像アイコン**が表示される
- **原因**：`<img src={path}>` の onError ハンドラなし、emoji fallback ロジックは `useSprite` の `loaded` 判定経由だが何らかの理由で発火していない
- **影響**：第一印象が「未完成」に見える
- **修正方針**：
  - 各 `<img>` に `onError={(e) => e.currentTarget.style.display = 'none'}` を追加（最低限）
  - 理想は `useSprite` を強化して img 失敗時に emoji フォールバックに自動切替

### 修正順序の方針
1. **B-Crit-1 / B-Crit-2 / B-Crit-3 を最優先**（バランス計測の前提）
2. **B-Crit-4** の数値はこの設計書（§3）に従って書き換え
3. **B-Maj-1** は見た目修正、バランスとは独立

## 1. 時間バランス

### 1-1. タイピング時間（規模ごと）

| 規模 | タイピング時間 | ゲーム内週数 | ゲーム内月数 |
|---|---|---|---|
| mini | **60 秒** | 8 週 | 2 ヶ月 |
| mobile | 90 秒 | 12 週 | 3 ヶ月 |
| indie | 150 秒 | 20 週 | 5 ヶ月 |
| hit | 210 秒 | 28 週 | 7 ヶ月 |
| aaa | 270 秒 | 36 週 | 9 ヶ月 |

### 1-2. 時間進行レート

- **タイピング中**：リアル 7.5 秒 = ゲーム内 1 週
- **アイドル中**：リアル 30 秒 = ゲーム内 1 週（タイピング中の 1/4 速度）

### 1-3. 完了判定（重要・現実装と乖離）
- **時間ベース**：`elapsedWeeks >= neededWeeks` で完了
- 旧仕様（`doneLoC >= requiredLoC` で即終了）は廃止
- タイピングは「**指定された期間中ずっと打ち続けるもの**」

### 1-4. 30 分プレイの時間進行
- アイドル混在で 30 分プレイ ≒ ゲーム内 **1〜2 年**
- mini 1 本 = 60 秒（タイピング中）= ゲーム内 2 ヶ月
- 30 分で mini × 10 本作る想定（全てタイピング中なら 10 分、アイドル混在で 30 分）

## 6. 詳細バランス（2026-06-09 議論で確定）

### 6-1. 月給の計算式 ✅
- **役職差なし**、power のみで計算
- 式：**月給 = base ¥30 万 + power × ¥20 万**
- 例：power 1（N）¥50 万 / power 3（R）¥90 万 / power 5（SR）¥130 万 / power 7（SSR）¥170 万
- 役職（プログラマ / デザイナー / PR）の特徴は `role` の能力寄与（既存ロジック）で差別化

### 6-2. 賃料と社員上限 ✅
- **賃料は固定**：全規模で **¥30 万 / 月**（単一固定）
- **社員上限なし**（何人でも雇える、給与で人件費が増える）
- §5-1 の「規模別賃料テーブル」は **無効化**（¥30 万に統一）
- 拠点・オフィスアップグレード等の概念は v0.10 では導入しない

### 6-3. ジャンル相性スコアの正規化 ✅（厳しめ）
- 設計目標：「**全部揃った時のみ高スコア**」
- 計算式（暫定）：

```
genreAffinity = 30                              // base
  + (ジャンル一致時) 15                          // ジャンル × テーマ
  + (テーマ一致時) 15                            // 同上
  + (カテゴリ 1 つ目のジャンル/テーマ相性) 8〜10
  + (カテゴリ 2 つ目の相性) 8〜10
  + (カテゴリ 3 つ目の相性) 8〜10
                                                = 0〜100 にクランプ
```

シミュレーション：
- 何も考えずに選ぶ：base 30 のみ → 致命的失敗予備軍
- 良い組合せ 1 つだけ：30 + 15 + 8 = **53** → 普通帯
- 全部揃える：30 + 30 + 24-30 = **84-90** → ヒット〜大ヒット

### 6-4. キャラ能力スコアの正規化 ✅（厳しめ）
- 4 要素の **最大 50% を担うコアドライバー**
- 計算式（暫定）：

```
charPower = 30                                          // base
  + (power 合計 / 規模適合上限) × 30                    // power 寄与（最大 +30）
  + (役割マッチ：プログラマ×機能カテゴリ等で +10)        // 最大 +10
  + (specialty 一致：1 つ +5、最大 +15)                  // 最大 +15
  + (アサイン人数：1 人 0、2 人 +5、3 人 +10)             // 最大 +10
  + (規模適合：人数不足 -10、十分 0、過剰 -5)            // ±10
                                                        = 0〜100 にクランプ
```

規模適合 power 合計上限：
| 規模 | power 合計上限 |
|---|---|
| mini | 6（N×3） |
| mobile | 9 |
| indie | 15 |
| hit | 21 |
| aaa | 24（SSR×3） |

シミュレーション：
- N 1 人だけアサイン → mini：base 30 - 規模不足 10 + 少 power 5 = **25**（致命的）
- R 3 人 + 役割マッチ → mini：30 + 30 + 10 + 5 + 10 = **85**（大ヒット）
- SSR 3 人 + 全 specialty → aaa：30 + 30 + 10 + 15 + 10 = **95**（神ゲー領域）

### 6-5. タイピング能力スコア ✅（厳しく）
- base を 50 から **30 に下げる**（4 要素全体で base 30 を統一）
- 上手いと大きくブースト：
  - WPM 100 基準 ±20
  - コンボ 30+ で +5、100+ で +10、200+ で +15、500+ で +20（500 は緩和）
  - 精度 95% 未満で -20 まで
  - バグなし完走 +5
- 結果レンジ：下手 0-30 / 普通 50-60 / 上手 70-90
- タイピング能力が**勝負を分ける**設計

### 6-6. ピティ UI 表示 ✅（部分的）
- **OfficeScreen 等での常設表示は無し**（数字を凝視するゲーム性を避ける）
- **ReleaseScreen の breakdown** に小さく「神ゲー判定確率 X%（ピティ込み）」
- **神ゲー判定時のテロップ**「6 本目でガチャ当選！」など、過去何本連続外したか分かる演出
- ピティの存在自体は体感できるが、本筋を邪魔しない

### 6-7. 借金システム ✅
- **借入上限**：月固定費 × 12 ヶ月分
  - 例：mini オフィスで給与 ¥50 万 × 3 人 + 賃料 ¥30 万 = ¥180 万 → 上限 ¥2160 万
- **月利**：3%（spec §9-2 のまま、高利貸し風で緊張感）
- **ゲームオーバー条件**：借入上限を超えた + 資金 0
- 借金額 + 月利が **月初の固定費** に加算される
- UI：OfficeScreen に「借金 ¥XX 万 / 月利 +¥X 万」の表示パネル

シミュレーション：
- 最大 ¥2160 万借りると月利 ¥64 万 → 12 ヶ月で +¥780 万追加負担
- 緊張感あるが、ヒット作 1 本（mini 大ヒット ¥5000 万）で完済可能

### 6-8. ジャンル/テーマ/カテゴリの解放テンポ ✅（ハイブリッド）

#### 解放軸 3 種類
1. **基本軸：累計売上**（数だけじゃなく稼げないと解放されない）
2. **加速軸：ヒット作**（質の高い作品を作るとボーナス解放）
3. **特殊軸：チャレンジ達成**（隠しコンテンツ）

#### 解放テーブル（暫定）

| 解放 | 条件 |
|---|---|
| 新ジャンル 1 個目 | 累計売上 ¥1000 万 |
| 新ジャンル 2 個目 | 累計売上 ¥5000 万 |
| 新ジャンル 3 個目 | ヒット作（メタ 70+）3 本 |
| 新ジャンル 4-12 個目 | 累計売上 + ヒット作 + チャレンジを混ぜて段階解放 |
| 新テーマ 1 個目 | 累計売上 ¥3000 万 |
| 新テーマ 2-10 個目 | 累計売上で段階解放 |
| 新カテゴリ（story） | 全初期カテゴリ（graphics/sound/gameplay）で作品リリース |
| 新カテゴリ（presentation） | ヒット作 5 本 |
| 新カテゴリ（innovation） | 累計売上 ¥1 億 |

#### 設計意図
- 「**駄作量産では解放されない**」現実感
- ヒット作を狙う動機が生まれる
- チャレンジ達成は「攻略の楽しみ」を作る
- 30 分プレイで 1〜2 つの新規解放を体感（柱 5「進化」）

## 8. 検証方法（実装後）

### 8-1. 通しプレイで確認
- 30 分プレイを 3 回繰り返す
- 各プレイで以下を計測：
  - リリース本数
  - スコア帯分布
  - 神ゲー出現回数
  - 収支（資金推移）
  - 規模解放まで何分？

### 8-2. 合格基準
- リリース 8〜12 本
- 致命的失敗 ≒ 20%、失敗 ≒ 35%（誤差 ±5%）
- 神ゲー 0〜1 回
- 30 分以内に mobile 解放可能
- 「**ヒット作が来た時に明らかに嬉しい**」体感

### 8-3. 不合格時の調整
- 全体的にスコア高すぎる → metascore の `-15` オフセットを大きく
- 神ゲー出すぎ → ベース確率を下げる
- mobile 解放できない → unlockSalesRequired を下げる or 売上倍率を上げる
