## 2. 問題点（issues）

### 2-1. ⛔ **OfficeView のスプライト 404 が深刻**
- 机・椅子・人物・キャビネット等のスプライト画像が全て黒い枠で表示される
- `public/sprites/office/` 配下に必要な PNG が無く、`<img>` の壊れマーク（小さなアイコン）が並んでいる
- 第一印象として「未完成」「壊れている」と見える
- **修正必須**：fallback CSS（emoji / 単色矩形）か、本素材生成

### 2-2. ⚠ **localStorage シードが反映されない**
- Playwright で `typing-factory:v5` キーに seed を入れたが、画面上の値（資金 ¥1500万 / ファン 0 / 従業員 0 / 作品 0）は seed と異なる
- 期待値：funds=50,000,000、library 2 本、employees 3 人、achievements 2 個 等
- 実際：funds=15,000,000（デフォルト？）、空の library / employees
- **原因**：storage.ts のロード時にスキーマ検証 or マイグレーション処理で seed が無効化されている可能性
- 影響：テスト・スクリーンショット駆動の検証フローが回らない
- **修正必須**：seed の構造を storage.ts の Persisted 型に合わせる、または migration を経由させる

### 2-3. ⚠ **既存テスト（smoke / office-screenshot）の破綻**
- 全 9 件 timeout（「オフィスへ」ボタン非存在）
- 原因：v0.10 で初期画面が OfficeScreen に変わり、UI セレクタが変化
- CI が落ちる、リグレッション保証なし
- **修正必須**：tests/smoke.spec.ts と tests/office-screenshot.spec.ts を v0.10 UI 用に書き直し（O-1, O-2）

### 2-4. ⚠ **Library 画面への遷移失敗**
- スクショで「作品」クリック → 同じ Plan 画面が表示された（PlayWright のクリック判定ミス or 遷移実装の問題）
- ユーザーが手動で遷移すれば動くと思われるが、自動テストでブロック
- **修正**：PixelMenuBar のクリック判定見直し、または Playwright セレクタ修正

### 2-5. ⚠ **CollectionScreen の「発見 0 / 180」**
- seed の library 2 本が反映されないので、発見済みセルがゼロ
- これも 2-2 と同じ原因の可能性
- 実機で 1 本リリースすれば 1 マス埋まるはず

## 5. プロデューサーの判断

### 5-1. 「リリース可能か」
**まだ不可**。OfficeView スプライト 404 が見えると「未完成感」が強く、ユーザーがプレイ前に離れる。
これを直すだけで第一印象が大きく改善する。

### 5-2. 次にやるべきこと（順序）
1. **OfficeView スプライト 404 修正**（1-2 時間）— 最優先、見た目の問題を解決
2. **既存テスト書き換え**（2-3 時間）— CI 復活、リグレッション保証
3. **シード問題調査・修正**（1 時間）— 検証フロー復活
4. **vitest 導入 + 単体テスト**（半日）— 数値系の信頼性
5. **P1 着手**（数日）— タイピング長尺化 → 設備 → 採用ガチャ → 多層モチベ

### 5-3. v0.10 リリース目標
P0 のコア機能は揃った。**残作業は「O 系補修 + P1 全部 + P3 全部」**。
集中して進めれば 1 週間以内に「v0.10 として遊べる」状態に。
