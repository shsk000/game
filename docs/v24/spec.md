## 0. この版の位置づけ（冒頭・重要）

ローンチ（一般公開）に向けた**仕上げの版**。本来は「磨き」と「収益化」の2本柱だが、
**収益化（広告SDK・デプロイ）は着手保留**となったため、本版で手を動かすのは**磨き（音・チュートリアル・タイトル）**が中心。

**実装の実態＝「ゼロから作る」のではなく「既にある土台を本実装へ引き上げる」**。調査で判明した現状:

| 系統 | 既にあるもの | 本版で足す/替えるもの | 本版で着手 |
|---|---|---|---|
| 音 | 内蔵シンセSE `src/utils/sfx.ts`（11音・稼働中、DevelopScreen中心）／ジュース `JUICE_CONFIG`(`data/balance.ts:349`)＋`core/juice.ts`（v20強化済み） | BGM／ミュート・音量／DevelopScreen外（特にReleaseScreen）へのSE展開 | ○ |
| チュートリアル | `src/components/Tutorial.tsx`（4ステップ固定・PlanScreen依存） | 初回導線の刷新 | ○ |
| タイトル | 無し（起動即オフィス。`screen:'office'` 初期値 `gameStore.ts:216`） | タイトル画面新設 | ○ |
| 広告 | 抽象レイヤ `src/ads/AdProvider.ts`（`mockProvider`）／リワード**5箇所が配線済み** | `setAdProvider` で実SDKに差し替え／未配線3つ／デプロイ | **保留（後日）** |

→ 本版は「音と磨きで**手触りを仕上げ**、収益化は準備が整い次第 別フェーズで本実装する」。

## 1. 事業目的と前提

最上位の目的（game-design スキル）継承：広告収益／**広告は人質にしない**／誰も弾かない／長く遊ぶ人が一番得する。
課金は入れない。**サーバーレス静的構成を維持**（roadmap:81。マルチプレイ/ランキングサーバーはやらない）。

収益化フェーズでは「広告を人質にしない」が**レビューの必須ゲート**になる（§7）。

## 3. 各機能の設計

### 3-A. 音（BGM／SE／ミュート・音量）

- **現状**：`sfx.ts` が `AudioContext` で矩形波ビープ11音（key/crit/combo/rare/crunch/gear/miss/complete/alert/success/phase）を鳴らす。
  発火は `DevelopScreen.tsx` に集中し、**ReleaseScreen 等は無音**。ミュート機構は無い。BGM も無い。
  旧実装 `src/utils/sound.ts`（死にコード）に `window.__sfxMuted` ベースのミュート方式が残る。
- **やること**：
  1. **ミュート/音量**：状態を `gameStore` に追加し永続化。設定モーダル（`OfficeScreen.tsx:914`）にトグル＋スライダー。
     `sound.ts` のミュート方式を現行 `sfx.ts` に統合し、**死にコード `sound.ts` は削除**。
  2. **SE展開**：`DevelopScreen` 以外へ。特に **リリースファンファーレ**（`ReleaseScreen` の `releaseWork` 付近）、
     レベルアップ・実績解放。フックは state/store アクション後の副作用として挿す。
  3. **BGM**：ループ再生機構を新規（`sfx.ts` の AudioContext 再利用 or 音源ファイル）。画面別に切替。
- **音源方針 🔧**：ゼロ依存の内蔵シンセ路線を続けるか、外部音源（要・商用ライセンス、game-design §8 の権利厳守）を
  入れるか。BGM は内蔵シンセだと質が厳しいので要判断。
- **因果チェーン**：音は演出のみで経済数値に一切影響しない（安全）。

### 3-B. 磨き（チュートリアル刷新／タイトル画面）— 今回対応不要（次版・オーナー指示 2026-07-19）

- **チュートリアル**：現状 `Tutorial.tsx` は4ステップ固定テキストで、表示トリガが **PlanScreen 依存**（`PlanScreen.tsx:584`）＝
  初回導線として弱い。**初回起動時に確実に出す導線**へ刷新。インタラクティブ誘導/ハイライトの深さは段階的に 🔧。
  状態 `tutorialDone`（`gameStore.ts:186`）は流用。
- **タイトル画面（新設）**：現状は起動即オフィス（`screen: 'office'` 初期値 `gameStore.ts:216`、`Screen` union `types.ts:6` に title 無し）。
  3点新設：`Screen` union に `'title'` 追加／初期値・boot 分岐（`App.tsx`）でセーブ有無により出し分け／タイトルUI。
  継続プレイ時にタイトルを挟むか直行かは 🔧。
- **因果チェーン**：導線・表示のみ、ロジック無変更（安全）。

### 3-C. 収益化（広告SDK本実装／デプロイ）— 着手保留（オーナー指示 2026-07-19）

> 本版では着手しない。方針だけ残し、準備（デプロイ先・広告SDK選定）が整ったら別フェーズで本実装する。

- **広告SDK 本実装**：
  - 抽象レイヤ `src/ads/AdProvider.ts` の `mockProvider` を**実SDK provider に差し替え**（`setAdProvider`）。
    リワード5箇所（市場調査／マーケティング／デバッグチーム／ローンチ／デバッグ応援）は**既に配線済み**で、実SDKを差せば動く。
  - **視聴完了コールバック後に付与＋フォールバック必須**（`AdProvider.ts` 冒頭コメント／v08§6 の鉄則）。
  - **未配線3つ**（強制広告 `showInterstitial`／開発加速×2 `buyAdDevBoost`／オフライン2倍）を配線するか判断 🔧。
- **広告配置の数の整合（要確定）**：roadmap は「**配置4箇所は確定済み**」だが、一次資料の spec は
  **リワード6種＋強制1種**（`docs/v09/spec.md:288` が最新確定表、デバッグ応援は `docs/v19/spec.md:68`）、
  実装は**リワード5箇所**。「4」という数の出典が無い。着手時に**配置リストを1つに確定**させる 🔧。
- **SDK選定＋デプロイ先（未着手・後戻りしにくい）**：現状 base 未設定・ホスティング/CI/manifest すべて無し。
  サーバーレス静的構成が制約（roadmap:81）。選択肢は密結合なので**同時に決める**:
  - (a) **自前静的ホスティング**（Vercel/Netlify/GitHub Pages）＋ **Google H5 Games Ads**
  - (b) **ゲームポータル配信**（CrazyGames/Poki 等）＋ **各ポータルSDK**（独占条件・審査・専用SDKに注意）
  - **着手前にオーナー決定**（調達・契約・後戻りコストが大きい判断）。
- **レビューゲート**：広告OFFで全規模クリア可能を検証で担保（最上位の目的「人質にしない」）。

## 6. 技術メモ

- 状態追加の3点セット：`GameState`（`gameStore.ts`）＋ `boot.ts` の save/hydrate ＋ `storage.ts` の `Persisted`。
  音量/ミュート等の**追加フィールドは `shapeLoaded` が欠損補完する**ため、defaults 追加で足りる可能性が高い
  （version bump 要否は後方互換で判断 🔧）。
- 音・演出は**ゼロ依存路線**（内蔵シンセ `sfx.ts` ＋ CSS `@keyframes`。framer-motion 等は不使用）を踏襲。
- ロジックは `src/core/` 純関数、rng/時刻は `Deps`（`core/ports.ts`）経由（logic-architecture 規約）。
- （収益化フェーズ）デプロイ：`vite.config.ts` の `base` 設定／ホスティング／CI（`.github/`）／`index.html` meta・OGP／
  （ポータル配信なら）各SDKの script 挿入。デプロイ先により内容が変わる（§3-C 決定後に確定）。

- **音**：心地よさ・BGMの良さは機械検証不可 → オーナー確認待ち（§8）。

- **（収益化フェーズ）広告レビューゲート**：広告を全部 OFF にしても全規模クリア可能であること
  （`progressionSimulation.test.ts` 相当を「広告なし」条件で担保）。広告が進行の人質になっていないか。
