# 「発見した組合せ 0 / 756」をやめる（つぎの目標が一生埋まらない）

- **id**: `20260725-collection-denominator`
- **優先度**: P2（低リスク・純表示・経済に無影響）
- **ステータス**: 未完了
- **出典**: 責任者が現ゲーム（`:5174`）を新規プレイヤーとして実プレイ（オフィス画面の 🎯 つぎの目標）＋ `src/core/goals.ts` / `CollectionScreen.tsx` 読解
- **最上位の目的**: 継続＝広告収益（game-design §0/§10）

## 2. 課題（Problem）

**「あと少しで次」を作るための 🎯 つぎの目標ウィジェットが、新規プレイヤーに「0 / 756」という到達不能な分母を突きつけている。**しかも同じ図鑑の進捗を、図鑑画面は別の分母で表示している。

実機（新規プレイ・オフィス画面）：

```
🎯 つぎの目標
  🏢 スマホゲーム解放まで   あと ¥3000万
  👥 従業員を採用しよう      オフィスの採用から
  📖 発見した組合せ         0 / 756      ← これ
```

コードで裏取り：

| 場所 | 分母 | 値（新規時） |
|---|---|---|
| 🎯 つぎの目標（`src/core/goals.ts:75`） | `GENRES.length * THEMES.length` ＝ **全母集団** | **0 / 756** |
| 📖 図鑑画面（`src/features/collection/CollectionScreen.tsx:108,127`） | `visibleGenres.length * visibleThemes.length` ＝ **解放済みのみ** | **0 / 9** |

図鑑画面のほうは v0.10 の確定方針「未解放ジャンル / テーマは図鑑にも出さない（何があるか分からない設計）」（`CollectionScreen.tsx:65`）に従って正しく解放済みで割っている。**目標ウィジェット側だけが全母集団で割っており、方針と食い違っている。**

新規プレイヤーの解放は stage1 の 3 ジャンル × 3 テーマ ＝ **9 マス**。そこに「0 / 756」と出るので、

- 分母の 747 マスは**まだ存在すら見えていない**（図鑑にも出ない）
- v0.29 で解放は購入制一本化（無償の自動解放を廃止）になったため、756 に近づく手段は**資金だけ**
- 序盤は資金が尽きる側（→ `20260725-mini-solvency`）なので、**実質的に一生 0.x% のまま**

game-design §6 の「メタ進行 3 本柱」の柱2（コレクションが埋まる）と、§10-④「**常にどれか 1 つは『あと少しで達成』の状態を作る**（ツァイガルニク効果）」に対して、この表示は真逆に働いている。**「あと少し」を作るための枠が、「果てしなく遠い」を毎回表示している。**

## 3. プレイヤー体験（Job Story）

プレイヤーが「**1 本作り終えてオフィスに戻ったとき**」、「次に何を目指せばいいか知りたい」ので、「**🎯 つぎの目標を見て、あと 1 つ埋めれば進む手応えを得る**」。

いま得られるのは「0 / 756」＝ 0.13%。1 本作っても「1 / 756」で、進んだ実感がない。目標ウィジェットの他 2 項目（スマホ解放まで ¥3000万／社員 Lv2 まで exp 20）は距離感が具体的なので、**この 1 行だけが浮いている**。

## 4. 提案（What）＋UI導線・置き場所

- **🎯 つぎの目標の分母を、図鑑画面と同じ「解放済みプール」に揃える**：`src/core/goals.ts:75` の `GENRES.length * THEMES.length` を `unlockedGenres.length * unlockedThemes.length` に変更。新規プレイヤーは **0 / 9** になり、1 本作れば **1 / 9（11%）**＝進んだ実感が出る。
- **埋まりきったら次の目標に切り替える**：解放済みプールを全部埋めたら「📖 未解放のジャンル/テーマを買って図鑑を広げよう」に文言を差し替える（§10-④「常にどれか 1 つはあと少し」）。これでジャンル/テーマ購入（v0.21/v0.29）への導線にもなる。
- **UI 導線は既存のまま**：オフィス画面 🎯 つぎの目標の 3 行目。新規画面・新規素材なし。
- 全体像（756 マス）を見たい欲求は、図鑑画面側の既存表示（`CollectionScreen.tsx:177` の「未解放が N 種ある」相当）で足りているので、目標ウィジェットに全母集団を出す必要はない。

🔧 **要社長判断（軽微）**：解放済みプールを埋めきった後の文言を「購入を促す」方向にするか、単に「◯ / ◯ コンプリート！」で止めるか。責任者の推奨は**購入を促す**（メタ進行が途切れない）。

## 5. なぜ今／最上位の目的リンク

- **継続（§10-①・§10-④）**：コレクションは「明日も遊ぶ理由」の柱の 1 つ（§6 柱2）。その進捗表示が 0.13% では燃料にならない。分母を変えるだけで、毎作リリースするたびに +11% 進む体感になる。
- **メタ進行の連結（§10-④）**：埋まりきった時に「買って広げよう」に切り替わることで、**コレクション → 投資（購入）→ 新しい組合せの発見**というループが繋がる。今は繋がっていない。
- **同時起票との相性**：`20260725-trend-unlocked-pool`（トレンドを解放済みプールから抽選）と同じ「**解放済みプールを主語にする**」是正。片方だけだと「トレンドは狙えるのに図鑑の分母は 756」とちぐはぐが残る。セットで承認すると一貫する。
- **コストが極小**：純粋関数 1 箇所の分母変更＋文言分岐。経済数値・素材・レイアウトに一切触らない。

## 6. 成功条件・指標

- [ ] 新規プレイヤー（3 ジャンル × 3 テーマ）で 🎯 つぎの目標が **「0 / 9」** を表示する
- [ ] 1 本リリース後に **「1 / 9」** に増える
- [ ] 図鑑画面（`CollectionScreen`）の分母と**常に一致**する（両者がズレないこと）
- [ ] 解放済みプールを埋めきったら文言が「未解放を買って広げよう」に切り替わる
- [ ] `src/core/goals.test.ts` の既存テスト（「③発見した組合せはユニーク数」）を更新して緑
- [ ] ジャンル/テーマ購入後に分母が増える（購入 → 分母 3×3 → 4×3 → 0/9 が 1/12 になる等）ことを実機で確認
- [ ] 1280×720 固定・スクロールなしを維持（行数・文字数が増えない）
- **指標**：図鑑の発見率（解放済みプール比）、ジャンル/テーマ購入の発生率

## 7. スコープ外（Non-goals）

- 図鑑画面（`CollectionScreen`）のレイアウト・見せ方の変更（既に解放済み基準で正しい）
- ジャンル/テーマの価格・解放条件の変更 → §v0.28 / v0.29 申し送り
- 実績・称号システムの拡張
- 相性値そのものの設計変更

## 8. リスク／要社長判断

- 🔧 埋めきった後の文言（購入促進 ／ コンプリート表示のみ）。推奨は購入促進。
- **リスクは小さい**：純表示の変更で経済・セーブ・バランスに影響しない。ただし `goals.ts` は純粋関数なので `goals.test.ts` の期待値更新が必須。
- 分母が動的（購入で増える）になるため、「9 マス埋めた直後に買うと 1/12 に見えて後退した気がする」ケースがありうる。文言（「図鑑が広がった！」等）で吸収するか、達成済みマス数を主表示にするかは実装時に判断。
