## 1. 目的（オーナーの言葉で1行）

**画面に出した売上の数字を、実際にそのとおりにする。**

## 2. 課題（Problem）— 実コードで確認した4件

### 問題A：ローンチ広告「売上 +50%」の実効は **総売上 +10%**（← 指摘の本体）

| 場所 | 内容 |
|---|---|
| `ReleaseScreen.tsx:586`（旧） | ボタン表示 `📺 ローンチ広告 売上 +50%` |
| `ReleaseScreen.tsx:579`（旧） | 適用後表示 `✅ 適用済（売上 ×1.5）` |
| `ReleaseScreen.tsx:213`（旧） | 実装 `extra = round(work.initialRevenue * 0.5)` |
| `sales.ts:23` | `INITIAL_SHARE = 0.2`（初動は総売上の20%） |

→ `initialRevenue = 総売上 × 0.2` なので **extra = 総売上 × 0.10**。販売プール（80%）には効かない。

### 問題B：広告ボーナスが記録に残らない

旧 `runLaunchAd` が更新するのは `funds` と `lifetimeRevenue` **だけ**。

- `work.totalRevenue` に入らない → ライブラリ「累計」・図鑑の最高売上に反映されない
- `records.bestRevenue` にも入らない
- `bonusRevenue` は React ローカル state → **画面を離れると消え、利益見込の表示も元に戻る**
- `work.launchAdUsed` は常に false（`releaseWork` が `launchAd` を渡さない）→ セーブに履歴が残らない

### 問題C：デッドコード＋ドキュメント不整合

- `metascore.ts:83` の `launchBonus = launchAdActive ? 0.1 : 0` は**到達不能**
- `docs/scoring.md:95`「ローンチ広告 = +10%」はその到達不能コードを説明した誤記

### 問題D：企画画面の「予想売上レンジ／予想利益」が実式と**別の数列**

- 予測：`estimateRevenueRange(def.baseUnit)` ＝ `scales.ts` の `baseUnit` 系列
- 実売上：`SCALE_BALANCE[scale].baseRevenue × salesMultiplierForScore(メタスコア)`

**2つの数列に接点がない。** 素の額（ソフト補正なし）の実測：

| 規模 | 旧予測 mid | 旧予測 high | 実・致命的×0.33 | 実・失敗×3.33 | 実・普通×10 | 実・大ヒット×100 |
|---|---|---|---|---|---|---|
| ミニ | ¥100万 | ¥500万 | ¥10万 | ¥100万 | ¥300万 | ¥3000万 |
| スマホ | ¥300万 | ¥1500万 | ¥100万 | ¥1000万 | ¥3000万 | ¥3億 |
| **インディー** | **¥800万** | **¥4000万** | ¥999万 | ¥9999万 | **¥3億** | ¥30億 |
| **話題作** | **¥1800万** | **¥9000万** | ¥9990万 | ¥9.99億 | **¥30億** | ¥300億 |
| **AAA** | **¥4000万** | **¥2億** | ¥9.99億 | ¥99.9億 | **¥300億** | ¥3000億 |

→ **インディー以上は「予測の中央値」が「実際の最悪帯」すら下回る**＝企画画面の予想利益が
「大ヒット時」でも常に大赤字を表示していた。**規模選択の判断材料が丸ごと嘘。**

## 3. オーナー判断（2026-07-25）

> 「**50%+大きすぎる**」

→ **効果を上げる案（総売上×1.5）は不採用**。実効は据え置き、**表示を実態に合わせる**方向で確定。
→ 問題D も同様に「盛らない」方向で、中央値は想定分布どおり**失敗帯 ×3.33** を採用。

## 4. やったこと（What）

### D-1. ローンチ広告：効果据え置き＋ラベル是正＋加算経路の一本化

- ラベル `📺 ローンチ広告 **初動売上** +50%` ／ 適用済 `✅ ローンチ広告キャンペーン適用済（初動売上 ×1.5）`
- `core/release.ts` に純粋関数 `applyLaunchAd(work)` を新設（`LAUNCH_AD_INITIAL_MULTIPLIER = 1.5`）
  - `initialRevenue × 1.5` ／ `totalRevenue += ボーナス` ／ `launchAdUsed = true` ／ 販売プールは不変
  - 二重適用は `launchAdUsed` で `null` を返して弾く
- `gameStore.applyLaunchAd()` アクションを新設し、`lastReleased`・`library` の該当作・`funds`・
  `lifetimeRevenue`・`records.bestRevenue` を**まとめて**更新（問題B解消）
- ReleaseScreen 側の `useGameStore.setState` 直叩きを廃止。適用済み判定を `work.launchAdUsed` に変更
  （ローカル state だと画面を出入りすると未適用に戻り二重視聴できた）
- 表示は `work.initialRevenue` をそのまま使う（ボーナスは既に加算済み＝二重計上しない）

### D-2. デッドコードとドキュメントの整理

- `metascore.ts` の `launchAdActive` 引数と `launchBonus` を削除、`ReleaseOpts.launchAd` も削除
- `docs/scoring.md` §3-3 からローンチ広告を除去し、§4 に「発売後リワード」として実態を明記

### D-3. 企画画面の売上予測を実式に接続

`estimateRevenueRange(scale)` を `SCALE_BALANCE[scale].baseRevenue × 段倍率` に変更：

| 表示 | 段 | 倍率 |
|---|---|---|
| low | 致命的失敗（メタ0〜29） | ×0.33 |
| mid（中央値） | 失敗（メタ30〜49） | ×3.33 |
| high（大ヒット時） | 大ヒット（メタ80〜89） | ×100 |

`SCORE_TIERS` の想定分布（致命的20%＋失敗35%＝累積55%）で統計的中央値は失敗帯。
`sub` の表記も「平均」→「中央値」に是正。**再発防止に `ScaleDef.baseUnit` を削除**（別数列を残さない）。

### D-4. `balance.ts` の陳腐化コメント（「normal で ×16.67 = ¥500万」→ `normal(×10) で ¥300万`）を修正
