# 序盤の「段の崖」を越えられるようにする（1本目 ROI -89% の是正）

- **id**: `20260725-mini-solvency`
- **優先度**: P0（要社長判断・経済バランスに触れる）
- **ステータス**: 未完了
- **出典**: 責任者が現ゲーム（`:5174`）を新規プレイヤーとして実プレイ（1本目を発売まで）＋ `src/data/balance.ts` / `src/core/release.ts` 読解
- **最上位の目的**: 継続＝広告収益（game-design §0/§10）

## 2. 課題（Problem）

**新規プレイヤーの1本目は、メタスコアの段の崖（29→30 で売上倍率が 10 倍）の"下側"に構造的に落ちる。**そして Lv1 の社員では、崖を越えても損益分岐がほぼ理論上限になる。

### 実測（新規プレイ・社員 1 人 Lv1 ランク B・ミニゲーム・DEV スキップ＝タイピング50点/運50点の平均成績）

| 項目 | 実測値 |
|---|---|
| 品質 Q → メタスコア | 24 →『**バグだらけ**』 |
| 売上見込（マーケ広告込み） | ¥11.5万 |
| 利益見込 | **-¥97.7万 / ROI -89.4%** |

結果画面の品質内訳（実機表示）：

| 要素 | 実力 | 重み | 品質寄与 |
|---|---|---|---|
| 🧑‍💻 キャラ能力 | **9 点** | 60% | **+5** |
| 🧩 ジャンル相性 | 38 点 | 15% | +6 |
| ⚡ タイピング演技 | 50 点 | 15% | +8 |
| 🎲 運 | 50 点 | 10% | +5 |
| 🎪 イベント成果 | — | — | +5 |
| **合計 Q** | | | **24** |

### 因果（コードで裏取り）

1. **段の崖**：`salesMultiplierForScore`（`src/data/balance.ts:90-98`）は メタ ≤29 で **×0.333**、メタ 30〜49 で **×3.333**。**1 点差で売上が 10 倍**。中央値プレイヤーの Q=24 はこの崖の**すぐ下**。
2. mini の `baseRevenue` は ¥30万（`SCALE_BALANCE.mini`）。段倍率を掛けた素の売上は 致命的 ¥10万 / 失敗 ¥100万 / 普通 ¥300万。
3. 固定費は **¥79.2万/月**（給与 ¥49.2万 ＋ 賃料 ¥30万）。mini の想定期間は `neededWeeks` 8 週 ＋ `planWeeksAllowance` 4 週 ＝ **12 週（3 ヶ月）＝ ¥237.6万**（実測は DEV スキップで 1 ヶ月＝¥79.2万）。
4. **Lv1 ランク B ではキャラ能力が 9 点**（100 点満点）。重み 60% なので寄与は +5 で頭打ち。相性・タイピング・運をすべて満点にしても **Q の理論上限は ≒ 50**（5 + 15 + 15 + 10 + 5）。

### 帰結

| メタ帯 | 素の売上 | 利益（開発費¥30万＋固定費3ヶ月¥237.6万） |
|---|---|---|
| 24（実測・中央値） | ¥10万 | **-¥257.6万** |
| 30〜49（崖を越える） | ¥100万 | -¥167.6万 |
| 50〜69（普通） | ¥300万 | **+¥32.4万** |

**損益分岐＝メタ 50 は、Lv1 ランク B 社員での理論上限とほぼ同値**。つまり中央値プレイヤーは黒字にならず、上限を出しても収支トントン。初期資金 ¥445.8万（¥500万 − 採用 ¥54.2万）は **4〜5 本で尽きる**。しかも会社を育てる原資は作品の売上だけなので、**出口の閉じた円環**になっている。

これは game-design §10-② の「**序盤で破産ウォールや『失敗』の負の強化に偏ると①（継続＝広告収益）を殺す**」に真正面から抵触する。初回セッションで『バグだらけ』と ROI -89% を突きつけられたプレイヤーは、広告を 1 本も見ずに離脱する。

> **注記（並走セッションの発見と切り分け）**：企画画面の「予想利益（中央値）-¥167.6万」表示は、`20260725-revenue-honesty` の**問題D**（予測が実式と別の数列）により**そもそも当てにならない**ため、本提案の根拠には使っていない。根拠は上表の**実測値と実式**のみ。逆に言えば D-3（予測の実式接続）を直しても、上記の**実際の採算は 1 円も変わらない**。表示の是正（revenue-honesty）と採算の是正（本提案）は別問題。
>
> roadmap §v0.28 B-2/B-3/B-4 として起票済みの課題を、実プレイの実数で裏取り・精緻化したもの。B-1 の solvency シミュは `src/core/solvencySimulation.test.ts` として実装済みなので、判定の土台は既にある。

## 3. プレイヤー体験（Job Story）

プレイヤーが「**初めてゲームを作り終えて結果を見たとき**」、「自分の会社が伸びている手応えが欲しい」ので、「**次はもっと大きいのを作ろう、と思ってオフィスに戻る**」。

いま起きているのは真逆で、「1 本目＝『バグだらけ』＋ ROI -89%」→「2 本目も同じ」→「資金が減るだけ」。§10-④ のツァイガルニク（あと少しで次）ではなく、**確定した敗北の反復**になっている。

## 4. 提案（What）＋UI導線・置き場所

**stage1（ミニゲーム）を「収支を学ぶ練習場」にする。**中央値プレイヤーが 1〜2 本目で段の崖を越え、3 本目までに黒字を一度は見られる幅にする。

方針は 🔧 社長判断。責任者の推奨は **案A ＋ 案B の併用**。

| 案 | 内容 | 触る場所 | 影響範囲 |
|---|---|---|---|
| **案A（推奨）** | **段の崖をならす**：`catastrophic` 0.333 → 1.0 程度に引き上げ、29/30 の 10 倍ギャップを縮める | `src/data/balance.ts:79-87` | 全規模に波及。roadmap B-3（段の非線形）も同時に解消 |
| **案B（推奨・併用）** | **Lv1 のキャラ能力の底上げ**：ランク B Lv1 で 9 点は低すぎる。序盤の天井（Q上限50）を押し上げる | `ROLE_EFFECT` / ガチャのランク帯 / レベル換算 | 序盤に厚い。品質式の**重みは変えない**（§0 確定方針） |
| 案C | stage1 の間は「自宅の一室」扱いで**賃料 ¥30万 を免除**（オンボーディング猶予） | `MONTHLY_RENT` の適用条件 | 序盤限定・副作用が最も小さいが、効き幅も小さい（-¥90万/3ヶ月） |
| 案D | mini の `baseRevenue` / `neededWeeks` を見直す | `SCALE_BALANCE.mini` | mini のみ。mobile 解放（累計 ¥3000万）までの本数が変わる |

- **UI 導線（変更が見える場所）**：新規 UI は作らない。効果が出る場所は **リリース結果画面のメタスコアと売上画面の利益**。加えて結果画面のアドバイス（実機で「👥 社員の力不足が響いた。育成か採用で会社を強くしよう」）は正しい方向を指しているので、**そのアドバイスに従えば実際に効く**状態になる（今は従っても資金が先に尽きる）。
- **やらないこと**：品質式の重み（charPower 0.6 / タイピング 0.15）は §0 の確定方針なので触らない。「腕でメタスコアの段を越えさせる」設計には戻さない。

## 5. なぜ今／最上位の目的リンク

- **継続＝広告収益（§10-①）**：初回セッションの離脱は広告視聴のすべてを失う。破産ウォールは最上位目的への直接の損失。
- **誰も弾かない（§10-②・絶対原則）**：現状は「腕を上げても Lv1 では収支トントンが上限」。人質にしているのは広告ではなく**採算そのもの**。
- **他の広告提案の前提**：同時進行の `20260725-revenue-honesty`（ローンチ広告を総売上 ×1.5 に）も、既存の `20260725-rescue-ad`（月末レスキュー広告）も、**採算の谷が -¥100万〜-¥258万規模のままでは焼け石に水**。実測で広告 2 本を見ても ROI が -89.4% → -88.4% しか動かなかったのがその証拠。ここを直して初めて「広告を見れば赤字が黒字にひっくり返る」救済（roadmap A-4）が成立する。
- **ソシャゲ型メタ進行（§10-④）**：「会社の育ちが勝敗を決める」（§0）設計自体は正しい。問題は**育てる原資を得る手段が塞がっている**こと。入口だけ開ける。

## 8. リスク／要社長判断

- 🔧 **どの案を採るか（A / B / C / D、併用可）**。責任者の推奨は **A＋B**。
- 🔧 **そもそも是正するか**：roadmap §v0.28 の注記どおり「**失敗 2-3 本で詰むのを意図として据え置く**」も選択肢。据え置く場合、序盤リテンションと広告収益を捨てる判断になるため、明示的な決定が要る。
- **バランス改変リスク**：緩めすぎると資金インフレ（§7 経済原則 3）。判定は既存 3 シミュレーションテストをゲートにする。
- 案A は段テーブルを触るため**全規模に波及**（影響が最も広い）。案B は Lv1 帯だけを動かせるので副作用が読みやすい。
- roadmap B-5（社員 0 でのソロ不可＝最低 1 人採用が強制）は本提案のスコープ外だが、固定費デススパイラルの入口として関連する 🔧。
