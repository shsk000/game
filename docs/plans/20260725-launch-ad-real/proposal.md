# ローンチ広告を表示どおり効かせる（**取り下げ・重複**）

- **id**: `20260725-launch-ad-real`
- **優先度**: —
- **ステータス**: 却下（重複のため取り下げ）
- **却下理由**: 起票直後に、並走セッションが同じ課題をより網羅的に起票済みであることを確認した。
  → **`docs/plans/20260725-revenue-honesty/proposal.md` に一本化する。**

## 重複の内容

本提案が挙げたのは以下2点：

1. ローンチ広告のボタン表示「売上 +50%」／適用後「売上 ×1.5」に対し、実効は**総売上 +10%**
   （`ReleaseScreen.tsx:213` `work.initialRevenue * 0.5` × `INITIAL_SHARE = 0.2`）
2. `metascore.ts` の `launchBonus`（+10%）がデッドコードで `docs/scoring.md:95` と不整合

`20260725-revenue-honesty` は上記を**問題A・問題C**として同じ file:line で押さえたうえで、さらに

- **問題B**：広告ボーナスが `work.totalRevenue` / `records.bestRevenue` / `launchAdUsed` に残らず、画面を離れると消える
- **問題D**：企画画面の「予想売上レンジ／予想利益」が実式（`baseRevenue × 段倍率`）と**別の数列**（`baseUnit` 系列）で、インディー以上は予測中央値が実際の最悪帯すら下回る

まで含んでおり、上位互換。加えて「実装が確定仕様（`docs/v09/spec.md:292`「初動・販売プール双方に効く」）から外れた**バグの是正**であってバランス変更ではない」という筋の通し方も本提案より正確だった。

## 本提案から引き継ぐ実測値（参考）

実機（新規プレイ1本目）で広告を押して測った before/after。`revenue-honesty` の裏付けに使える：

| | 売上見込 | ROI |
|---|---|---|
| 広告前 | ¥11.5万 | -89.4% |
| ローンチ広告（表示「+50%」）後 | ¥12.7万（**+10.4%**） | -88.4% |

マーケティング広告 ×1.10 と合算しても **×1.21** で、game-design §7 の「広告ありだと体感 1.3〜2 倍」に未達。
