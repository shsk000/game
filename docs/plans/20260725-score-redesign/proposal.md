## 1. なぜ引き直すのか（現行実装の破綻・実測済み）

| # | 問題 | 実測・根拠 |
|---|---|---|
| 1 | **1文も打たずに「ヒット」が出る** | 社員能力85・相性80で品質約72＝メタ70台。社員能力が打鍵と無関係に品質の60%を占める |
| 2 | **上手い人ほどイベント報酬が0になる** | 品質の加点枠8点を devStats とイベント報酬が共有。速い人は devStats だけで8点に張り付く |
| 3 | **装備が「社員の能力」を上げていない** | 装備は作品側の数値に掛かる別枠6点。社員には何も起きない |
| 4 | **デザイナーの効果が存在しない** | `sumDesignerBonus` が未接続。表示「品質基礎 +5.0」だけがある |
| 5 | **社員の得意分野が存在しない** | `specialties` はガチャ演出の表示のみ。カテゴリ体系も4種の作業と不一致 |
| 6 | **devStats がプレイヤーに見えない** | 品質の5〜8点を決めるのに画面に出ない |
| 7 | **「運」が運になっていない** | 常に50点固定＝全員に配られる下駄 |
| 8 | **イベント「開発期間−1週」が表示だけ** | カレンダーも固定費も動かない |
| 9 | **終盤に1作で兆が出る**（新設計の検証で判明） | 売上倍率×500は「神ゲー=1%」前提。新モデルでは終盤の常態になる |

**共通の病理**：スコアへの経路が並列に4本（社員60%／打鍵15%／加点枠8点／装備枠6点）あり、
互いに独立なので「何をすればスコアが上がるか」が繋がらない。

## 2. 実装の段階分割

**実装ステップ** ＝ この計画の実装単位。1ステップごとに検証して出荷できる。
**ゲーム内の「フェーズ」（企画→開発→テスト→デバッグ）とは別物**（用語集参照）。

### 実装ステップ1：社員のスキル化（データ基盤）

**やること**
- `Employee` を新形式に：**スキル（5種のうち1〜2個・0〜100）／総合力／ランク C/B/A/S**。
  レベル成長を天井型（Lv1ほぼ同じ→Lv10でランク差）に。2スキルは分散ペナルティ ×0.9
- **職種表示を「一番高いスキルの呼び名」に変更**（役割の管理をやめる）。経験値カーブは🔧（ステップ内で確定）
- 採用ガチャを4種ランク構成に（排出率🔧）。スキル数は 50/50 🔧・スキルの振り
- **セーブ移行 v7→v8**：既存社員の `power`（0..1）→ 総合力へ換算、`specialties` 廃棄、役割→主スキルに変換
- ~~**互換アダプタ**：現行の品質計算が使う `power` を「総合力÷100」で導出して残す~~
  → **不採用（実装中に判明）**。旧 power 帯（B 0.2〜0.4）と新しい総合力帯（Lv1 15〜28）は
  単位が違い、÷100 は変換にならない。採用社員の平均能力が半減し、序盤の総売上が10分の1になった。
  **代わりに「power / role / ランク排出は旧ロジックのまま凍結し、スキルは同じ値の別表現
  （旧 power × 100）として並走させる」形にした。** ランクの天井・C の排出・分散ペナルティ・
  スキル上限100 は実装ステップ3 で一度に有効化する
- UI：社員リスト・ガチャ開封・企画画面のスキル表示（「品質基礎+5.0」等の嘘表示はここで削除）

**完成条件**
- [x] ガチャを引くとスキル1〜2個持ちの社員が出て、開封画面にスキルとランクが出る
- [x] 既存セーブを読み込んでも社員が壊れない（旧 power から変換される・ランクも帯から復元）
- [x] 現行のスコア・売上の数値が**一切変わらない**
  （本番経路 `pullGacha` からの分布ガード＋採用→発売の通しガード。
  **どちらも回帰を再現したコードで実際に落ちることを確認済み**）
- [x] 4点セット全緑（build / unit 475 / ui 14 / e2e 7）

**実装で分かったこと（同じ轍を踏まないために）**
1. **スケールの違う2つの値を「変換」でつなごうとしない。** 切り替えは一点に集約する
2. **ガードは本番が実際に呼ぶ入口から通す。** 「同じ入力なら同じ出力」は恒真になりやすい
3. **ガードは落ちるところを一度実際に見るまで信用しない。** 本実装では2度、
   本番が通らない経路にガードを置いて回帰を素通しさせた

### 実装ステップ2：打鍵 → 特徴ポイントの蓄積（まだスコアに接続しない）

**やること**
- 作業チケットを4分野（プログラミング/グラフィック/サウンド/シナリオ）に付け替え。
  旧「ゲームデザイン」の文プールをシナリオ向けに改稿 🔧（コンテンツ作業）
- `CurrentProject` に特徴ポイント5種を追加。加算式・カバー分野のみのローテーション・
  同分野2人目×0.5・打鍵倍率 0.95〜1.05・ミニ4週化（すべて spec の確定値）
- 開発画面に**特徴ポイントのリアルタイム表示**と加算ポップ（「🎨 +2.7」）
- この段階では**品質計算に接続しない**（蓄積と表示のみ）。実測検証がしやすい
- **企画フェーズの打鍵は現行のまま**（効き先の変更は 実装ステップ3 までの決定を待つ）

**完成条件**
- [x] 文を打ち切ると該当分野の特徴ポイントが式どおり増える（実測 25.6／27.5 vs 期待 25.1〜27.7）
- [x] チームにスキルが無い分野の文は出ない・総打鍵量が減る（4分野=12文／2分野=6文／1分野=3文）
- [x] ミニゲームが4週（12文）で完成する
- [x] 現行のスコア・売上は不変のまま（この時点では未接続）
- [x] 4点セット全緑

### 実装ステップ3：メタスコア・売上の切り替え（スイッチを入れる）

**やること**

まず **実装ステップ1 で意図的に保留した「値の切り替え」を一度に有効化する**
（実装済みだが本番から外してあるもの。取り落とすと確定仕様が入らないまま先へ進む）：

- [x] `gameStore.pullGacha` のランク抽選を `rollRank` → **`rollRank4`**（C を含む4種）に切り替え
- [x] 排出率の参照を `GACHA_CONFIG[kind].rates` → **`GACHA_RANK_RATES`** に切り替え（C の解禁）
- [x] 総合力の生成を「旧 `power` × 100」→ **`RANK_TOTAL_POWER`（ランクの天井）** に切り替え
- [x] 成長を `powerAt` → **`growSkills`**（天井に向かう伸び）に切り替え
- [x] **分散ペナルティ ×0.9 を有効化**（`rollSkills` / `distributeSkills` の第3引数を既定へ戻す）
- [x] **スキルの上限 100 を導入**（いま総合力は旧 power と同じスケールなので 100 を超えうる）
- [x] 旧セーブ移行の `basePower` → 総合力の換算を、新スケール（ランク帯）へ作り直す
- [x] **開封画面に到達点（「育てば 100」）を表示**（天井が入るのと同時。先に出すと嘘になる）
- [x] `docs/spec/score-model.md` 冒頭の ⚠ 表と `glossary.md` の「未接続」表記を消す

そのうえで本体：

- 型6種データ＋27ジャンル割当。メタスコア＝Σ(特徴ポイント×重み)＋トレンド＋評価家のブレ
- 革新性（同じジャンル×テーマ連投の判定。作品履歴から）
- ヒット区分の売上倍率 ×0.25〜×10・基準売上の再定義
- **旧経路の削除**：`computeQualityV10`／`charPower`系／`QUALITY_WEIGHTS`／品質系の軸／
  共有CAP群／運50／`specialties`／`ROLE_EFFECT`／互換アダプタ
- **カテゴリ6種一式の削除**：`categories.ts`／`unlockedCategories`／`Work.selectedCategories`／
  `computeNewlyUnlockedCategories`（永久に解放されない死に処理）／セーブ項目
- **広報スキル→売上倍率・バグ抑制→プログラミングスキルの付け替え**（式は🔧。旧 power 前提の2式を置換）
- **既存イベントの報酬付け替え**：品質系の軸（面白さ/操作性/バランス）の廃止で無効になる報酬を、
  有効な効き先へ暫定変更する（「効かない報酬」を再発させない。イベント本体の作り直しは別プラン）
- **相性の効き先の実装**（GO前の判断事項。下記）
- リリース画面のブレイクダウンを特徴ポイント5項目に作り替え。**ヒット区分名の表示と
  スコアフレーバー（「今年の傑作」等）の整合**もここで取る
- **企画画面に選んだジャンルの◎○△を表示**（「このジャンルで重要な分野」が見える）
- シミュレーションテスト（progression/solvency/balance）を新式で書き直し

**完成条件**
- [x] 通しシミュレーションで、ミニ／スマホ／インディー／話題作の本数がそれぞれ 7〜9本に収まる（実測 8 / 16 / 24 / 32 本目に解放＝各8本）
- [x] 1文も打たずに発売すると致命的失敗になる（実測：平均メタ 12・致命的失敗率 100%）
- [x] リリース画面に特徴ポイント5項目の内訳が出る（相性・トレンド・評価家のブレも。1280×720 スクロールなし）
- [x] 1作の売上が最大でも数百億（AAA神ゲー＝¥500億）
- [x] 通しシミュレーション：序盤に破産しない（中央値プレイヤーは2本目で黒字転換・破産なし）
- [x] 4点セット全緑＋実機で企画→開発→発売を1周（入門チームでメタ74〜79＝ヒット）

## 3. このプランに含めない（別プランに切り出す）

| 項目 | 理由 |
|---|---|
| **イベントの作り直し**（企画完了時モーダル・打鍵なし・状態依存の発生） | 方向は合意済み。詳細設計が未着手（8秒抽選と企画打鍵の扱いは決定済み） |
| **経済トラック**（開発費・解放閾値・ミニ以外の週数・金の使い道） | スコアモデルとは独立に調整できる。実装ステップ3 の通しシミュレーション後に起票 |
| ガチャ・装備の**価格** | 経済トラックに含める |
