## 2. 何を作ったか

**スコアと売上を「打鍵 → 特徴ポイント → メタスコア → ヒット区分 → 売上」の一本道にした。**
この経路以外でスコアは動かない。

```
【スキル】社員が持つ能力（5種）
      ↓ 開発フェーズの打鍵で積む（規模係数 × 打鍵倍率 × スキル合計）
【特徴ポイント】操作性／グラフィック／サウンド／ストーリー／革新性（各0〜100）
      ↓ Σ(特徴ポイント × ジャンルの型の重み) ＋ 相性 ＋ トレンド ＋ 評価家のブレ
【メタスコア】0〜100
      ↓ ヒット区分の売上倍率（×0.25〜×10）
【売上】
```

### 実装ステップ

| | 内容 | コミット |
|---|---|---|
| 1 | 社員の能力を `power` 単一値 → **スキル5種 × ランクの天井** | `ae52947` `4b7b865` `75d3426` |
| 2 | **打鍵で特徴ポイントが積み上がる**（まだスコア未接続） | `87dc49d` |
| 3 | **メタスコア・売上を新モデルへ切り替え**＋旧経路を削除 | `b02958d` `7865728` `5d144c8` |
| 4 | **装備を社員のスキルに掛ける**方式へ | `7865728` |

### 削除したもの（復活させない）

品質 Q（キャラ能力・ジャンル相性・タイピング演技・運の基底50 の合成）／カテゴリ6種一式／
品質系の軸（面白さ・操作性・バランス）／devStats と装備の品質加点／`ROLE_EFFECT`／
軸「売上予測」／旧 `computeMetascore`・`computeQuality`・`hitTierMultiplier`・
`SCORE_BASE`・`LUCK_DEFAULT`・`rollSpecialties`・`sumProgrammerPower` ほか。

## 3. プロデューサーが代理で決めたこと（オーナー不在のため）

オーナー指示「実装中に不足箇所があり確認が必要となっても producer に相談し
決定した内容で開発をすすめてください」に基づく。**オーナーが覆せる。**

### 決定1. ガチャ開封に「育てば○○」を表示する

**Lv1 の総合力はランクによらずほぼ同じ**（15〜28）なので、開封した瞬間の数値では
C と S の差が分からない。ランクバッジの文字だけが差になり、引いた瞬間のペイオフが立たない。
そこで**到達点**（Lv10 の値）を併記する。

```
グラフィック 24 → 育てば 100
```

- 2スキル持ちは分散ペナルティ込みで出す（S の2スキル持ちは合計90。100 とは言わない）
- **却下した案**: Lv1 の幅を広げる → 採用直後に差が小さいのは確定仕様の狙い（序盤の難易度を緩める）。
  ガチャの快感のために序盤を厳しくするのは順序が逆で、破産ウォールを悪化させる
- **却下した案**: C の排出率を下げる → 安い normal にハズレが混じるからこそ premium に価値が出る。
  **ハズレの存在ではなく、ハズレだと分からないことが問題**だった

⚠ **確定仕様に関わる判断**。オーナーが最も覆したい可能性がある。

### 決定2. ゲーム規模の解放ペースは「4規模を7〜9本ずつ、AAA は残り全部」

当初は「解放閾値は経済トラック（別プラン）のスコープだから触らない」と判断したが、
**売上テーブルの入れ替えと不可分**だと分かった時点で撤回した。

実装前は **23本目に AAA まで全部開き**、内訳は ミニ10／スマホ6／インディー5／**話題作2**／AAA 22。
話題作は「その規模用にチームを組んで試す」前に終わる長さで、
企画（ジャンルの◎○△に合わせて人を選ぶ）という設計の主眼が働かない。

**実測 8 / 17 / 24 / 31本目**（閾値 ¥1.5億／¥17億／¥80億／¥350億）。

### 決定3. 重み △ を 0.3 → 0.5 に上げる

仕様の「分野ごとの公平性」チェックが **◎ の数しか数えていなかった**。

| | 🕹 操作性 | 🎨 グラフィック | 🎵 サウンド | 📖 ストーリー |
|---|---|---|---|---|
| ◎ のジャンル数 | 15 | 14 | 12 | 13 |
| **△ のジャンル数** | 10 | **0** | 3 | **14** |

◎ だけ見ると 📖=13 で健全だが、△ を数えると **📖 は27ジャンル中14（過半数）**が △ で、
🎨 は一度も △ にならない。0.3 では正規化後の寄与が 3.6% しかなく、
**シナリオライターが半分以上のジャンルで実質置物**になる（game-design §10-4 に反する）。

型テーブルの組み替え（27ジャンルの再割当）は後戻りが重いので採らず、
spec が設計した「調整は3定数で済む」という狙いどおりの一点変更にした。

### 決定4. 経験値をゲーム規模に連動させる

解放ペースに育成が追いつかなかった。解放は累計売上ゲートで、売上も閾値も規模ごとに ×10 で
伸びるため各規模は数本で次を解放するのに、必要 exp は `20 × Lv^1.5` で急増する。
実測では**話題作の解放時に Lv4**（想定 A級Lv7〜8）までしか育っていなかった。

```
exp = (基礎10 + メタ連動ボーナス) × ゲーム規模の倍率
     ミニ ×1 ／ スマホ ×3 ／ インディー ×6 ／ 話題作 ×12 ／ AAA ×24
```

- **却下した案**: カーブ指数（1.5）を下げる → 終盤の伸びしろ＝「あと少しで次のレベル」を弱める
- **副作用が狙いどおり**: 上位規模は**失敗しても経験値が入る**ので、
  「上位規模で失敗続き → 育て直しに戻れない」死の螺旋にならない。
  悲観シミュレーションでは定額のままだと **AAA で33本目に破産**するが、規模連動なら45本完走

### 決定5. 同分野の2人目以降の効率を 0.5 → 0.12 に下げる

**実機で支配戦略が見つかった。** 同じ4人・同じ総スキルでミニゲームを作った実測：

| 配置 | 総文数 | メタ | 総売上 |
|---|---|---|---|
| 均等（4分野に1人ずつ） | 12文 | 75 | ¥580万 |
| ◎の2分野に2人ずつ | **6文** | **86** | **¥1080万** |

**半分の労力でスコアも売上も上**。開発期間も半分なので固定費まで安く、
均等を選ぶ理由が一つもなかった。仕様（均等59 ＞ 集中55）と逆。

- **却下した案**: 全分野の底上げボーナス → §0「この一本以外の経路でスコアが動くことはない」に反する
- **却下した案**: 総文数を固定／1分野あたりを分野数で割る → 集中の利得はそのままで対価だけ消える
- **却下した案**: ◎○△ の梯子を触る → §4「ジャンルで重要な分野が決まる」が薄まる。支配戦略より上位の柱

**この定数には上下両方から制約がある。** 片方だけ見て動かすと別の支配戦略が生まれる：

| | 何が起きるか |
|---|---|
| 上げすぎ（0.25以上） | 「◎に人を寄せる」が勝つ |
| 下げすぎ（0に近い） | 「◎の2分野に**1人ずつ、2人だけ雇う**」が勝つ（人件費も期間も半分） |

0.12 は全5規模 × 3チーム強度で4条件を同時に満たす値（`teamLayout.test.ts` が固定）。

**修正後**: 均等 12文/メタ75 ／ 集中 6文/メタ68 ／ 少人数 6文/メタ61。
プレイヤーへの言い方は「**均等は +6メタで区分が1つ上がる／集中は開発期間と人件費が半分**」。

### 決定6. AAA の開発費を ¥100億 → ¥60億

A級Lv10 で **話題作 ¥110億 vs AAA ¥75億**。終盤13本が「話題作を回すのが最適」で、
最上位規模に作る理由がなかった。¥60億にすると規模の順序が正しくなり、
仕様の「普通（¥50億）では赤字・ヒット以上で黒字＝大作を当てにいく」も保てる。

### 決定7. 係数を「実ガチャのチーム」基準に再校正

既存の採算ガードは Employee を手組みしていた（6人が1スキルずつ・4分野を完璧に分担）。
**実際のガチャは 50% が2スキル持ち・主スキルの一部が広報**なので、
同じ人数でも実効スキルは理想配置の6割前後。`pullGacha` から通して測ると
**AAA は粗利中央値 −¥10億（黒字 0/100件）**だった。

- `spreadRatio` 主 0.55 → **0.70**（2スキル持ちの主スキルが 0.495 → 0.63。専門特化の優位は保つ）
- 広報の抽選重み 20% → **12%**（開発に効かない社員が5人に1人だった）
- 規模係数を **×1.2**（ミニ1.58／スマホ0.3／インディー0.108／話題作0.058／AAA0.041）

## 4. 実装中に私が入れて、止められたバグ

**5件すべて「ユニットテスト全緑」を通過していた。**

| | バグ | どう見つかったか |
|---|---|---|
| 1 | 互換アダプタの単位ズレで採用社員が半減、**序盤の売上が10分の1** | producer が本番経路で実測 |
| 2 | 1を直したつもりが**本番は別関数**で、まだ C ランクが35%出ていた | producer が `gameStore` を確認 |
| 3 | 進捗が打鍵の速さで進み、**2分野カバーなのに片方の文が1回も回らない** | **実機で通して発覚** |
| 4 | 旧経路の削除で **`bugRate`（バグ率 −10%）の消費側だけが消えた** | producer が grep |
| 5 | 2分野集中の支配戦略 | **実機で2通り並べて比較** |

### 原因と対策

1・2 の原因は**ガードが本番の入口を通っていなかった**こと。安全弁として置いたテストが
「power が同じならスコアが同じ」という**恒真テスト**で、power の値そのものを見ていなかった。

`tasks/lessons.md` に3件記録した：

- **#15** スケールの違う値を「変換」でつながない。切り替えは一点に集約する
- **#16** ガードは**本番が実際に呼ぶ入口**から通す（`store.action()` から入る）
- **#17** ガードは**落ちるところを一度実際に見る**まで信用しない。実測値をコミットメッセージに残す

3・5 は**実機でしか出なかった**。unit 621件・全27ジャンルの機械検証を通過してなお、
実際に触る／2通り並べて比べるまで出なかった。
**「式が正しいこと」と「遊びとして成立していること」は別の検証が要る。**

## 8. 続き（2026-07-29）：実機プレイで見つかった分

オーナーが実際に遊んで出した指摘を順に潰した。**同じ「表示の嘘」の系統が続いていた。**

### 8-1. 進行不能バグ2件

| 症状 | 原因 |
|---|---|
| 神ゲーが出るとリリース画面から**先に進めない** | 認定枠（58px）で中身が 78px あふれ、`overflow: hidden` で「売上を見る」がクリップ（実測 top 691 / ビューポート 720） |
| 開発の最後の1文で**ボスが出現する** | 最後の1文がボスだと `isBossPhrase` が立ったまま残り、フェーズ遷移で要素が張り替わってアニメが再生 |

どちらも**実機で再現→修正→再現しないことを確認**。前者は e2e（`release-fits.spec.ts`）で固定し、
修正前の状態に戻すと落ちることまで確かめた。

ボスの件は**1回目の修正が的外れだった**（「最後の1文で次の抽選をしない」だけでは、
すでに立っているフラグが消えない）。オーナーの「変わってないです」で気づいた。

### 8-2. 同じ数字の二重表示4件

企画画面の担当リストと革新性の警告が2回ずつ／開発中の4分野の値が左パネルと結果カードに二重／
企画書42%が中央ヘッダーと左パネルに二重／左パネルの中でラベルが2行。

**役割で分けた**：左パネル＝いまの到達値、結果カード＝この1打の成果、中央ヘッダー＝いまの状態（FEVER等）。

### 8-3. 利益計算の固定費が推定だった

> これ最終的にマイナスだけど本当にマイナス？残高的にはプラスになってるけど

額は幻ではなかった（実際に引かれている）が、**2つ問題があった**。

1. **払っていない月を計上していた。** `Math.round(開発週数 ÷ 4)` は推定で、下限1ヶ月まで付いていた。
   10週なら実際の徴収は2回でも「3ヶ月」と表示。誤差1ヶ月＝約 ¥252万は
   **その作品の総売上 ¥249.5万を上回る**。借金の利息は逆に入っていなかった
2. **いつ払ったのかが読めなかった。** 費用は全部過去に払い終えていて、
   リリース画面で動くのは初動の入金だけ。だから「画面はマイナスなのに残高は増えた」に見える

`monthlyTick`（実際に資金を減らす場所）で実額を積むようにした。
実測で `資金 470万 → 380万（−90万）` と表示 `−¥90万（月初3回）` が一致。
下限1ヶ月も撤廃した（「速く打つほど固定費が安い」という手応えを表示が打ち消していた）。

### 8-4. 促したとおり雇うと破産する

企画画面は「🎵 担当なし」を**警告色**で出して4分野ぶんの採用を促していた。
ところが実測すると、社員0人で 16.7 ヶ月もつ資金が、4人雇うと **1.7 ヶ月**に落ちる。

**画面が守れない約束をしていた。** 促しを外して事実提示（`担当なし（この分野は 0 点）`）にし、
代わりに**ランウェイ**（資金が何ヶ月もつか）をオフィス・企画・採用の3画面に出した。

採用でもう1件見つけた：`¥406,800` は**初回に1回引かれる額であると同時に毎月かかる額**なのに、
画面には1回ぶんしか出ていなかった。`👛 いま ¥40.7万 ＋ 毎月 ¥40.7万` と両方出す。

⚠ **給与式・基準売上・賃料の定数は1つも変えていない**（構造の是正は v0.28 へ）。

### 8-5. 相性が平坦で「探す面白さ」が無かった

> バランスが悪くて組み合わせを見つける面白さあまりない。右側とか1.0が多いし

756組のうち **185組（24%）がちょうど 1.00**。原因は3つあり、
**テーブルのスカスカだけではなかった**（それだけ直しても平坦は消えない）。

1. タグ相性表が 63通り中 22通りしか定義されていない
2. **加点が Σ（合計）だった。** タグが1つのテーマ（ゾンビ・戦争等）は当たりうるペアが
   最大2つ＝**構造的に平坦**。ゾンビ列は 27ジャンル中 24個が 1.00
3. タグ順に意味がなく、27ジャンル→23行 / 28テーマ→25列に潰れていた

**合計 → 加重平均**にし、タグ順に意味（主×2／副×1）を持たせ、72マス全部を定義した。

| 指標 | 前 | 後 |
|---|---|---|
| ちょうど 1.00 | 185（24%） | **0** |
| テーマ列の最頻値シェア | ゾンビ 89% | 最悪 26% |
| 別値のジャンル行 / テーマ列 | 23/27・25/28 | **27/27・28/28** |

### 8-6. 相性の効きが仕様の半分以下だった（§7 の未決1）

`docs/spec/scoring.md` は「−8〜+8」と書き、**同じファイルの下で「実際は −2.4〜+4.8」と
自白していた**。効きが評価家のブレ（振れ幅10）より小さいので、神を見つけても運に埋もれる。
相性は 📺市場調査（リワード広告）で調べられる唯一のレバーなので、**広告を見る動機が消えていた**。

仕様どおり ±8 にした（当てると +8／外しても −3.6 止まり）。
あわせて `1.20x` という倍率表記をやめた（相性は乗算ではなく加点なので嘘になる）。

### 8-7. 解放金が途中で壁になっていた

> ジャンルテーマの解放金だけどもう少し緩やかにしてほしい。途中からあげれない

公比 1.8 は「無償の自動解放と**併存する**」前提の値だったが、v0.29 で自動解放を廃止して
**購入が唯一の経路**になったのに再調整されていなかった（`balance.ts` のコメントは今も
「併存する」と書いていた）。

初期解放は6個、購入対象は49個。旧実装では 21個目が **¥382億** ＝ AAA の基準売上 ¥60億 でも
次の1個が買えない。**ジャンル27種の大半に一生触れない構造だった。**

公比を 1.2 にし、購入数を **stage 別に分離**した（通しカウンタは
「探索のために安いテーマを買うほど人気ジャンルが遠のく」＝相性の柱と逆行していた）。
全49個の総額は **¥17.1億**（AAA 規模の解放費 ¥15億 と同水準）。

## 9. プロデューサーが決めたこと（§8 の分）

| | 決定 | 理由 |
|---|---|---|
| A | 利益の固定費は**実額を記録**。粗利と会社固定費を分けて表示。下限1ヶ月を撤廃 | 誤差が作品1本の売上を超える。下限が「速く打つ」の手応えを消していた |
| B | バランス定数は触らず、**促しの表現とランウェイ表示**だけ直す（v0.28 へ送る） | 弾いているのは経済ではなく、コストを隠して採用を勧める UI |
| C | 相性は **Σ→加重平均＋主副タグ＋72マス全定義**。手打ち（756マス）は却下 | 手打ちは学習可能な法則が無く、ジャンル追加のたびに55マス手作業になる |
| D | 相性の効きを**仕様どおり ±8** に。上振れ厚め・下振れ浅め | 仕様の履行であって変更ではない。§10-2「誰も弾かない」は最上位 |
| E | 解放金の公比 **1.8 → 1.2**、購入数を **stage 別**に | 49個すべてに到達可能でないと C の盤面が一生見えない |
| F | 無償解放は**戻さない**（購入一本化を維持） | E で壁が消えるなら不要。「稼ぐ→盤面が広がる」の因果を保つ |

### プロデューサーの判定を採らなかった箇所

`computeStageUnlocks` を「呼ばれていない死にコード」と判定していたが、
**実際は v6→v7 のセーブ移行で使われていた**。削除せず、
「新規プレイでは呼ばれない／唯一の呼び出し元は v6 移行」と明記するに留めた。
