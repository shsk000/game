## 0. 事業目的と前提（v0.8 から不変・確定）

本プロジェクトは**リアルマネーの収益化を目的**とする。**長く遊ぶユーザーが結局一番広告を見る**から、「面白くて続く」設計が「稼げる」設計と一致する。

### 収益化の基本方針（確定）
- 収益手段は当面「広告」に一本化。課金は将来検討
- **リワード広告（任意視聴）を主役**にする
- 強制広告は区切りでたまに。バナーは任意の補助収入
- **大原則：広告を「進行の人質」にしない**

### 広告の3分類
| 種類 | 見せ方 | 本作での扱い |
|---|---|---|
| **リワード広告** | 任意。見ると報酬 | ◎ 主役 |
| **インタースティシャル** | 強制。区切りで全画面 | △ 区切りでたまに |
| **バナー** | 常時表示 | ○ 補助収入 |

### プレイ環境
- **PC横画面前提**。物理キーボードでの高速タイピング前提
- スマホ対応はスコープ外

## 1. コンセプト（v0.9 改訂）

プレイヤーはインディーゲーム会社の社長。自分でコードを打ち、社員と組んで作品を作る。

**v0.8 までの「自分の打鍵だけが品質を決める」設計から、「企画判断 × 社員選定 × タイピング演技 × 広告」の4要素で品質が決まる設計に転換**。タイピングは**短いライブ演技**として一発勝負化し、その代わり**企画と経営の戦略性**が品質に直結する。

**設計思想：**
- タイピングは**スキルの見せ場**（グラインドではない）
- 経営は**戦術と戦略**（雇用と配属の悩み）
- 開発カテゴリは**毎回違う判断**（同じジャンルでも切り口が変わる）
- 広告は**結果に変化を与える選択肢**（効率ではなくチャンス）

## 2. 中核ループ（v0.9 改訂）

```
作品を企画
  ├─ ジャンル × テーマ を選ぶ
  ├─ 開発カテゴリを6種から3つ選ぶ（NEW）
  └─ 社員を2〜3人アサイン（NEW）
        ↓
【開発フェーズ】必要コード量を打ち切るまで打鍵（経過時間が記録）
   - 過去最速ゴーストが並走
   - 打鍵に応じて IDE風コードが組み上がる（NEW：コード雰囲気エディタ）
   - 社員（プログラマー）が自動でも生産
   - タイピング演技スコアをリアルタイム集計：WPM・最大コンボ・精度
        ↓
必要LoC到達 = 開発完了
   ※ ポリッシュフェーズは廃止
        ↓
リリース判断（任意でローンチ広告）
        ↓
品質確定 → メタスコア → 連続販売（ジワ売れ・ロングテール）
        ↓
売上を投資（社員採用 / 規模解放 / アンロック）
```

### プレイヤーごとの楽しみ方（v0.9 整理）
- **打鍵特化型** → タイピング演技を磨く。Q寄与は最大+20
- **経営特化型** → 良い社員を集めて適切にアサイン。Q寄与は最大+25
- **企画特化型** → カテゴリ選びを煮詰める。Q寄与は最大+20
- **広告活用型** → タイミング良く広告を見る。Q寄与は最大+15

→ **どのスタイルでも前進できる**が、上を狙うには全部が要る。

## 3. 4レバーが品質をつくる

```
Quality (Q) = clamp(0, 100,
    Base ベース                30
  + CategoryContribution       0〜20    ← 開発カテゴリ
  + EmployeeContribution       0〜25    ← 社員アサイン
  + PerformanceContribution    0〜20    ← タイピング演技
  + AdContribution             0〜15    ← 広告ブースト
  + Variance                   ±5      ← 揺らぎ
)
```

- 4レバーは**独立に可視化**される。リリース画面で「カテゴリ +18 / チーム +14 / 演技 +16 / 広告 +5 / 揺らぎ +3 → Q86」のように見える
- どのレバーが効いたか分かるので、**次のプレイで改善できる**＝学習ループが回る

- 高ティア継続中はパフォーマンス寄与に加点

## 4-H. 評価システム（v0.9 改訂：4レバー結果開示に拡張）

### 開発中：リアルタイムの手応え
- カテゴリ寄与は企画時に確定 → 開発前から「これは噛み合ってる」が分かる
- 社員寄与も企画時に確定 → 「この組み合わせなら…」の予感
- タイピング演技はリアルタイム表示（WPM・最大コンボ・精度）
- 広告寄与はリリース直前に選択

### 完成後：メタスコア開示
リリース後、**カテゴリ→チーム→演技→広告→揺らぎ→合計** の順に演出付きで開示される。

```
Base                       30
+ 🎨 カテゴリ寄与         +18  (グラフィック・サウンド・ストーリー)
+ 👥 チーム寄与            +14  (田中の🎨デザインが冴えた)
+ ⚡ タイピング演技        +16  (WPM 68・Max Combo 42・Acc 96%)
+ 📺 広告ブースト          +5
+ ✨ 揺らぎ                +3
                          ────
   メタスコア:            86 → 演出付き
```

- **変動（揺らぎ）±5**：同じ作りでも毎回少しブレる → ガチャ性
- **神ゲー認定**：ごく低確率で大幅プラス補正（既存3%・継続）

## 4-I. 販売・資金化（v0.8 から不変）

リリース後は**ジワ売れモデル**で資金が流入する。

```
リリース
  ↓
初動（メタ × ファン × 規模で算出）の20%が即時加算
  ↓
残り80%が販売プールに入り、メタスコア依存の指数減衰で時間経過に応じて流入
  ├─ 高メタほど減衰が遅い（ロングテール）
  ├─ メタ100で半減期 約115秒、メタ30で約35秒
  └─ 複数作品の同時販売が成立
  ↓
オフラインでも経過時間ぶんを一括精算
```

### 広告との接続
- **ローンチ広告**（リワード）：初動 ×1.5
- **オフライン2倍広告**：再訪時の販売差分を倍化（🔧 未実装）

## 4-J. 開発カテゴリシステム（v0.9 新設）

企画時に**6カテゴリから3つを選ぶ**。選んだ組合せがジャンル×テーマと噛み合うほどカテゴリ寄与が伸びる。

### カテゴリ一覧
| カテゴリ | アイコン | 効きやすいジャンル例 | 効きやすいテーマ例 |
|---|---|---|---|
| グラフィック | 🎨 | アクション・レース・ホラー | SF・ファンタジー |
| サウンド | 🎵 | ホラー・リズム・アドベンチャー | 温泉・忍者 |
| ストーリー | 📖 | RPG・アドベンチャー・ホラー | ファンタジー・中世 |
| ゲームプレイ | 🎮 | パズル・格闘・ローグライク | 寿司・コンビニ |
| 演出 | ✨ | アクション・シューティング | 戦争・宇宙人 |
| 革新性 | 💡 | ローグライク・サンドボックス | 宇宙人・農業 |

### 寄与の計算
```
CategoryContribution = Σ (選んだカテゴリそれぞれの噛み合い度)
噛み合い度 = ジャンル一致 +4、テーマ一致 +3、両方一致 +8
基礎寄与 = 各カテゴリ +2（選んだだけで最低3カテゴリ×2 = +6）
上限 = 20
```

### アンロック設計
- 初期：3カテゴリ（グラフィック・サウンド・ゲームプレイ）
- リリース5本で +1（ストーリー）
- 10本で +1（演出）
- 20本で +1（革新性）

→ 序盤は「全部選ぶ」相当だが、解放されるにつれ**戦略選択**になる

## 4-K. 社員アサインシステム（v0.9 新設）

採用済み社員から、**この作品の開発チーム（2〜3人）を選ぶ**。

### 社員の能力（v0.9 拡張）
v0.8 の社員は職種＋単一パワー値だったが、v0.9 では**得意カテゴリ**を持つ：

```
田中 太郎 [デザイナー]
  🎨 グラフィック  +12
  🎵 サウンド       +3
  賃金: ¥720
```

職種別の傾向：
- **プログラマー**：ゲームプレイ・革新性が得意。LoC自動生産も継続
- **デザイナー**：グラフィック・サウンドが得意
- **広報**：ストーリー・演出が得意。売上%加算も継続（既存維持）

### 寄与の計算
```
EmployeeContribution = Σ (アサイン社員ごとの、選んだ3カテゴリへの寄与の合計) × 0.4
上限 = 25
```
- アサイン社員1人あたり最大 約8〜10ポイント寄与
- 3人投入で最大25付近に到達

### 制約（戦略性を生む）
- 1作に投入できるのは最大3人（中盤までは2人）
- 投入中の社員は**その作品の開発が終わるまで他作品に投入できない**
  → 同時並行案件が解放される後半は、戦略がさらに深くなる

### 採用候補（既存維持）
- 候補1人を常時表示
- 採用 or 別の候補（¥50）

## 7. 経済バランス（v0.9 改訂）

### 売上計算式
```
売上 = 基礎単価 × LoC係数 × (メタ/50) × 相性 × トレンド × ファン係数
       × ローンチ広告 × 広報係数 × 新規開拓ボーナス
```

- 基礎単価：作品規模ごとに固定（mini=100 / aaa=4000）
- LoC係数：1 + ln(requiredLoC/8)
- 広報係数：1 + (アサインした広報社員のパワー合計 / 100)
- 新規開拓：1.3（初回組合せ）

### 連続販売
- 初動 = 売上の20%、即時加算
- 販売プール = 売上の80%、メタ依存の指数減衰で流入
- 減衰率 = 0.022 − メタ/100 × 0.018（メタ100で約0.005/秒）

### 品質計算（v0.9 新規）
```
Q = 30
  + min(20, Σ category_match)         // カテゴリ寄与
  + min(25, Σ employee_match × 0.4)   // 社員寄与
  + min(20, perfScore)                // 演技
  + adBonus                           // 広告
  + ((random - 0.5) * 10)             // 揺らぎ
```
`perfScore = wpmScore + comboScore + accuracyScore`（各最大7点目安）

### 経済バランスの原則（v0.8 から不変）
1. 広告なしでも全規模クリア可能
2. 広告ありだと体感1.3〜2倍お得
3. 規模上昇に応じて社員・解放コストが指数的に上がる
4. 1作あたりプレイ時間は数十秒〜数分

## 付録C. コード雰囲気エディタ（v0.9 新設）

### 設計思想
**本物のエンジニアが書くようなコードである必要はない**。プレイヤーが「いま自分はエンジニアやってる」と感じる**雰囲気**を作るのが目的。ハリウッド映画のハッキング画面と同じノリ。

### 画面イメージ
```
┌─────────────────────────┬──────────────────────────────────┐
│ 💻 開発中                 │ 📄 game.ts                          │
│  ┌─────┐ ⏱ 12.3s         │ ─────────────────────────────────  │
│  │ジャケ│ Ghost: 14.5s    │ 1  async function curse(target) { │
│  └─────┘                  │ 2    const ghost = new Yokai;     │
│                          │ 3    ghost.scare(target);          │
│  進捗 ████░░░ 4/8         │ 4  }                              │
│                          │ 5  ▮                              │
│  打鍵: ふっかつする       │                                  │
│  入力: fukk____           │   ← ここに次の行が「タイプ」      │
│                          │      されていく演出               │
│  ⚡ Combo 23 (HOT)        │                                  │
└─────────────────────────┴──────────────────────────────────┘
```

### コード生成のしくみ
打鍵フレーズ完了ごとに、エディタに**1行追加**される。中身はテンプレと単語プールの組み合わせ：

```
${visibility} ${keyword} ${verb}(${arg}) { ${body}; }
```

- **visibility**：public / private / async / export / const / let
- **keyword**：function / const / class / interface
- **verb**：ジャンル別単語プール（horror: haunt, summon, curse / rpg: cast, slay, revive）
- **arg**：テーマ別単語プール（sushi: tuna, wasabi / onsen: hotSpring, towel）
- **body**：それっぽい1行（`return ${arg}.power;` / `${arg}.hp -= 10;`）

### ジャンル×テーマで変わる例
- **ホラー×ゾンビ**:
  ```
  class Zombie extends Undead { hunger = 100; }
  async function infect(victim) { return victim.curse(); }
  ```
- **RPG×ファンタジー**:
  ```
  function castFireball(target) { return damage * mana; }
  class Dragon extends Boss { hp = 9999; }
  ```
- **レース×寿司**:
  ```
  const sushiBelt = new ConveyorBelt({ speed: 1.5 });
  function deliver(plate) { plate.boost(turbo); }
  ```

### バグイベント
発生時：エディタの**ある行に赤波線**が表示される。
```
3    return ghost.scare(towel
                              ^ syntax error: missing )
```
バグ修正フレーズ（既存「ばぐしゅうせい」など）を打ち切ると赤が消えてその行が緑色に。

### リリース演出
```
> Compiling sources...
> Bundling assets...
> Optimizing for 60fps...
> Build successful ✓
> Shipping to stores...
```
順番に表示されながら、背景にジャケットが浮かび上がる。

- テンプレ：10〜15種類
