## 0. プロデューサー診断：いま何がリスクか

v0.15〜17 で「タイピングの手応え」「能力が支配する評価」「バグの因果」は入った。
次に体験を殺すのは機能不足ではなく**ペーシング**。数値で確認した現状：

### 診断1: 最初の大きな解放（mobile）が遠すぎる 🚨最重要

- mobile 解放条件は累計売上 **¥3,000万**（v0.10 の「初手メタ95が出る」旧経済のまま）
- v0.16 の新分布では序盤はメタ20〜50中心 → 1作 **¥10万〜100万**。普通スコア（50+）に乗っても ¥300万
- → 解放まで **15〜25作 ≒ リアル1時間以上、その間ずっと mini の繰り返し**。
  「上手くなってきた」の実感（Lv3、メタ50台）より先に「変化がない」が来て離脱する
- indie（¥3億）以降も同様に旧経済前提。**評価は再設計したのに経済カーブが旧のまま**という v0.16 の積み残し

### 診断2: 目標がゲーム内で見えない

- 「次に何を目指すか」（次の解放まであと¥いくら／社員の次Lvまで／図鑑の進み）が**どの画面にも常設されていない**
- 経営シムの中毒性は「常に3つくらいの短期目標が見えている」ことで作られる（最上位の目的 §メタ進行）。今は解放可能になった瞬間に通知が出るだけ

### 診断3: 初期の赤字が「学び」ではなく「罰」になっている

- 序盤は設計どおり赤字（確定済み）。ただし**なぜ赤字か・次はどうすれば良いかをゲームが教えない**
- 開封画面に4要素の内訳は出るが、「あなたの最大のボトルネックはキャラ能力です→社員を育てよう」までの翻訳がない
- 赤字が「自分のせい＋改善の道筋が見える」なら継続動機、見えないならただのストレス

### 診断4: 決着待ちの負債2件

- **旧セーブの累計売上引き継ぎ**（2本目で全解放の件。オーナー判断待ち）
- **デバッグ負荷**：ミス＝バグ確定化で、精度76%プレイだと数十匹 → デバッグ数十文の恐れ（実プレイFB待ち）

## 1. 経済カーブの再設計（診断1）

**設計目標：「変化が起きる間隔」を一定に保つ。** mini 期は 8〜12 作で卒業できる。

- 解放閾値を新分布に整合 🔧（叩き台）：

| 規模 | 現行 unlockSalesRequired | 改訂案 🔧 | 想定到達 |
|---|---|---|---|
| mobile | ¥3,000万 | **¥800万** | 8〜12作目（Lv3 前後・メタ50台に乗り始める頃） |
| indie | ¥3億 | **¥8,000万** | mobile 6〜10作 |
| hit | ¥30億 | **¥10億** | indie 6〜10作 |
| aaa | ¥300億 | **¥120億** | hit 6〜10作 |

- 各ティア「6〜10作で次が見える」の等間隔リズム。1周（→aaa→メタ95）は **40〜50作 ≒ Lv10到達と同期**
- **進行シミュレーションテストを新設**：成長モデル（平均的な腕）で30作プレイを seed 固定シミュレートし、
  「mobile 解放は8〜14作目の間」「1周のリリース数が40〜60」を assert → 以後の数値調整の回帰ガード
- unlockCost（解放の一括支払い）も同率で圧縮 🔧

## 2. 「次の目標」の常設表示（診断2）

オフィス画面に **🎯目標ウィジェット**（PixelWindow・3行固定）を常設：

```
🎯 つぎの目標
🏢 スマホゲーム解放まで  あと ¥420万
⬆ 田中 太郎 Lv3 まで     あと exp 25
📖 図鑑発見              12 / 180
```

- 表示は常に3つ：①次の規模解放（未解放があれば）②次にLvが上がる社員 ③図鑑発見数
- 達成された行はその場で「✓＋ファンファーレ」→ 次の目標に差し替わる（短期目標の連鎖）
- 1280×720 内・スクロールなし（既存お知らせ窓の下 🔧位置は実装時に調整）

## 3. リリース結果に「次の一手」を出す（診断3）

売上画面（STEP2）の末尾に **📈 アドバイス1行**を追加：

- 4要素＋残バグから**最大のボトルネックを1つだけ**特定して翻訳する（複数言わない）：
  - キャラ能力が最小 →「社員の力不足。育成か採用を」
  - 相性が低い →「組合せが地雷気味。図鑑で相性を探そう」
  - タイピングが低い →「ミスが品質を下げた。正確に打とう」
  - 残バグあり →「バグ N 匹を残して発売した。デバッグで潰せば品質+」
- 純粋関数 `adviceFor(work, breakdown)` として core/ に実装（unit テスト可能）

## 4. 負債の決着（診断4）
