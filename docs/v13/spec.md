## 0. 改訂背景 / この版で変えること

v0.11 までで、オフィス画面の **UI 枠（HUD・オーバーレイ窓・メニュー・ティッカー）** はリファレンス準拠に再構築された。
しかし画面の主役である **中央のアイソメ・オフィス（社員と家具のシーン）** は、まだ初期実装のままで品質が低い:

- 社員は **単一スプライト（黒髪・青シャツの立ち姿8方向）1 種のみ** → 全員が同じ見た目で、誰が誰か分からず愛着が湧かない
- 家具は **机・椅子・モニター・床・植物・窓** の最小セットのみ → オフィスが閑散として「会社が育つ」実感が薄い
- 社員は **棒立ち** → 「働いている」「生きている」感がない
- 雰囲気演出（吹き出し・気分）が **皆無**

v0.13 は **ゲームプレイ（システム）には手を入れず、オフィス中央シーンと社員のビジュアル品質だけを目標リファレンスに引き上げる**。

> ⚠️ プロデューサー注（game-design §8）: 本来「面白いと確認してから絵を作り込む」が原則。本版は世界観の没入＝継続にも効くという判断のもと、**オーナー（shsk）決定**で先行してビジュアルを磨く。ゲームシステムの深化（旧 v0.11 spec の 5 軸・世界×物語）は別版に繰越。

## 1. 目標リファレンス（確定ターゲット）

ユーザー提示のオフィス画面リファレンス（2026-06-13 添付）。Kairosoft Game Dev Story 風の、**活気ある満員オフィス**。

> ※ `public/phase/development.png`（開発フェーズの暗い夜シーン）は **本件と無関係**。混同しないこと。

### リファレンスから読み取れる構成要素

| 区分 | 要素 |
|---|---|
| **社員（多様）** | 髪色（黒/茶/ピンク/緑/グレー/オレンジ）・髪型・服色がバラバラ。着席タイピング姿＋一部は立ち/ラウンジ |
| **社員の生命感** | 頭上のステータス吹き出し（💡ひらめき / `{-}`コード中 / ☕休憩 / 💤疲労(Zzz) / 🎨デザイン中） |
| **机配置** | 向かい合わせペア（お見合い席）で島を作る。緑のオフィスチェア |
| **家具・設備** | ホワイトボード（図表付き・壁掛け＋自立式）/ ウォーターサーバー / 冷蔵庫 / 本棚（複数）/ 自販機 / 観葉植物（大小多数）/ ゴミ箱 / 壁ポスター・絵画 / 時計 |
| **ラウンジ** | 緑ソファ ＋ コーヒーテーブル ＋ TV ＋ 植物の休憩エリア |
| **部屋** | L 字壁（北＋側面）/ グレー市松タイル床 / 出入口ドア（PARKING 看板）/ 窓（都市スカイライン＋並木） |
| **雰囲気** | 昼・明るい・人口密度高め・活気 |

## 2. 改訂の柱（5 本）

### 2-1. 社員ビジュアルの個性化（§3）
単一スプライト → 多様な見た目。データ上の各社員と 1 対 1 で結びつく。着席タイピング姿。

### 2-2. 社員の「生きている」演出（§4）
頭上ステータス吹き出し＋気分表現で、オフィスが動いて見える。

### 2-3. オフィス家具・設備のリッチ化（§5）
ホワイトボード・ウォーターサーバー・冷蔵庫・本棚・自販機・ラウンジ・植物・装飾を追加し密度を上げる。

### 2-4. 部屋・床・壁・窓・出入口の作り込み（§6）
L 字壁・市松床・都市ビューの窓・ドアで「箱」としての完成度を上げる。

### 2-5. 家具ティアの視覚差別化（§7）
「家具」メニュー（basic→legendary）の投資が見た目で分かるようにする。

## 3. 社員ビジュアルの個性化

### 3-1. 個性化の方式 🔧（要決定 → §10-Q1）
2 案。**推奨はプリセット・バリエーション方式（カイロ式）**。

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. プリセット・バリエーション（推奨）** | 8〜12 種の見た目プリセットを用意し、髪色/服色をパレット差し替えで増幅。社員生成時に割り当て | 低コスト・破綻しにくい・カイロ準拠 | 厳密には有限バリエーション |
| B. パーツ合成 | 顔・髪・体・服を別レイヤーで合成（game-design §8 の合成思想） | 理論上無限の組合せ | アイソメ着席姿でのレイヤー位置合わせが難しい・破綻リスク |

### 3-2. 必要なポーズ／向き
office-visual-design §2-B / §2-C-5（リアル方式・向かい合わせペア）に従う:
- **着席タイピング**：SW 向き（上段席）／ NE 向き（下段席）の 2 方向
- **着席 idle**（呼吸の揺れ）：2 方向
- **立ち**（ラウンジ・移動）：2 方向 🔧（優先度低・後回し可）

### 3-3. 多様性のパラメータ
- 髪型 🔧（4〜6 種）/ 髪色（6 色以上）/ 服色（6 色以上）/ 肌色（2〜3 種）
- 職種で傾向を出す（プログラマ＝パーカー、デザイナ＝私服、サウンド＝ヘッドホン 等）🔧

### 3-4. 社員リスト用の顔サムネ
- リファレンス左下「社員リスト」の顔アイコン（小サムネ＋気分絵文字）も本版で用意
- 着席スプライトと同じ見た目プリセットから生成（一貫性）

### 3-5. データ結合
- `Employee` に **見た目 ID（appearanceId / カラーシード）** を持たせ、生成時に確定・保存
- 既存セーブの社員には後方互換でデフォルト割り当て（§9）

## 4. 社員の「生きている」演出

### 4-1. ステータス吹き出し
頭上に状態を示す吹き出しを出す（リファレンス準拠）:

| 吹き出し | 意味 | 駆動 🔧 |
|---|---|---|
| `{-}` | コード中（実装作業） | 開発フェーズ中・プログラマ |
| 🎨 | デザイン中 | デザイナ |
| 💡 | ひらめき | ランダム演出 or イベント連動 |
| ☕ | 休憩中 | ラウンジ配置 or ランダム |
| 💤 (Zzz) | 疲労 | 疲労 state があれば連動、なければ演出 |

- 駆動データは 🔧（§10-Q3）: 既存に社員 state（疲労・作業内容）が無ければ、**まずは軽量な「演出用 state」or ランダムローテーション**で見た目だけ成立させる（ゲームシステムには踏み込まない）

### 4-2. アイドルアニメ
- 着席 idle の微揺れ（既存 SpriteAnimation 活用）
- タイピング時は両腕が動く（office-visual-design §4-5）

## 5. オフィス家具・設備のリッチ化

### 5-1. 追加する家具・設備（PixelLab 新規発注）
office-visual-design §2-A-3 の立方体規格で発注:

| 物体 | cube 規格（既定/新規 🔧） | 用途 |
|---|---|---|
| 緑オフィスチェア | 1×1×2（既存椅子の色違い/差し替え） | 着席 |
| ホワイトボード（図表） | 2×0.1×1.5（壁掛け）/ 自立式 🔧 | 装飾・密度 |
| ウォーターサーバー | 1×1×1.5 🔧 | 装飾 |
| 冷蔵庫 | 1×1×2 🔧 | 装飾 |
| 本棚 | 1×1×2.5 | 装飾 |
| 自販機 | 1×1×2 🔧 | 装飾 |
| ソファ（緑） | 2×1×1.2 | ラウンジ |
| コーヒーテーブル | 1×1×0.5 🔧 | ラウンジ |
| TV（壁/台） | 1.5×0.3×1 🔧 | ラウンジ |
| 観葉植物（大/小） | 1×1×1.5 / 既存 plant | 散らし |
| ゴミ箱 | 0.5×0.5×0.7 🔧 | 散らし |
| 壁ポスター・絵画 | 壁貼り（向き不要） | 壁面 |
| 時計 | 壁貼り | 壁面 |

### 5-2. 配置ロジック
- ワークステーション（向かい合わせペア）は既存ロジック（OfficeView）を踏襲・密度UP
- 装飾は **壁際・隅・余白** に散らす（office-visual-design §6-4）
- ラウンジは部屋の一角に固定領域として確保 🔧

### 5-3. 発注コストの管理
- pixelart-prompting のコスト規約に従い、1 物体ずつ `create_map_object` で発注
- NE 方向が必要な非対称物のみ 2 方向発注（office-visual-design §2-B-5）
- 概算 gen 数を tasks.md で見積もる

## 6. 部屋・床・壁・窓・出入口の作り込み

- **床**：グレー市松タイル（既存 tile_pro_* の見直し／再発注 🔧）
- **壁**：L 字（北＋側面）。幅木・コンセント等のディテール 🔧
- **窓**：都市スカイライン＋並木の背景（既存 window 差し替え）
- **出入口**：ドア＋ PARKING 看板（装飾）
- 規模（mini→aaa）で部屋が広がる既存ロジックは維持し、各規模で密度が成立するよう装飾量を調整

## 7. 家具ティアの視覚差別化

- 「家具」メニューの設備ティア（basic / mini / pro / premium / legendary）が**見た目で区別できる**ようにする
- 最低でも **机・椅子・モニター** の 3 種でティア差を付ける 🔧（全ティア×全家具は過剰なので優先順位付け）
- 投資（資金消費）の手応え＝メタ進行・柱1（game-design §6）の可視化に接続

## 10. 確定が必要な点（プロデューサーから）

### Q1. 社員個性化の方式
A: プリセット・バリエーション（推奨）/ B: パーツ合成 — どちらで進めるか（§3-1）

### Q2. 部屋モデル
規模ごとのグリッド拡張を維持（推奨）か、単一の広い部屋に作り直すか（§6）

### Q3. ステータス吹き出しの駆動
既存に社員 state（疲労・作業内容）があるか要確認。無ければ「演出用の軽量 state or ランダム」で見た目だけ先行（推奨）か、簡単な疲労 state を新設するか（§4-1）

### Q4. 家具ティア視覚差別化の範囲
机・椅子・モニターの 3 種に絞る（推奨）か、もっと広げるか（§7）

> 🔧 のついた数値・規格・優先度は、発注前にこの場で詰める。

## 11. 検証方法（memory: 検証ルール準拠）

完成後、**ブラウザ実機を起動して目視確認**＋ office-visual-design §9 プロトコル:
- [ ] 社員が多様な見た目になっているか（全員同じでない）
- [ ] 各社員がデータと結びつき、リロードしても見た目が変わらないか
- [ ] 吹き出し演出でオフィスが「動いて見える」か
- [ ] 家具・装飾でリファレンス相当の密度になったか
- [ ] アイソメ視点・立方体規格・向かい合わせペアの整合（§9-1〜9-3）
- [ ] 家具ティアの差が見て分かるか
- [ ] 各規模（mini→aaa）で破綻しないか
- [ ] 既存セーブが壊れていないか（回帰）
