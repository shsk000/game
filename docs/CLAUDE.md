# docs/ のドキュメント運用規約

このディレクトリで設計・タスクを扱うときに Claude（あなた）が守るべきルール。

---

## 1. ディレクトリ構造

```
docs/
  CLAUDE.md           ← このファイル（規約）
  vNN/                ← 各バージョンの設計成果物（NNはゼロ埋め2桁）
    spec.md           ← そのバージョンの確定企画書（必須）
    tasks.md          ← そのバージョンの実装タスクリスト（必須）
    gaps.md           ← 仕様と現状の差分・優先度（任意・大きな差分がある時のみ）
    notes/            ← 補助メモ・議事・実験ログ（任意）
```

**重要**: `docs/` 直下に企画書/タスク/差分の本体を置かない。必ず `vNN/` 配下に置く。

---

## 2. バージョンの上げ方

### 軽微な変更（数値調整・表現修正・誤字）
- 現行 `vNN/spec.md` を直接編集。`tasks.md` に項目追加。
- バージョンは上げない。

### 設計を変更する変更（コアループ・主要システム・新機能）
1. 新バージョンディレクトリ `vNN+1/` を作成
2. `vNN/spec.md` を `vNN+1/spec.md` にコピーして、改訂履歴セクションに項目追加
3. 変更内容を `spec.md` 本文に反映
4. `vNN+1/tasks.md` を新規作成。**前バージョンから引き継ぐ未完タスク** ＋ **新規追加タスク** を区別して列挙
5. 大きな差分がある場合は `vNN+1/gaps.md` も作成
6. **前バージョンのファイルは消さない**（履歴として残す）

例：v0.8 で「ポリッシュ＝追加打鍵で品質UP」だったものを v0.9 で廃止する場合 → `docs/v09/` を新設。

---

## 3. spec.md の書き方

### 必須要素
- 先頭に「**改訂履歴**」セクション。前版からの変更点を1行ずつ列挙
- 「事業目的と前提」「コンセプト」「コアループ」「経済設計」「UX」「技術メモ」を必ず含める
- 数値は「叩き台」と「確定」を区別する（叩き台には 🔧 マークを付ける）

### 変更時の作法
- 既存セクションを **削除する場合は改訂履歴に明記**（消した理由を1行）
- 新規セクションを足す場合も改訂履歴に追記
- 大きな思想転換は「**この版で変えたこと**」セクションを冒頭に置く

---

## 4. tasks.md の書き方

### フォーマット
- 凡例：`[x]` 実装済 / `[~]` 部分実装 / `[ ]` 未着手
- 章は spec.md の節構造に合わせる（1. コアループ / 2. ジャンル相性 ... のように）
- 各項目は **テスト可能な単位** に分解する。曖昧な「いい感じに」項目は禁止

### バージョン更新時
- 前版から引き継ぐ未完タスクは「**継承タスク（前版から）**」セクションにまとめる
- 新バージョンで増えたタスクは「**追加タスク（このバージョン）**」セクションに

### 進捗の更新タイミング
- 機能実装が完了して動作確認できたら同タスクの `[ ]` を `[x]` に変える
- コミットと同じタイミングで更新するのが目安

---

## 5. gaps.md の書き方（任意）

設計（spec）と実装の差分を、**優先度付き**で並べる。

- 凡例：P0（コア体験に直結）/ P1（中毒性・収益）/ P2（磨き）/ P3（ローンチ整備）
- 各ギャップに **「何が足りない」「なぜ足りない」「直すなら」** の3点を書く
- 単なる「未実装」リストではなく、**判断材料**になる粒度で書く

---

## 6. Claude（あなた）の動き方

### 設計に関する質問を受けた時
1. 最新の `docs/vNN/spec.md` を最初に読む（`ls docs/` で最大のNNを特定）
2. その内容を真として答える
3. 旧バージョンに言及する必要がある時は `docs/vXX/spec.md` を明示的に開く

### 仕様変更を依頼された時
1. 影響範囲を判定し「軽微」か「設計変更」かを切り分ける
2. 軽微なら現行 spec.md を編集
3. 設計変更なら新バージョンディレクトリを作成（§2 のフロー）
4. 変更内容を **ユーザーに要約して見せる**。勝手に大規模な書き換えをしない

### 実装を始める時
1. `vNN/tasks.md` の該当項目を確認
2. 着手中の項目は `[~]` に更新（メモリ上のタスクシステムと併用）
3. 完了したら `[x]` に更新し、同じコミットに含める

### 旧バージョンファイルの扱い
- **読むのは可**、**編集は禁止**（歴史を改ざんしない）
- ただし誤字・リンク切れの修正は許容

---

## 7. リンク・参照

- spec.md 内から tasks.md / gaps.md への相互リンクを置く
- ルート `README.md` から最新版 spec.md にリンクを置く
- 古い版へは「歴史的参照」として注釈付きでリンク

---

## 8. 命名規則

- バージョン番号: `v0.8` → `v08`、`v1.0` → `v10`（ピリオドを抜く2桁）
- セマンティック準拠：マイナーアップ＝コアループ変更／パッチ＝数値・誤字
- pre-release（草案）の場合は `v09-draft/` のようにサフィックスを付け、確定時にリネーム

---

## 9. このファイル自体の更新

`CLAUDE.md` の規約変更は **明示的な相談の上で**。勝手にルールを変えない。
