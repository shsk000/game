## v0.21「投資」— 金の使い道（オーナー指定・[spec.md](./v21/spec.md) 展開済み）

> **状態：🟡 部分完了** — ジャンル/テーマ購入は実装済み（feat 2d20315）。**「金で社員育成（研修）」は未実装**（`applyExpGain` 切り出し・研修アクション・UI・テストが `tasks.md` で `[ ]`）＋価格チューニング/実プレイ確認待ち。

**問い：稼いだ金で何を買えば楽しいか？**

現状、資金の使い道は「採用・規模解放・借金返済」だけ。オーナー指定の2本を軸にする：

- **ジャンル・テーマをお金で購入**（オーナー指定）
  - 未解放のジャンル/テーマを資金で個別購入できる（人気なほど高い 🔧）
  - 既存のステージ解放（累計売上）との関係は spec 時に確定 🔧：
    案A=併存（ステージ到達で無料解放 or 先行して金で買う＝「先行投資」）／案B=購入制に一本化
  - 「作りたい組合せを金で引き寄せる」＝探索（図鑑）への投資になる
- **お金で社員を育成**（オーナー指定）
  - 研修コマンド：資金を払って対象社員に exp を直接付与 🔧（例：¥50万 = exp 20。リリース獲得より割高だが確実）
  - 上位研修（レベルキャップ付近で解放）などの階段は spec 時に設計
  - 「リリースで自然に育つ」＋「金で加速する」の2路線＝固定費増（給与）とのトレードオフ
- オフィス設備（バグ抑制サーバー等）は**任意枠 🔧**：上記2本の手応えを見て入れるか判断
- **判断ゲート**：進行シミュレーション（mobile 8〜16作・分布ガード）を金の近道込みで再検証

### 敵対的レビュー由来のバランス課題（2026-07-23 起票・要オーナー方針判断あり）

- [ ] **B-1 進行シミュに固定費・破産を織り込む（土台）**：`progressionSimulation.test.ts` は「資金は十分ある前提」で累計"粗"売上のみ追い、**固定費・給与・借金・破産を一切モデル化していない**。→ 固定費/借入上限/破産（`economy.ts` `gameOver = debt > borrowingLimit && funds<=0`）を通した **solvency シミュ**を新規追加し、「mobile 到達が資金面でも破産せず成立する」経路の存在をガードにする。**これが無いと以降の調整の当否を判定できない**（最優先）。
