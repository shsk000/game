## 1. リリース結果を 2 画面に分割（スクロール禁止の回復）

現行 ReleaseScreen は 1 画面に「4要素開封＋メタスコア＋実績＋Lvアップ＋売上＋販売プール＋利益計算＋ボーナス広告」が同居し、1280×720 からあふれている（UI 規約違反）。

**STEP 1「📊 評価」**（開封の山場だけ）
- 4 要素の開封演出 → 品質 → メタスコアカウントアップ（既存演出は温存）
- 名作認定・実績解除・社員レベルアップのバッジ
- `[売上を見る ▶]`

**STEP 2「💰 売上」**（お金の話だけ）
- 初動売上・販売プール・利益計算（開発費・固定費・利益・ROI）
- ボーナス収入広告（既存機能の移設）
- `[次へ（オフィス）]`

- 両ステップとも **1280×720 固定・overflow なし**（はみ出す場合は行数を削る。スキル規約どおり）
- ユースケーステスト更新：STEP1 でメタスコア表示 → STEP2 で売上表示 → オフィス帰還

## 2. 従業員は基本全員参加（アサイン UI 廃止）

- `startProject(genre, theme, scale)` に変更し、**参加者は常に全社員**（内部の assignedEmployeeIds には全員を積み、互換を維持）
- PlanScreen のアサインチェックボックスを削除 → 「👥 参加メンバー: 全員（N 人）」の表示だけ残す
- 開始条件は「社員 1 人以上」（現行と同じ意味に帰着）
- **キャラ能力スコアの規模適合を改訂**：人数がレバーでなくなるため
  - 推奨人数**未満**のペナルティ -10 は維持（「この規模には人が足りない」＝雇用の動機）
  - 超過ペナルティ -5 は**廃止**（全員参加が正なら罰は理不尽）🔧
- 分布シミュレーションの各モデルも「全員参加」前提に更新（帯が変わらないことを確認）

## 3. 能力とレベルの「効き先」可視化

**役割の効果を常設表示**（値は balance.ts の ROLE_EFFECT から生成。ハードコードしない）：

| 役割 | 表示文言（例） |
|---|---|
| 🧑‍💻 プログラマー | 自動で開発が進む（+0.48 LoC/秒）／**バグを抑える**（§4 連動） |
| 🎨 デザイナー | 作品の品質 +4.0 |
| 📣 広報 | 売上 +8% |

- 表示場所：採用パネル（候補カード）・オフィス社員リスト・PlanScreen
- **PlanScreen にチーム効果プレビュー**を 1 箱で：「⚡開発速度 +X LoC/s ／ 🎨品質 +Y ／ 📣売上 +Z% ／ 🐛バグ抑制 W%」→「このチームで作ると何が起きるか」が企画時点で見える
- **レベルアップのメリットを数字で見せる**：
  - 開封バッジを効果差分つきに：「⬆ 田中 太郎 Lv3！ power 0.40→0.46（開発速度+7%・給与 +¥8.6万）」
  - 社員リストに **次レベルまでの exp ゲージ**（育てている実感）
  - 開封の 4 要素ラベルを「キャラ能力（社員の育ち）」等、因果が読める文言に

**レベル連動の固定費（オーナー指示 2026-07-10「Lv が上がるごとに固定費が上がるように」）**：
- 月給式に**明示のレベル項**を追加：`月給 = ¥30万 + power × ¥60万 + (level − 1) × ¥5万` 🔧
- 現行も power 成長経由で微増（Lv+1 ≈ +¥3.6万）していたが、レベル項で「育てるほど確実に高給」を明確化
  （basePower 0.4 の社員：Lv1 ¥54万 → Lv5 ¥88万 → Lv10 ¥146万）
- 強い会社ほど月次固定費が重くなり、v0.16 の経済緊張（借金→ゲームオーバー）と噛み合う

## 3.5 ゲームタイトルの命名（オーナー指示 2026-07-10）

- **自分で決められる**：PlanScreen の企画プレビューにタイトル入力欄（最大 16 文字 🔧）
- **つけたくない人にはランダム**：入力欄の隣に `[🎲]` ボタン。既存 `generateTitle`（ジャンル別の接頭語 × テーマ別の名詞の**組み合わせ**）で再抽選し続けられる
- 初期値はランダム生成済みのタイトル（＝1 回も触らなければ従来と同じ体験）
- 開始時に空欄ならランダムで補完（空タイトルの作品は生まれない）
- `startProject` に title 引数を追加（省略時はランダム生成＝互換維持）

## 4. バグ発生システム（本丸・コアループ拡張）

**設計思想**：バグは「タイピングの腕」と「エンジニアの質」の両方が現れる場所。
発生（開発中）→ 発覚（テスト）→ 返済（デバッグ）の一本の因果にし、v0.14 のランダムバグ抽選（15%）と v0.15 のバグ文（12%混入）を**この新システムに統合**する。

### 4-1. 発生（開発フェーズ）

`current.bugCount` に蓄積。発生源は 2 つ：

- **ミス打鍵**：fail のたび `P = BUG_ON_MISS × (1 − 抑制率)` で +1 🔧（BUG_ON_MISS = 0.35）
- **コード起因**：フレーズ完走ごと `P = BUG_ON_PHRASE × (1 − 抑制率)` で +1 🔧（BUG_ON_PHRASE = 0.10。ミスゼロでも一定量は出る＝デバッグフェーズが空にならない）

**抑制率 = min(0.8, プログラマー power 合計 / BUG_SUPPRESS_CAP)** 🔧（CAP = 2.0）
→ エンジニアが強い会社ほどバグが出ない（§3 の「プログラマーの効き先」が明確になる）

- HUD に **🐛×N カウンタ**常設。発生時は「🐛 バグが埋まった！」ポップ＋SE（因果の可視化）

### 4-2. 発覚（テストフェーズに実ゲームプレイを与える）

- 現行のテストフェーズは素通りに近い。**テストチケット（固定 3 枚 🔧）**をタイピングで消化すると、
  たまったバグが「発覚」する演出（🐛カウンタが精査され確定）→ デバッグへ
- テスト消化はバグを増やしも減らしもしない（発覚させるだけ。ここもミスすればバグは増える）

### 4-3. 返済（デバッグフェーズ＝バグが多いと大変）

- **デバッグの作業量 = bugCount × PHRASES_PER_BUG** 🔧（= 2 文/匹）
  → 開発中にバグを出すほど、デバッグで打つ量が線形に増える（オーナー要求の核）
- バグ修正文を 1 セット打ち切るごとに 🐛 が 1 匹消える（駆除ポップ＋SE）
- **全部潰すと「バグゼロ」ボーナス**：既存の noBugs 判定（タイピング演技 +5）に接続
- **途中で発売に進むことも可能**（`[このまま発売する]` ボタン）：残バグ 1 匹につき
  品質 −2 🔧・炎上リスク +2 🔧 を背負う（急いで出すか、丁寧に潰すかの駆け引き）

### 4-4. 統合・廃止

- `triggerBugIfDue`（15% 抽選の赤行バグ）と devPhrases の「約12%でバグ文」は廃止し、本システムに一本化
- 既存の `axes.bugRate`（イベント由来）は残バグのペナルティ合流先として継続利用
- `CurrentProject.bugCount` を追加（セーブは current 非保存のため移行不要）

### 4-5. 数値まとめ（すべて叩き台 🔧。分布シミュレーションと実機で追い込む）

| 項目 | 叩き台 |
|---|---|
| ミス打鍵のバグ化率 BUG_ON_MISS | 0.35 |
| コード起因のバグ化率 BUG_ON_PHRASE（フレーズ完走ごと） | 0.10 |
| 抑制率 | min(0.8, プログラマー power 合計 / 2.0) |
| デバッグ工数 PHRASES_PER_BUG | 2 文/匹 |
| テストチケット数 | 3 枚 |
| 残バグペナルティ | 品質 −2/匹・炎上リスク +2/匹 |
| 想定バグ数（mini・普通の腕・プログラマー1人） | 3〜6 匹 → デバッグ 6〜12 文 |

## 6. 検証チェックリスト（実装完了の定義）

- [ ] 全画面（企画/開発/テスト/デバッグ/評価/売上）が 1280×720 に収まりスクロールなし
- [ ] アサイン操作なしで企画→開発開始できる（全員参加）
- [ ] 役割効果・チーム効果プレビュー・Lvアップ差分・expゲージが表示される
- [ ] ミスするとバグが増え、プログラマーを増やすと減ることが体感できる（🐛カウンタ）
- [ ] バグが多いほどデバッグの打鍵量が増える。全部潰すとボーナス、残すとペナルティ
- [ ] 分布シミュレーションが引き続き緑（序盤 70+ 0% / 終盤 95+ ≤15%）
- [ ] unit（バグ発生・抑制率・デバッグ工数・残バグペナルティ）+ ユースケース（2画面分割・バグ駆除）
