## 0. オーナーフィードバック（2026-07-11）

1. **企画・開発の打鍵は「ましになったが、面白くはない。作業感が増してくる」**
2. **デバッグは非常に退屈。ただし退屈のままでよい** — ここは社員能力・アイテム・広告で解決する場所（痛みが投資の動機になる設計）
3. ただしデバッグは企画・開発と比べて**画面が寂しいので UI 改善は必要**

### プロデューサー解釈

- 作業感の正体＝**意思決定の不在**。今の打鍵は「出された文を順番に打つだけ」で、30秒ごとの選択が何もない。数字が伸びても「自分が選んだ結果」ではないので作業になる
- デバッグの退屈は**設計資産**。退屈 → 社員を育てる/広告を見る動機になる。ここで足すべきは面白さではなく「痛みの出口」と「見た目の張り合い」

## 1. 作業チケットの選択制（本丸・企画/開発の作業感対策）

**「打つ対象は常に1つ」の原則（v15確定）は守ったまま、「打つ前にどれをやるか選ぶ」を追加する。**

### 1-1. 開発フェーズ

現在：チケットがカテゴリ順に自動で出てくる → **改訂：常に手札3枚から1枚選ぶ**

```
┌─ つぎの作業を選ぶ（1/2/3 キー or クリック）─────────────┐
│ [1] 🎨 背景を描く       ふつう（3文）      品質 +標準     │
│ [2] </> 当たり判定を作る 長文チャレンジ（5文）品質 +大 ⚠ミスでバグ2倍 │
│ [3] 🐛 バグを1匹すぐ直す 短い（2文）        バグ -1       │
└──────────────────────────────────────────────┘
```

- 手札の内訳 🔧：
  - **標準チケット**（従来どおり。3文・標準報酬）
  - **チャレンジチケット**（低確率で混入。長文×5文・属性報酬1.5倍・**打鍵中のミスはバグ化率2倍**＝リスクリターン）
  - **🐛即修チケット**（bugCount ≥ 1 のとき混入。2文でバグ-1。後回しにしてデバッグで払うか、今払うかの選択）
- 選択は 1〜3 キー（ホームポジションから手を離さない）またはクリック。**選んだら打つ対象は1つ**（原則堅持）
- 選択肢の生成は `core/tickets.ts` の純粋関数（rng注入・unit テスト）

### 1-2. 企画フェーズ

- 同じ手札UIで「どの企画項目から埋めるか」を選ぶ（コンセプト/世界観/…の順序が選べるだけでも「進め方は自分が決めた」感が出る）
- 各カテゴリの効果（💡面白さ寄り / ⭐期待度寄り）は表示済みなので、**選択＝ビルド方針**になる

### 1-3. なぜこれが作業感に効くか

- 30秒ごとに「安全に積むか、リスクを取るか、借金（バグ）を返すか」の3択が発生する
- バグの「今すぐ直す vs 後回し（デバッグで払う）」の駆け引きがコアループに入る（v17 の [このまま発売] と対になる）

## 2. デバッグの UI 改善＋「出口」（退屈は仕様のまま）

**ゲームメカニクスは変えない**（バグ×2文の返済のまま）。見た目と出口だけ整える。

### 2-1. UI 改善（寂しさ対策）

- **バグ列の可視化**：残バグを 🐛×N の羅列ではなく「虫が並んで待っている」列で表示。1匹倒すごとに**潰れる演出＋SE＋残りが詰まる**
- 修正ログ（「✓ ぬるちぇっくをたす — 1匹駆除」）を流す
- 進捗バー「駆除 3/8」
- ※ドット絵素材（バグ虫スプライト。v15 で保留したもの）の投入は **PixelLab 発注＋オーナー承認後**。v19 はまず絵文字＋CSS アニメで骨格を作る

### 2-2. 出口①：広告でバグ半減（マネタイズ動線の初号）

- デバッグフェーズに **「📺 広告を見てデバッグ応援（バグ半分駆除）」** ボタン 🔧（1開発1回）
- 既存 AdProvider（モック）を使用。「退屈 → 広告が救い」はオーナーの設計意図（アイテムは規模が大きいので次版以降）

### 2-3. 出口②（既存の確認）

- 社員能力による抑制（発生を減らす）は実装済み。デバッグ画面に「🧑‍💻 バグ抑制 N%（プログラマー）」を表示して**育てる理由をここでも見せる**

## 3. スコープ外

- アイテムシステム（デバッグ緩和アイテム等）→ v20 候補。設計から必要
- 山場イベント（締切依頼・ライバル発売）→ 選択制の手応えを見てから
- 音・BGM 本実装／PixelLab 素材の本発注（骨格の体験確定後にオーナー承認を取って発注）

## 4. 数値まとめ（叩き台 🔧）

| 項目 | 叩き台 |
|---|---|
| 手札の枚数 | 3 枚（標準は常に1枚以上） |
| チャレンジチケット | 出現率 30% / 5文 / 属性報酬 ×1.5 / ミスのバグ化 ×2 |
| 即修チケット | bugCount≥1 で出現率 50% / 2文 / バグ −1 |
| 広告デバッグ応援 | バグ残数の 50% を即駆除（切り上げ）。1開発1回 |

## 5. 検証チェックリスト

- [ ] 手札選択が 1〜3 キーで動き、選択後は従来どおり1文入力（1280×720 内・スクロールなし）
- [ ] チャレンジのリスク（ミスバグ2倍）とリターン（報酬1.5倍）が unit テストで保証される
- [ ] 即修チケットでバグが減る／広告でバグ半減（実CDP入力テスト＋unit）
- [ ] デバッグ画面：駆除演出・ログ・進捗バー・抑制率表示（overflow 0）
- [ ] 分布ガード・進行シミュレーション・既存 e2e がすべて緑のまま
- [ ] オーナー実プレイで「作業感」が減ったかを確認
