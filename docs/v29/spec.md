## 改訂履歴

- 2026-07-22 初版。発売による無償ステージ自動解放（`computeStageUnlocks`）を廃止し、ジャンル/テーマの stage2 以降は **購入（`buyGenre`/`buyTheme`）でのみ解放**に一本化する方針を確定。初期解放（stage1）と既存プレイヤーのレガシー移行（`toV7`）、カテゴリの自動解放は**据え置き**。価格バランスは 🔧 で残置。

## この版で変えること（要点）

1. **発売時の自動解放を止める**：`computeRelease` が毎回呼んでいた `computeStageUnlocks`（累計売上 or ヒット作本数でステージ到達→無償一括解放）を発売処理から外す。発売を重ねてもジャンル/テーマは解放されない。
2. **解放経路は購入のみに一本化**：stage2〜4 のジャンル/テーマは `buyGenre`/`buyTheme`（資金で購入）でしか解放されない。購入導線・価格・UI は v0.21 のまま流用（**無改修**）。
3. **据え置くもの（変えない）**：
   - 初期解放 = stage1（ジャンル: puzzle/adventure/simulation、テーマ: sushi/onsen/farming）。最初から使える。
   - **カテゴリ**（グラフィック/サウンド/…）の解放は現状どおり（対象外）。
   - レガシーセーブ移行 `toV7`（v6→v7 一度きり）は `computeStageUnlocks` を残して**過去に稼いで得た解放を消さない**。
4. **なぜ小さく済むか**：継続的な自動解放は `release.ts:242` の1経路だけ。毎回のロード整形 `shapeLoaded` はしきい値再解放をしておらず（保存済み∪使用済みの防御 union のみ）、修正は発売処理の数行の除去で足りる。

## 1. 事業目的と前提

- 最上位の目的：「速さと品質を競うゲーム会社経営シム／長く遊ぶ人が一番得する／広告は人質にしない」（game-design スキル）。
- 目的（オーナーの言葉・1行）：**「作っていれば勝手に増える」をやめ、ジャンル/テーマは金を払って解放する**。解放を能動的な投資判断にする。
- 前提：v0.21 で購入システム（`buyGenre`/`buyTheme`・価格逓増）は実装済み。本版は**既存の自動解放を外すだけ**で購入制へ移行できる。

## 2. コンセプト

- 解放 = 「作りたい組合せを金で引き寄せる能動的投資」。図鑑探索（コレクション）への投資と一体化する。
- 「駄作量産でも時間で解放される」受動進行を廃し、**資金の使い道**として解放を明確な選択肢にする（採用・規模解放・借金返済・広告に並ぶ4本目の金の吸収先）。

## 3. コアループへの影響

- **企画**：選べるのは「初期解放 + これまでに購入したもの」だけ。未解放は従来どおり `LockedShop`（購入導線）に並ぶ（`PlanScreen.tsx:272-330`。UI 変更なし）。
- **発売**：メタスコア/売上/ファン/実績/カテゴリ解放/社員成長は従来どおり。**ジャンル/テーマの解放パッチだけが無くなる**。
- 詰まり防止：初期3ジャンル×3テーマ（=9組）は最初から自由に作れるので、序盤に選択肢ゼロで手詰まりにはならない。

## 4. 経済設計

- 購入価格（`INVEST_CONFIG`・据え置き）：基礎額 stage2 ¥30万 / stage3 ¥300万 / stage4 ¥3000万。実価格 = 基礎額 × `1.8 ^ (これまでの購入数)`（買うほど逓増）。
- **購入対象の総量**：stage2〜4 のジャンル **24種**（stage2:13 / 3:6 / 4:5）＋ テーマ **26種**（stage1=3種のみ初期）。合計 約50件が購入対象になる。
- 🔧 **価格バランス（要オーナー判断・本版では据え置き実装）**：逓増カーブ 1.8^n は「一部は自動解放され、残りを金で前倒し」という**併存前提**でチューニングされた（`balance.ts:INVEST_CONFIG` コメント「青天井の金の吸収先」）。自動解放を外すと**全50件を購入前提**になり、数個買うと1件あたり数千万〜億に跳ね上がって実質解放不能域に入る。以下は次段の判断材料：
  - (a) 逓増はそのまま（＝解放は超長期の金の使い道。終盤リッチ層向けシンク）。← 本版の既定
  - (b) 公比を緩める（例 1.8→1.3）／基礎額を下げる。
  - (c) 購入数カウントの扱いを見直す（stage別に分ける等）。
  - → 実機で序盤〜中盤の体感を見てから、必要なら **v0.28 総合バランス**で調整する（本版は機構の切替に限定）。

## 5. UX

- UI 追加・削除なし。企画画面のジャンル/テーマ節は解放フィルタ済み（`PlanScreen.tsx:275,306`）＋購入ショップ（`LockedShop`）がそのまま機能する。
- 発売画面に「新ジャンル解放！」のトースト等は**元々存在しない**（自動解放は無告知でパッチされていただけ）ので、除去に伴う UI 欠けは無い。カテゴリ解放の告知があればそれは維持。

## 6. 技術メモ（変更点の因果チェーン）

- **除去**：`src/core/release.ts` — `computeStageUnlocks` の呼び出し（242-247）と、パッチの `unlockedGenres/unlockedThemes` への `...stageUnlock.newGenres/Themes` 追記（281-282）。パッチはこの2フィールドを**現状値のパススルー**（`[...ctx.unlockedGenres]` / `[...ctx.unlockedThemes]`）にする（`ReleasePatch` 型は必須フィールドのため省略不可）。`import` から `computeStageUnlocks`（と未使用化するなら `StageUnlock`）を整理。
- **維持**：`src/core/progression.ts` の `computeStageUnlocks` 関数本体（`src/utils/storage.ts:382` の `toV7` が使用継続＝レガシー移行のため残す。デッドコードにならない）。`progression.test.ts` も維持。
- **維持**：`shapeLoaded`（`storage.ts:411-438`）はしきい値再解放をしていないので変更不要。`buyGenre`/`buyTheme`（`gameStore.ts:658-682`）・`invest.ts`・`PlanScreen`・`LockedShop` は無改修。
- **カテゴリ非対象**：`computeNewlyUnlockedCategories`（`release.ts:248-252,283`）は一切触らない。

## 7. 検証チェックリスト（完成条件・[3]検証の消し込み用）

ユーザー操作の言葉で「何が起きたら完成か」：

1. 初期状態で企画を開くと、選べるジャンルは puzzle/adventure/simulation の3つだけ、テーマは sushi/onsen/farming の3つだけ（stage1）。
2. DEV で累計売上を ¥1億超・ヒット作を複数出しても、**発売後に企画のジャンル/テーマ選択肢が増えない**（自動解放しない）。
3. 未解放ジャンル/テーマは `LockedShop` に価格付きで並ぶ。**購入すると**その場でジャンル/テーマ選択肢に現れ、資金が価格分だけ減る。
4. 資金不足では購入できず、残高がマイナスにならない。既に解放済みは購入不可（二重課金なし）。
5. リロードしても、解放集合は「初期 ∪ 購入済み ∪ ライブラリ使用済み」のまま（発売しきい値で勝手に増えない・購入済みが巻き戻らない）。
6. カテゴリ解放は従来どおり機能する（回帰なし）。
7. 検証4点セット（build / test:unit / test:ui / test:e2e）が全緑。
