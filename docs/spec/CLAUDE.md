# docs/spec/ — 現行の確定仕様（生きた資料）

**このフォルダは「いまのゲームが実際にどう動いているか」を書く唯一の場所。**

## このフォルダを触るときのルール

1. **新しい言葉を思いつきで使わない。** 会話でも同じ。
   **①言葉と定義をオーナーに提示 → ②合意 → ③[glossary.md](./glossary.md) に記載 → ④使う** の順を守る。
   仮の呼び名で説明を進めると、何の話をしているのか通じなくなる
2. **実装が真。** 資料と実装が食い違ったら、**まずコードを確認してから**資料を直す。資料を信じて実装を変えない
3. **効いていない機能を「効く」と書かない。** 定義だけあって効果がないものは、資料からも画面からも消す
4. **叩き台の数値をここに置かない。** 検討中の値は `docs/plans/` に置き、確定してから持ってくる
5. **決定の経緯・不採用にした案を書かない。** 経緯は `docs/plans/<id>/` と git 履歴。ここは「今どうなっているか」だけ
6. **ロジックを変えたら、同じコミットでここを更新する。** 実装だけ直して資料を放置しない
7. **章を足したら下の目次に追記する**

## 目次

| ファイル | 内容 |
|---|---|
| [glossary.md](./glossary.md) | 用語定義。何がどこに属するか・どの機能が実際に効いているか |
| [score-model.md](./score-model.md) | **スコアの仕組み**。スキル → 特徴ポイント → メタスコア → 売上 |
| [scoring.md](./scoring.md) | 計算式の読み順（どのファイルの何を見ればよいか） |

**未実装のものはここに書かない。** ここは「いま動いているもの」だけ。決定したが未実装のものは `docs/plans/` に置く。

## なぜこのフォルダがあるか

版ごとの企画書（旧 `docs/vNN/spec.md`）を現行仕様として読んだことで、事故が繰り返された：

| 資料の記述 | 実際 |
|---|---|
| ローンチ広告 リリース売上 ×1.5 | 初動のみ ×1.5（総売上では +10%）＝**画面の「売上+50%」は詐称だった** |
| 軸「売上予測」が売上に効く | 到達不能なデッドコード |
| 品質の肝は「完成後の任意ポリッシュ」 | その画面は stub で存在しない |
| 社員リストの「開発 +0.60 LoC/秒」 | 自動開発機能は誰も呼んでいなかった |

**資料が実装より古いと、プレイヤーに嘘をつく実装が生まれる。** だから版ごとの企画書は全廃した。
