# スコアと売上の算出方法

作品をリリースしたときに「メタスコア」と「売上」がどう決まるかを、順番どおりにまとめる。
**設計の意図と根拠は [score-model.md](./score-model.md)** にある。ここは実装の読み順。

実装は `src/core/release.ts`（全体の流れ）／`src/core/metascore.ts`（メタスコアの式）／
`src/core/features.ts`（特徴ポイントの蓄積）／`src/utils/metascore.ts`（売上とファン）。

計算は **特徴ポイント → メタスコア → 売上 → 入金** の順に進む。

---

## 1. 特徴ポイント（0〜100 × 5種）

作品は 🕹操作性 ／ 🎨グラフィック ／ 🎵サウンド ／ 📖ストーリー ／ 💡革新性 の5つを持つ。

### 1-1. 開発フェーズの打鍵で積む

文を1つ打ち切るごとに、その文の分野の特徴ポイントが増える。

```
加算量 ＝ ゲーム規模係数 × 打鍵倍率 × スキル合計
```

| 項 | 中身 | 実装 |
|---|---|---|
| ゲーム規模係数 | ミニ 1.32 ／ スマホ 0.25 ／ インディー 0.09 ／ 話題作 0.048 ／ AAA 0.034 | `FEATURE_SCALE_COEF` |
| 打鍵倍率 | 0.95〜1.05（速度ランク × コンボ帯） | `typingMultiplier` |
| スキル合計 | その分野のスキルを持つ参加社員の合計。**同分野の2人目以降は効率が大きく落ちる（×0.12）**。装備の倍率込み | `skillTotalsOf` / `effectiveSkillsOf` |

- **文が回ってくるのはチームがカバーしている分野だけ。** グラフィッカーがいなければグラフィックの文は出ない
- 総打鍵量 ＝（総文数 ÷ 4）× カバー分野数。**分野を絞ると開発が早く終わる**（＝月固定費が安い）

### 1-2. 革新性だけ打鍵では伸びない

企画時点で決まる。**同じジャンル×テーマを連投すると下がる**（100 → 50 → 25 → 10）。
別の組合せを1本作れば 100 に戻る。実装は `innovationFor`。

### 1-3. 残バグは特徴ポイントを削る

発売時に残っているバグは操作性から引かれる（`remainingBugPenalty`）。
バグは触り心地に出る、という理屈。

## 2. メタスコア（0〜100）

```
メタスコア = Σ( 特徴ポイント × 正規化重み )
           ＋ 相性補正（−8〜+8）
           ＋ トレンド合致（両方 +10 ／ 片方 +5）
           ＋ 評価家のブレ（±5）
           → 0〜100 にクランプ
```

**この一本以外の経路でスコアは動かない。**

### 2-1. 重みはジャンルの「型」が決める

27ジャンルは6つの型のどれかに属し、型が ◎（3）／○（1）／△（0.5）を決める。
**各ジャンルで合計 1.0 に正規化**する（揃えないと ◎ の多いジャンルが有利になる）。

実装は `src/data/archetypes.ts`。型と割当の一覧は [score-model.md §4](./score-model.md)。

### 2-2. 相性はメタスコアに加算する

ジャンル×テーマの相性を −8〜+8 点に写像して足す（`compatBonusFor`）。
**実装の相性は 0.70〜1.60**（中央値 1.05）なので、実際に出る補正は **−2.4〜+4.8**。
売上への乗算ではなく点にするのは、**区分をまたがせて発見の報酬を実感させる**ため。

---

## 3. 売上

```
売上 ＝ 基準売上（規模） × ヒット区分の倍率 × ソフトボーナス × トレンド × マーケ広告 × 市場系軸
```

### 3-1. ヒット区分

| メタスコア | 区分 | 倍率 |
|---|---|---|
| 0〜29 | 致命的失敗 | ×0.25 |
| 30〜49 | 失敗 | ×0.6 |
| 50〜69 | 普通 | ×1 |
| 70〜79 | ヒット | ×2 |
| 80〜89 | 大ヒット | ×3.5 |
| 90〜94 | 名作 | ×6 |
| 95〜100 | 神ゲー | ×10 |

**基準売上 ＝ 普通（×1）のときの売上。** ミニ ¥300万 ／ スマホ ¥3000万 ／
インディー ¥3億 ／ 話題作 ¥20億 ／ AAA ¥60億。

### 3-2. ソフトボーナス（上限なし・独立倍率）

| ボーナス | 式 |
|---|---|
| 広報 | 広報スキル合計 ÷ 100 × 0.2（2人目以降は ×0.12） |
| ファン | √ファン数 ÷ 400（1万人 +25% ／ 4万人 +50%） |
| 初組合せ | +5% |

### 3-3. 別枠の倍率

トレンド売上（両方 ×1.10 ／ 片方 ×1.05）、マーケティング広告（×1.1）、
市場系軸（話題性 − 炎上リスク。0.5〜2.0 でクランプ）。

### 3-4. 入金

総売上の **20%** が初動で即入金、残り 80% は販売プールに入って日々取り崩される。
減衰率はメタスコアで決まる（高評価ほど長く売れる）。

**ローンチ広告**（発売後のリワード広告）は**発売直後の入金だけ ×1.5**。
総売上に対する実効は +10%。画面には「初動」と書かず「発売直後の入金 +50%」と書く。

---

## 4. ファン

```
獲得ファン ＝ fanDelta(メタスコア, 広報ボーナス) ＋ 期待度 ＋ 話題性×0.5 ＋ 信頼度 − 炎上リスク
```

企画フェーズの打鍵は**期待度**に積まれ、ここでファン増加になる。

---

## 5. 廃止したもの（復活させない）

| 廃止したもの | 理由 |
|---|---|
| 品質 Q（キャラ能力・ジャンル相性・タイピング演技・運の基底50 の合成） | 「打たなくてもスコアが出る」の元凶。1文も打たずに品質72が出ていた |
| カテゴリ6種 | 企画で選ぶ枠が二重になっていた。選ぶのはジャンル×テーマだけ |
| 品質系の軸（面白さ／操作性／バランス） | 品質という合成値ごと廃止。付与していたイベントは期待度へ付け替え |
| devStats の品質加点・装備の品質加点 | 特徴ポイントに一本化 |
| 軸「売上予測」 | 到達不能なデッドコードだった |
| 役割の固定係数（`ROLE_EFFECT`） | 職種＝一番高いスキルの呼び名になったので不要 |
