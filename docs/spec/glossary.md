# 用語集

このプロジェクトで使う言葉の定義。**ここにない言葉を新しく作らない。**

用語が混ざる最大の原因は「社員に属するもの」「作品1本に属するもの」「発売後の評価」が
同じ言葉で語られていたこと。**所属で分けて定義する。**

凡例
- ✅ **確定** … 決定済みの仕様（[score-model.md](./score-model.md)）。実装はこれから
- ⚙ **現行** … いま動いている実装（[scoring.md](./scoring.md)）。確定仕様に置き換わる
- ❌ **廃止** … 使わない。復活させない

## A. 社員に属する

会社の資産。作品をまたいで持ち越す。

| 用語 | 定義 | 状態 |
|---|---|---|
| **スキル** | 社員が持つ能力値。種類は プログラミング／グラフィック／サウンド／シナリオ／広報 の5種。**1人が持てるのは1つか2つ**（持たない分野は伸ばせない） | ⚙ 現行 |
| **総合力** | その社員のスキル値の**合計**。採用時に範囲からランダムに決まり、**レベルアップで増える**（増えた分は持っているスキルに配分される）。**1スキルならそのまま1分野に乗り、2スキルは分散ペナルティ（×0.9）を掛けてから主0.7／副0.3 で配分** | ⚙ 現行 |
| **分散ペナルティ** | 2スキルの社員に掛かる目減り（×0.9）。専門特化のほうが総合力が高くなる | ⚙ 現行 |
| **ランク** | **C／B／A／S の4種**。**採用時に決まる素質のラベルで、育っても変わらない。「どこまで伸びるか」（天井）を表す**。Lv1 の総合力はランクによらずほぼ同じ（15〜28 🔧）で、Lv10 で C=40／B=60／A=80／S=100 まで開く 🔧。開封画面には**到達点**（「育てば 100」）を出す | ⚙ 現行 |
| **職種** | **一番高いスキルの呼び名**。プログラマー／グラフィッカー／サウンドクリエイター／シナリオライター／広報。2つ目のスキルは職種名に出ない。管理する枠ではなく表示上の名前 | ⚙ 現行 |
| **装備** | 社員ごとの PC・チェア・小物の3スロット。**社員のスキルに分野別の倍率を掛ける**（作品側の数値には直接掛けない。固定値を足す方式は不採用）。例：液タブ＝グラフィック ×1.25。**装備を掛けた実効スキルは 100 を超えてよい**（特徴ポイント側に0〜100の上限があるのでスコアは壊れない） | ⚙ 現行 |
| **レベル / 経験値** | リリースに参加すると経験値が入り、レベルが上がる。**レベルが上がると総合力が増える＝「今どこまで伸びたか」を表す**。スキルの種類は増えない。1本で得る経験値は **(基礎10 + メタ連動ボーナス) × ゲーム規模の倍率**（ミニ ×1／スマホ ×3／インディー ×6／話題作 ×12／AAA ×24） | ⚙ 現行 |
| **作業チケット** | 開発フェーズで打つ作業の単位。カテゴリは プログラム／グラフィック／サウンド／**シナリオ** の4種で、開発スキル4種と1対1。旧「ゲームデザイン」はシナリオに付け替えた（文プールも書き下ろし） | ⚙ 現行 |
| **オフィス規模** | オフィスの席数。現在は**6席**。将来は拡張できる。**ゲーム規模とは別物** | ⚙ 現行 |
| ~~能力（`power`）~~ | 役割共通の単一能力値（0〜1）。スコア・売上・バグ抑制はすべてスキルへ移行済み。**給与計算だけがまだ使う**（総合力 ÷ 100 で導出される互換値） | ❌ 廃止（給与のみ残存） |
| ~~得意分野（`specialties`）~~ | 社員が得意な分野。未接続で表示だけされていた | ❌ 廃止 → 画面表示は撤去済み。型は互換のため残存（セーブ互換） |
| ~~役割の固定係数（`ROLE_EFFECT`）~~ | 役割ごとに `power` に掛ける係数 | ❌ 廃止 → 職種＝スキルなので不要 |
| ~~品質 Q~~ | キャラ能力・ジャンル相性・タイピング演技・運の基底50 を合成した値 | ❌ 廃止 → 特徴ポイント → メタスコアの一本道に置換 |
| ~~カテゴリ6種~~ | 企画で選ぶ「グラフィック/サウンド/ストーリー…」の枠 | ❌ 廃止 → 選ぶのはジャンル×テーマだけ |
| ~~品質系の軸（面白さ/操作性/バランス）~~ | イベントで増える品質加点 | ❌ 廃止 → 付与していたイベントは期待度（hype）へ付け替え |

## B. 作品1本に属する

企画〜発売で積み上がり、発売でリセットされる。

| 用語 | 定義 | 状態 |
|---|---|---|
| **特徴ポイント** | **どの作品も持つ5つの数値**。作品の出来を表す。🕹操作性／🎨グラフィック／🎵サウンド／📖ストーリー／💡革新性。上4つはスキルで伸ばす。**革新性だけスキルでは伸ばせず、同じジャンル×テーマの組合せを連投すると下がる**（別の組合せを1本作れば復活）。**メタスコアはこの5つだけから決まる** | ⚙ 現行 |
| **ジャンル** | アクション、RPG、パズル等（27種）。企画で選ぶ。**どの特徴ポイントが重く効くかを決める** | ⚙ 現行＋✅追加 |
| **型** | ジャンルの分類（アクション型／体感型／戦術型／賑わい型／絵物語型／物語型 の**6種**）。**どの特徴ポイントが◎になるか**を持つ。全27ジャンルがどれかに属する | ✅ 確定 |
| **重み（◎○△）** | 型が持つ、特徴ポイントごとの重要度。**◎重要／○標準／△軽い**。全型が ◎2つ・○2つ・△1つ で合計が揃う。**革新性は全型で○固定**なので、◎は残り4分野から2つ選ぶ（6通り＝型6種）。内部では ◎=3／○=1／**△=0.5** に換算し、ジャンルごとに合計1.0へ正規化する | ⚙ 現行 |
| **テーマ** | ファンタジー、寿司、忍者等。企画で選ぶ | ⚙ 現行 |
| **相性** | ジャンル×テーマの組合せの良さ。**実装の実測は 0.70〜1.60**（中央値 1.05）。図鑑の発見対象。**相性補正に写像してメタスコアへ加算**（式の上限は ±8 だが、相性が 1.60 止まりなので実際に出るのは **−2.4〜+4.8**）。トレンド合致と同じ形＝発見がヒット区分を押し上げる | ⚙ 現行 |
| **ゲーム規模** | 作る作品の大きさ。ミニゲーム／スマホゲーム／インディー大作／話題作／AAAタイトル。開発費・売上・必要期間を決める。**ミニゲームの開発期間は 8週→4週 に短縮（実装済み）**。**オフィス規模（席数）とは別物** | ⚙ 現行 |
| **フェーズ** | 作品1本を作る工程。**企画 → 開発 → テスト → デバッグ → 発売** の順に進む。特徴ポイントが積まれるのは開発フェーズ。**企画フェーズの打鍵は期待度（発売時のファン増加）に効く** | ⚙ 現行＋✅ |
| **完成度** | 開発フェーズの進行度。100%でフェーズ完了。**スコアには効かない**（終了条件のみ） | ⚙ 現行 |
| **残バグ** | 発売時に残っているバグの数。ミス打鍵で発生し、デバッグフェーズで潰す | ⚙ 現行 |
| ~~作業チケットのカテゴリ~~ | プログラム／グラフィック／サウンド／ゲームデザインの4種 | ❌ 廃止 → 特徴ポイントの分野に統合 |
| ~~カテゴリ6種~~ | グラフィック／サウンド／ゲームプレイ／ストーリー／演出／革新性。企画で選ぶ想定だったが廃止済みで空のまま残っていた | ❌ 廃止 → 特徴ポイントに作り替え |
| ~~軸（面白さ／操作性／バランス）~~ | イベント報酬の中間変数 | ❌ 廃止 → 特徴ポイントに直接積む |
| ~~品質~~ | 0〜100 の内部スコア。特徴ポイントとメタスコアの間にあった中間値 | ❌ 廃止 → 特徴ポイントから直接メタスコアを出す |

## B2. 打鍵と加算（スキルが特徴ポイントに変わる仕組み）

| 用語 | 定義 | 画面に出るか | 状態 |
|---|---|---|---|
| **特徴ポイント加算量** | 文を1つ打ち切ったときに、その分野の特徴ポイントへ加算される点数 | **出る**（打ち切った瞬間に「🎨 グラフィック +2.7」） | ✅ 確定 |
| **スキル合計** | その分野のスキルを持つ参加社員の、スキル値の合計。**同じ分野の2人目以降は ×0.12**（分業のロス。1人目100＋2人目100 → 合計112） | **出る**（企画画面で内訳つき「グラフィック スキル合計 150（花子100＋太郎50）」） | ✅ 確定 |
| **ゲーム規模係数** | ゲーム規模ごとの定数 🔧（ミニ1.58／スマホ0.3／インディー0.108／話題作0.058／AAA0.041）。**入門チーム**（その規模を解放した直後の想定チーム）の主力分野が特徴ポイント70前後に届く値を基準にする。AAAのみ「最強構成＋上手い打鍵でようやく100」の天井基準 | 出ない（**内部専用**） | ✅ 確定 |
| **コンボ** | **ミスなしで連続して正しく打てたキーの数。** ミスで0に戻る。文をまたいで継続する | **出る**（打鍵中のコンボ表示） | ⚙ 現行 |
| **速度ランク** | **1文を打ち切るまでの時間で決まる3段階。** 基準時間は かな1文字あたり340ms。基準の55%未満＝PERFECT／85%未満＝GREAT／それ以上＝GOOD。**1文ごとにリセットされる** | **出る** | ⚙ 現行 |

```
特徴ポイント加算量 ＝ ゲーム規模係数 × 打鍵倍率 × スキル合計
```

**打鍵倍率**（✅ 確定）… 速度ランクとコンボから決まる **0.95〜1.05** の倍率。**下手は1未満＝ペナルティ**

| | 速度ランク | コンボ | 合計 |
|---|---|---|---|
| 下手 | ×0.97 | ×0.98 | ×0.95 |
| 普通 | ×1.00 | ×1.01 | ×1.01 |
| 上手 | ×1.03 | ×1.02 | ×1.05 |

- 速度ランク：GOOD ×0.97 ／ GREAT ×1.00 ／ PERFECT ×1.03
- コンボ：10未満 ×0.98 ／ 10以上 ×1.00 ／ 30以上 ×1.01 ／ 100以上 ×1.02
- **幅を 1.105 倍に抑える理由**：ヒット区分は上位で幅が狭い（名作5点・神ゲー6点）ため、
  1.07倍を超えると腕だけで区分をまたぐ。`game-design` §10-3 に反する。
  この幅なら中盤は0区分・上位帯で1区分だけ動く

**1分野あたりの文数は 総文数 ÷ 4 で固定**（カバー分野数で割らない）。分野を絞ると総打鍵量が減り、
開発が早く終わる＝月固定費が安くなる、という形で効く。

## C. 発売後の評価

| 用語 | 定義 | 状態 |
|---|---|---|
| **メタスコア** | レビュー点（0〜100）。**特徴ポイント × ジャンルの型の重み** を合計し、**相性補正（−8〜+8 🔧）**・トレンド合致（+10/+5）・評価家のブレ（±5）を乗せる。残バグは**操作性の特徴ポイント**から引かれる。**95以上で「神ゲー認定」** | ⚙ 現行 |
| **ヒット区分** | メタスコアの帯。7区分あり、それぞれが**売上倍率**を持つ（下表）。**1点の差で区分をまたぐと売上が約2倍変わる** | ✅ 確定 |
| **トレンド** | 今月人気のジャンル×テーマ。合致するとメタスコアと売上が上がる | ⚙ 現行 |
| **初動** | 売上総額の20%。発売直後に即入金 | ⚙ 現行 |
| **販売プール** | 売上総額の80%。時間減衰しながら少しずつ入金 | ⚙ 現行 |
| **ファン** | 会社のファン数。売上倍率に効く（√ファン数÷400・上限なし） | ⚙ 現行 |
| **ローンチ広告** | 発売後のリワード広告。**初動のみ ×1.5**（総売上では+10%）。表示は必ず「初動売上 +50%」と書く | ⚙ 現行 |

### ヒット区分の一覧（⚙ 現行）

| ヒット区分 | メタスコア | 売上倍率 🔧 |
|---|---|---|
| 致命的失敗 | 0〜29 | ×0.25 |
| 失敗 | 30〜49 | ×0.6 |
| 普通 | 50〜69 | ×1 |
| ヒット | 70〜79 | ×2 |
| 大ヒット | 80〜89 | ×3.5 |
| 名作 | 90〜94 | ×6 |
| 神ゲー | 95〜100 | ×10 |

```
売上総額 ＝ ゲーム規模ごとの基準売上 × ヒット区分の売上倍率 × その他の補正（広報・ファン・トレンド等）
```

- **基準売上 ＝ 普通（×1）のときの売上** に再定義 🔧：ミニ¥300万／スマホ¥3000万／インディー¥3億／話題作¥20億／AAA¥50億
- **1作の売上上限は数百億**（AAA×神ゲー＝¥500億。オーナー確定「兆は出さない」）
- 例）ミニゲーム: メタ49 → ¥180万 ／ メタ50 → ¥300万 ／ メタ95 → ¥3000万
- 旧実装は ×0.33〜×500（レンジ1500倍）で、終盤に1作で兆が出ていた。上表に置き換え済み
- 旧称「段」「段倍率」は使わない。**ヒット区分**／**ヒット区分の売上倍率**と呼ぶ

## 紛らわしい言葉の使い分け

| よくある混同 | 正しい区別 |
|---|---|
| **スキル** と **特徴ポイント** | スキルは**社員**が持つ。特徴ポイントは**作品**が持つ。スキルで打つと特徴ポイントが積まれる |
| **特徴ポイント** と **メタスコア** | 特徴ポイントは5項目の内訳。メタスコアはそこから出る1つの点数 |
| **ジャンル/テーマ** と **特徴ポイント** | ジャンル・テーマは「**何を**作るか」。特徴ポイントは「**どう出来たか**」 |
| **完成度** と **特徴ポイント** | 完成度は「開発が終わったか」。スコアには効かない |
| **フェーズ** と **実装ステップ** | フェーズ＝**ゲーム内**の開発工程（企画→開発→テスト→デバッグ）。実装ステップ＝**開発チーム側**の実装計画の区切り（docs/plans）。ゲームの話には「実装ステップ」を使わない |
| **ゲーム規模** と **オフィス規模** | ゲーム規模＝作る作品の大きさ（ミニゲーム〜AAA）。オフィス規模＝席数。**「規模」だけで呼ばない** |
| ~~カテゴリ~~ | 2つの別物に同じ名前が使われていた（作業4種と特徴6種）。**この語は使わない** |

## 呼び方のルール

- **画面に出す言葉と、この用語集の言葉を一致させる。** 実装変数名をそのまま画面に出さない
  （「売上予測」は変数名がそのまま表示されていた例。何を指すのか誰も説明できなかった）
- **効いていない機能を「効く」と書かない。** 表示だけのものは表示ごと消す
