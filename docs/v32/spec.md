## 目的（オーナーの言葉で1行）

**「企画のときみたいに、開発中も社員が椅子に座って働いて“動いている”様子を見せる」**

- 手段（着席アイドル揺れ／エモート吹き出し）ではなく、目的は「開発中の画面が“置物”でなく“働いている”ように見えること」。迷ったらここに戻る。

## この版で変えること（要点）

1. 開発フェーズ中央の「**実装中の様子**」枠に、社員が机に座って働くオフィスシーン（`DevDeskScene`）を出す。企画の `PlanMeetingBoard` と同じ雛形（`office_bg` を机エリアにフォーカス＋着席キャラ＋頭上エモート）。
2. 「動き」は企画と**同一機構を流用**：React state → `key` 再マウント → CSS `steps()` アニメ → `setTimeout` 自動消去。着席スプライトへの微小アイドル揺れ（CSS `translateY`）＋頭上エモート吹き出し。
3. エモートは**開発版の抽選**（`core/devEmote.ts`、`planEmote` の類似）：
   - ambient「集中中」（…/❓）を一定間隔でランダム社員へ
   - チケット文完了トリガーで着席社員に「できた」（✨/❗/💡）
4. **新規素材ゼロ**（既存 `sitting/north.png`・`chair_north.png`・`laptop_north.png`・`office_bg.png`・`emote_*.png` を流用）。着席“タイピング動作”専用スプライトシートは follow-up（PixelLab 承認制・方向ぶん新規発注）。

## 1. 事業目的と前提

- 北極星：「速さと品質を競うゲーム会社経営シム／誰も弾かない」。本版は**コア体験・数値に一切触れない見た目の磨き版**。
- 前提（v0.26 の学び）：着席アイドルは一度「廃止」判断が出ているが、それは「待機オフィスは歩きの方が動いて見える」ため。**開発フェーズは席で作業するのが自然**なので、ここでは着席ベースの動きが目的に合致する。

## 2. 因果チェーン確認（実装前）

- 本版の追加は**すべて表示専用**。ゲームロジック（品質・売上・進捗・バグ・メタスコア）へ**一切書き込まない**。
- 既存の `planEmote` と同型：`DevelopScreen` のローカル state に載せ、`gameStore` のアクションは呼ばない。
- したがって `AXIS_QUALITY_BONUS_CAP` 等の CAP・重み・クランプとは**無関係**（衝突なし）。※アンチパターン#1 の回避を明記。

## 3. 現状（着手前ベースライン）

- 開発フェーズ中央は `DevelopCenter`（`DevelopScreen.tsx`）。縦積み：ヘッダー → チケット → ゲージ → 入力文 → ローマ字入力＋速度/正確さ/バグ → **`WorkInProgressPanel`（実装中の様子）** → `ResultCard`。
- `WorkInProgressPanel` はカテゴリ別に見た目が変わる：`program`→ProgramLogPanel、`graphics`→GraphicsCanvasPanel、`sound`→SoundMeterPanel、`design`→DesignMemoPanel、ボス戦→BossBattlePanel。
- **社員の着席キャラは本番のどの画面でも未描画**（座り素材は6役職ぶん揃うが admin `/admin/props` のみ結線）。開発フェーズにキャラを座らせる描画は**新規**。
- 素材・データは揃っている：`OFFICE_LAYOUT.seats`（6席・全 `dir:'north'`）、`chairSprite/laptopSprite/sittingSprite`、`PROP_TRANSFORMS`、`officeBgSrc`。企画会議ボードと同じ `office_bg` 空間で組める。

## 4. 設計（案C＝右カラム移設・オーナー方針 2026-07-24）

### 4-1. 配置：カテゴリ演出を右カラムへ移し、中央「様子」枠を `DevDeskScene` にする

**オーナー方針（2026-07-24）**：「カテゴリごとのパネルは右側に表示したいかも」。現状の右カラム（300px）は「現在のプロジェクト／現在の開発内容／次の目標」だけで**下半分が大きく空いている**（実機確認済み `dev-current-layout.png`）。ここへカテゴリ演出を移す。

- **中央の `WorkInProgressPanel` 枠 → `DevDeskScene`（着席デスクシーン）に置き換え**。中央＝「働くオフィスの絵（キャラ）」。
- **カテゴリ別演出（ProgramLogPanel／GraphicsCanvasPanel／SoundMeterPanel／DesignMemoPanel／BossBattlePanel）→ 右カラムの空きスペースへ移設**。右＝「実際の成果物（コードログ・キャンバス・メーター等）」。演出は**一切消さない**。
- この分離で「今どのカテゴリを作っているか」は右パネルが担い、中央のキャラは「誰が働いているか／動いている実感」を担う（役割分担）。
- 幅の縮小：中央（〜600px）→ 右（300px）へ移るため、各カテゴリパネルは300px幅で崩れないか実機調整。スクロール禁止・1280×720 厳守。

### 4-2. 見せ方（`PlanMeetingBoard` を雛形に）

- パネル高さは企画会議（210px）に合わせるか、空いた中央枠に合わせて調整（スクロール禁止・1280×720 厳守）。
- `office_bg` の**座席群にフォーカス**する transform（`FOCUS_CX/CY/H`）。
- 各席に：`laptop_north.png`（奥）、`sitting/north.png`（キャラ）、`chair_north.png`（手前）を `PROP_TRANSFORMS` の相対値で重ねる（`OfficeView`/`PropEditorTool` の着席規約と同じ）。
- 頭上エモートは `EmoteBubble` を流用（座り頭頂の実測オフセットを取り直す）。

### 4-3. 動きの機構（企画と同一）

- `core/devEmote.ts`：`pickDevEmote(rng, seatCount, kind)`（`planEmote.ts` を雛形にした純粋関数・rng 注入・unit テスト必須）。
- `DevelopScreen` に `devEmote` state＋発火キー：ambient は再帰 `setTimeout`、チケット文完了は既存の完了ハンドラ（development 分岐）にフック。
- 着席アイドル揺れは CSS `@keyframes desk-idle-bob-kf`（`translateY` 微小・無限ループ・席ごとに `animation-delay` をずらす）。bottom-center アンカーは外側ラッパーが持ち、揺れは内側 img に当てる（アンカー transform を潰さない）。

## 5. 完成条件（検証チェックリスト＝ゲート[3]の消し込みリスト）

- [ ] 開発フェーズに入ると、中央「実装中の様子」枠に**社員が机に座っている**オフィスシーンが出る。
- [ ] 何もしなくても、社員の頭上に一定間隔で**エモート吹き出し**がポップして消える（ambient 集中）。
- [ ] チケット文を**1つ打ち切る**と、着席社員の頭上に「できた」系エモートが出る。
- [ ] 着席キャラが**微妙に揺れて**いる（完全静止でない）。
- [ ] カテゴリ演出（プログラムログ等）が**右カラム**に出る。ボス戦になると右で**ボス戦パネル（HPバー）**に切り替わる。
- [ ] 1280×720 内・スクロールなし・青地×黒字などのコントラスト崩れなし（コントラストオラクル）。
- [ ] 4点セット（build / test:unit / test:ui / test:e2e）が全緑。`pickDevEmote` の境界値 unit テストあり。

## 6. やらないこと

- ゲームロジック・数値・バランスの変更（表示専用に限定）。
- 着席“タイピング動作”スプライトシートの新規発注（follow-up 候補・PixelLab 承認制）。
- 待機オフィス（`OfficeView`）・テスト/デバッグ/リリース各フェーズの演出変更（本版は開発フェーズのみ）。
