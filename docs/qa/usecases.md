# バグハント ユースケース定義

`/bug-hunt` が実際にプレイする台本。各 UC は **手順** と **期待（オラクル）** をセットで持つ。期待の無い UC は「感想」しか生まないので書かない。

## 検証レベル（重要）
- **システム名レベル**：`src/state/types.ts`（`Screen` / `DevPhase`）と `gameStore.ts` のアクションで裏取り済み（下表）。
- **操作レベル（クリック経路）**：どのボタンで何が開くかは**実画面で1回通して確定する（🖐 = 初回ライブ実行で埋める）**。
- 期待の根拠：`docs/` 最大版 spec ＋ game-design skill。数値は最新 spec 優先。

### 実在の画面とフェーズ（出典：src/state/types.ts）
- **Screen** = `office`（ルート/世界ステージ）/ `plan`（企画）/ `develop`（開発=タイピング）/ `release`（リリース/評価開示）/ `library`（作品）/ `collection`（図鑑）。
- **DevPhase** = `development → testing → debugging`（`DEV_PHASE_ORDER`）。
- **主要アクション** = `startProject` `reportWPM/Accuracy` `finishDevelopment` `advancePhase` `noteBugOnMiss/fixBug` `releaseWork` `tickSales` `hireCandidate/pullGacha` `unlockNextScale` `buyGenre/buyTheme` `buyAdDevBoost/buyAdSurvey/adDebugAssist` `borrowMoney/repayDebt` `triggerGameOver` `finishTutorial` `clearOfflineReport`。

## 規約オラクル（全 UC 共通・機械判定）

どの UC を回している間も**常時**チェック。該当したら敵対的検証を飛ばして確定。

- **1280×720 はみ出し / スクロール発生**：**viewport を 1280×720 にして** `scrollWidth>innerWidth || scrollHeight>innerHeight` で判定（800 のまま 720 と比較しない＝誤検知）。overflow で逃げていない。
- **`console.error` / uncaught 例外**：`browser_console_messages` が clean。
- **白画面**：ルート描画あり。
- **数値異常**：`NaN` / `undefined` 表示・**マイナス残高**・想定外の 0。
- **濃色背景に黒字（可読性・機械判定）**：全テキスト要素で **WCAG コントラスト比**を測る。文字色 vs 実効背景色（透過なら親を遡って合成）を計算し、**通常文字 < 4.5:1 / 大きい文字(≥18pt or ≥14pt太字) < 3:1** を違反として列挙。青/濃色ブロックに黒字（[[feedback_dark_bg_light_text]]）を機械的に捕まえる。判定スニペットは bug-hunt.md 参照。

## コアループ

### UC-01 企画→開発→デバッグ→リリース→販売を一周
- **前提**：DEV ビルド起動直後（`screen==='office'`）。
- **手順（ライブ検証で確定 ✅）**：
  1. `▶ 新しいゲームを作る` を押す。**社員 0 人だと採用ガチャが開く**（企画ではない）。`引く ¥50,000`→`雇用する` で 1 人採用。
  2. ガチャを **Escape** で閉じる → 再度 `▶ 新しいゲームを作る` → **企画会議**ダイアログ。
  3. ジャンル/テーマ/規模を選び（初期選択でも可）`▶ 開発開始`。チュートリアルが出たら `スキップ`。
  4. develop 画面でローマ字タイピング（keydown を window が拾う＝`browser_press_key` で 1 文字ずつ）。
  5. フェーズ進行：企画→開発→テスト→デバッグ→発売→開発完了（UI 6 段表示）まで。
- **期待**：各遷移が成立し詰まない／リリース後メタスコア 0〜100／残高が売上分だけ正しく増える／`console.error` 無し。
- **注意（ライブで判明）**：
  - **時間はリアルタイム進行**。タイピングの実時間でゲーム内週が進み固定費が毎月引かれる。
  - **zustand ストアは window 非露出**（`window.*store` 無し）→ ストア直叩きの早送り不可。DEV デバッグにも「開発完了」系は無い（source確認済み）＝コアループは完全にタイピング律速。
  - **⚠ 構造的ブロッカー（重大）**：AI エージェントは Playwright のツール往復で 1 打鍵ごとに実時間が数秒空く。ミニゲーム（予定12週）でも**打ち切る前にゲーム内で1年以上経過**し、固定費で **借入上限まで枯渇→ゲームオーバー**（実測：企画14%・経過62/12週・借金¥997.5万で倒産）。→ **AIによる手打ちフル一巡は事実上不可能**。
  - **✅ 解決（DEV フック実装済み）**：develop 画面に DEV 限定ボタン **「🛠 [DEV] 開発を即完了（発売へ）」**（`finishDevelopment()`）を追加。企画/開発フェーズ途中で押すと**時間経過ゼロで発売フェーズへ即到達**。back-half は「企画開始→即完了→結果を発表」で検証可能（実測：メタスコア🎯21・売上計上・残高増、破産なし）。本番ビルドでは非表示。

### UC-02 タイピング開発の判定
- **手順**：`develop` で正確に打つ / わざとミス / 放置。
- **期待**：WPM・正確さが品質へ反映（`reportWPM/reportAccuracy`）／ミスで不正加点なし／`noteBugOnMiss` が過剰にバグを積まない／放置で NaN・無限進行なし。
- **観点**：仕様オラクル。🔧 判定の数値仕様は spec と突き合わせ

### UC-03 フェーズ遷移とバグ処理
- **手順**：`development→testing→debugging` を進め（`advancePhase`）、バグを修正（`fixBug`）してリリース可能まで。
- **期待**：`debugging` でバグ 0 まで詰められる／v0.17.1 のバグ最低保証（`gameStore.test.ts` 参照）が守られる／バグ残でリリース時の挙動が spec 通り。
- **観点**：仕様オラクル。

### UC-04 リリースと評価開示（メタスコア）
- **手順**：`releaseWork` → `release` 画面で評価開示。
- **期待**：メタスコア 0〜100＋ブレ範囲内／高品質×好相性で低スコアにならない／ファン数・自己最高記録が更新。
- **観点**：仕様オラクル。

### UC-05 ジャンル×テーマ相性と図鑑
- **手順**：未開拓の組合せを初めて作る → `collection`（図鑑）を開く。
- **期待**：初回は相性不明、作ると図鑑に記録され以降可視化／`library`（作品）・`collection` 表示が崩れない。
- **観点**：仕様オラクル。

## 経営・経済

### UC-06 規模解放
- **手順**：条件達成 or DEV「規模解放（条件無視）」→ `unlockNextScale`。
- **期待**：解放で新要素／解放後もレイアウト 1280×720 内／状態破綻なし。🔧 解放条件は spec 確認

### UC-07 ジャンル/テーマ購入
- **手順**：`buyGenre` / `buyTheme` を実行。
- **期待**：購入でコスト分だけ残高減／購入分が企画で選べるようになる／残高不足時は購入不可（マイナスにならない）。

### UC-08 借金・返済
- **手順**：`borrowMoney` で借入 → `repayDebt` で返済。
- **期待**：借入で残高増・負債計上／返済で負債減・残高減／過剰返済でマイナスにならない／利息が spec 通り。🔧 利息仕様確認
- **観点**：数値整合（経済の要）。

### UC-09 ゲームオーバー ✅（UC-01 実行中に偶発検証済み）
- **手順**：開発を長引かせ固定費で借入上限超過（or `triggerGameOver`）。
- **期待**：`GameOverModal` が出る／画面内に収まる／リセットで状態が壊れない。
- **検証結果（✅ 正常）**：借入上限超過で「ゲームオーバー（借入上限を超え…）」モーダルが正しく表示。残高¥0・借金¥997.5万を正確表示、1280×720 内に収まり `console.error` 0、「リセットして再開」導線あり。**倒産をクラッシュせず綺麗にハンドリング**。事前に「予定超過 +50週（固定費がかさむ！）」と警告する親切設計も確認。

## 補助システム

### UC-10 広告（開発ブースト/調査/デバッグ支援）
- **手順**：`buyAdDevBoost` / `buyAdSurvey` / `adDebugAssist` を各所で使う。
- **期待**：視聴後に効果が反映され操作に戻る（固まらない）／効果が spec の倍率通り／DEV と本番で挙動差が意図通り。

### UC-11 採用（メタスコアガチャ・社員）
- **手順**：`hireCandidate` / `pullGacha` / `dismissCandidate` / `fireEmployee`。
- **期待**：結果が正しく反映／演出後に操作可能へ復帰／コスト分だけ残高減／解雇で社員が消え数値が整合。

### UC-12 チュートリアル・オフライン報酬・設定モーダル
- **手順**：初回チュートリアル（`finishTutorial`）／再訪時のオフライン報酬（`clearOfflineReport`）／設定モーダル・各窓（`plan/library/release/collection`）の開閉。
- **期待**：チュートリアルが最後まで進み詰まない／オフライン報酬が妥当な値／モーダル開閉で背後状態が壊れない・画面内に収まる・ゲームに戻れる。

### UC-13 DEV デバッグ操作の副作用
- **手順**：DEV「お金追加」「累計売上を追加」「規模解放（条件無視）」。
- **期待**：加算が正しく反映され他システム（解放条件・実績）と矛盾しない。（DEV 限定＝本番非搭載を確認）
