## A. コアループの欠落

### A-1. ノリゲージ（4-G） — **P0**
- **設計**：ミスなく速く打ち続けるとゲージ上昇、打鍵効率・品質にボーナス。ミスで途切れる
- **現状**：ミスカウンタ表示のみ。連続正打のフィードバックなし
- **影響**：「ノってる」緊張感がゼロ。タイピングゲームとしての気持ちよさが弱い
- **要追加**：
  - `useTyping` にコンボ数の状態追加（correct時 +1、fail時 0）
  - ノリゲージUI（DevelopScreen/PolishScreen）
  - 一定コンボで自動進行ボーナス（例：+0.3 LoC/秒）
  - ポリッシュ時はQ加算係数を倍化（コンボ中 +6/LoC 等）

### A-2. ライバル会社（4-G） — **P1**
- **設計**：同ジャンルを開発中のライバル。先にリリースすると話題独占＝売上ボーナス
- **現状**：未実装
- **要追加**：開発開始時にライバルタイマー生成 → 完了時に勝敗判定 → 売上×1.2〜1.5

### A-3. バグイベント（6-5 ②） — **P2**
- **設計**：打鍵中にたまに赤行 → 素早く打ち直すとボーナス
- **現状**：未実装
- **要追加**：useTyping にイベント発火、赤フレーズ＋制限時間内クリアでLoCボーナス

### A-4. ポリッシュ品質の逓減カーブ（4・7-E） — **P0**
- **設計**：Q上昇は逓減（「どこで切り上げるか」の判断を生む）
- **現状**：`polishToQuality` は **線形 +3/LoC**（`utils/metascore.ts:50`）。すぐ100に貼り付く
- **要追加**：
  ```ts
  // 例：逓減カーブ（最大100、Q90以降は鈍化）
  Q = base + 60 * (1 - exp(-polishLoC / 25))
  ```
  もしくは段階係数（〜Q50: +3 / 〜Q80: +1.5 / 〜Q95: +0.5 / 以降: +0.1）

### A-5. ローンチ広告（4-I・6-1） — **P0（収益要件）**
- **設計**：リリース直後に「広告キャンペーン」リワードで売上 ×1.5
- **現状**：未実装。広告モックは「次の開発ブースト」のみ
- **要追加**：ReleaseScreen に「📺 広告でローンチキャンペーン（売上×1.5）」ボタン → リリース確定前に1回適用

### A-6. 市場調査広告（6-1） — **P2**
- **設計**：未知組合せの相性を一部開示／最低売上保証
- **現状**：未実装
- **要追加**：PlanScreen に「市場調査（広告）」ボタン → 相性ヒント or 売上下限保証フラグ

## B. 評価・販売の欠落

### B-1. 売上計算式の欠損（7-E） — **P0**
- **設計**：`売上 = 基礎単価 × 必要LoC × (Q/50) × 相性 × トレンド`
- **現状**：`computeRevenue = base × (meta/50) × compat`（`utils/metascore.ts:30`）
  - **LoC係数なし** → 大作のスケール感が弱い
  - **トレンド係数なし** → トレンド機能未実装の連鎖
- **要追加**：`requiredLoC` をパラメータに加える、トレンド係数を掛ける

### B-2. 日次販売・ロングテール（4-I） — **P1**
- **設計**：販売期間中ジワジワ売れる、メタが高いほど減衰遅
- **現状**：リリース時に総売上を即時加算（`releaseWork()`）
- **要追加**：
  - `Work` に `releasedAt`, `dailyRemaining`, `decayRate` 追加
  - tick で `funds += dailySales`、メタ高ほど `decayRate` 小
  - オフィスに「販売中の作品」リスト

### B-3. オフライン売上（4-I・9） — **P1**
- **設計**：離席時間ぶんの自動売上＋広告で2倍
- **現状**：未実装（離席時刻の保存もなし）
- **要追加**：
  - `storage` に `lastSeenAt` 保存
  - 起動時に経過時間×販売中作品の日次販売 を一括計上
  - 結果ダイアログ＋「広告で2倍」ボタン

### B-4. ファン数（4-H） — **P1**
- **設計**：高メタでファン増、次回作の初週販売を底上げ
- **現状**：未実装
- **要追加**：GameState に `fans`、リリース時 `fans += f(metascore)`、売上係数に反映

### B-5. ゴースト更新ファンファーレ（4-G） — **P2**
- **設計**：抜けば記録更新＝演出＋実績
- **現状**：ゴースト値は更新するが演出なし（`finishDevelopment`）
- **要追加**：完成時に「ゴースト更新！」演出フラグ、PolishScreenで表示
